# 首发范围与分批发布

> 状态：评审中 · 版本：1.0 · 更新：2026-10-13 · 负责人：产品负责人

本文记录招投标应用领域（`APP-TENDER`）首发范围的决定与推荐方案。标注“已决定”的条目来自项目负责人的决策；标注“推荐”的条目待确认。

## 1. 已决定

| 维度 | 决定 |
|---|---|
| 区域 | **全国** |
| P0 来源 | 以 Tender Intel 已整理的信源清单作为 P0 来源的初始清单，由数据负责人另行评审、补充并登记来源权利；只参考清单，不迁移任何代码或数据 |
| 首发信息领域 | `INF-PROC` 公共采购、`INF-INVP` 项目审批、`INF-ORG` 企业工商、`INF-CRED` 司法信用 |
| 商业目标 | 分批发布（见第 2 节） |
| 历史深度 | **不预设**。数据基础设施服务于 Agent：研究时由 Agent 按需决定所需的历史范围，并通过数据获取请求驱动回填（见 [acquisition](../../../03-architecture/subsystems/acquisition.md)、[AI 与 Agent](../../../03-architecture/05-ai-and-agent-architecture.md)）。首发只要求增量采集正常运行，并能响应回填请求 |
| 早期使用客户 | 建材供应商、投资决策者等多种类型 |

## 2. 商业目标分批（推荐）

分批原则：首发覆盖两类早期使用客户（建材供应商、投资决策者）的核心需求，且只依赖已决定的四个首发信息领域。

| 批次 | 商业目标 | 选择理由 | 依赖的信息领域 |
|---|---|---|---|
| **R1 首发** | A01 直接投标 | 投标类客户最基础的需求 | 采购、企业、信用 |
| | A02 进入供货 | 建材供应商的核心需求：中标结果 → 总包 → 供货窗口 | 采购、项目审批、企业 |
| | B03 竞争情报 | 两类客户都需要；完全基于中标与候选人数据 | 采购、企业 |
| | B05 目标企业经营跟踪 | 投资决策者的核心需求：订单趋势、客户结构、竞争地位 | 采购、企业、信用、项目审批 |
| | C01 交易对手风险评估 | 嵌入所有路径的风险研究；信用数据首发即具备 | 企业、信用、采购 |
| **R2** | A04 规格与品牌入围 | 依赖项目审批与设计阶段信号的深度运用 | 项目审批、采购 |
| | A05 合作组队 | 依赖资质数据（`INF-QUAL`），随该信息领域上线 | 资质、企业 |
| | A06 渠道与授权 | 需要品牌型号的识别积累 | 采购 |
| | B01 重点客户经营 | 需要财政预算数据增强 | 采购、财政 |
| | B02 市场研究与布局 | 需要统计汇总能力成熟 | 采购、项目审批 |
| | B04 价格与报价基准 | 需要标的与单价抽取质量达标 | 采购 |
| **R3** | A03 分包承接、C02 自身资格维护、C03 履约与回款、D01 金融服务获客、D02 专业服务获客 | 面向更多价值链角色的扩展 | 按目标而定 |

每个批次按 [质量与验收](../../../05-delivery/02-quality-and-acceptance.md) 的门槛独立发布；平台能力（机会路径引擎、判断框架、研究运行时）在首发时一次建成，后续批次只增加应用领域包中的定义。

## 3. 客户细分方案（推荐）

### 3.1 首发提供的价值链角色模板

| 角色模板 | 默认启用的 R1 目标 | 对应早期客户 |
|---|---|---|
| 材料设备厂商 `ROLE-MFR` | A01、A02、B03、C01 | 建材供应商 |
| 直接投标人 `ROLE-BIDDER` | A01、B03、C01 | 建材供应商（直接参与集采） |
| 总承包商 / 集成商 `ROLE-PRIME` | A01、B03、C01 | 扩展客户 |
| 经销代理商 `ROLE-DEALER` | A01、A02、C01 | 建材供应商的渠道 |
| 投资与研究机构 `ROLE-INVESTOR` | B05、B03、C01 | 投资决策者 |

租户可声明多个角色，系统合并其默认目标。

### 3.2 首发行业包

| 行业包 | 采购类别特征 | 选择理由 |
|---|---|---|
| **建材管材** | 货物为主，大量出现在工程项目中 | 早期使用客户所在行业；检验“进入供货”路径 |
| **信息化** | 服务与货物，政府采购占比高 | 与建材语言、流程差异大，检验平台通用性 |
| **环保水务** | 工程、设备与运营服务混合 | 同时覆盖工程、货物、服务三类，检验项目链与多角色 |

投资与研究机构不绑定行业包：其研究对象是企业，跨行业使用平台的品类分类体系。

### 3.3 推荐理由

- 角色模板覆盖供应侧（厂商、投标人、总包、经销）与观察侧（投资）两种截然不同的使用方式，可以尽早检验商业目标抽象是否成立；
- 三个行业包分别对应货物、服务、工程三类采购，能检验行业包机制而不是只适配一个行业；
- 更多行业包在首发后由领域团队按客户需求增加，不影响平台。
