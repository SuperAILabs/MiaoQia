# 信息领域目录

> 状态：评审中 · 版本：1.1 · 更新：2026-10-17 · 负责人：数据负责人

信息领域是平台的**数据侧**划分：一类外部信息及其结构、事件和生命周期。信息领域与应用领域是多对多关系：一个信息领域可服务多个应用领域，一个应用领域通常需要多个信息领域。

## 1. 目录

| 代码 | 信息领域 | 核心对象 | 典型来源类型 | 权利类型 | 优先级 |
|---|---|---|---|---|---|

## 3. 每个信息领域必须定义的内容

新增信息领域时，信息领域包必须提供以下内容（规格见 [可扩展性设计](../03-architecture/04-extensibility.md)）：

1. **来源清单**：来源、访问方式、更新频率、来源权利；
2. **领域 Schema**：核心对象、字段、精度、单位、时区，带 `schema_version`；
3. **解析器**：从原始制品到领域事实的解析逻辑与字段溯源；
4. **生命周期**：对象的状态机与合法转换；
5. **领域事件**：事件类型、触发条件与载荷；
6. **实体链接规则**：如何关联到组织、项目、地点、品类；
7. **跨记录聚合规则**：如何把多条记录归并为同一个领域对象（例如多条公告属于同一采购项目）；
8. **质量规则**：完整性、一致性、时效性检查；
9. **检索映射**：全文、结构化和语义索引字段；
10. **研究工具**：该领域向 Agent 提供的受控查询工具；
11. **个人信息清单**：包含哪些个人信息字段、处理目的与访问级别。

## 4. 跨领域共享的契约

所有信息领域共享平台统一的契约，不得各自实现：

| 契约 | 内容 |
|---|---|
| 证据契约 | 原始制品、快照、解析修订、字段溯源 |
| 时间契约 | 发布时间、观察时间、生效时间、记录时间（双时态） |
| 实体契约 | 组织、项目、地点、品类的统一标识与解析 |
| 质量契约 | 质量状态、警告、置信度 |
| 权利契约 | 来源权利条目引用随数据传递，逐维决定可见性与用途（[数据架构第 12 节](../03-architecture/02-data-architecture.md#12-来源权利与数据权益)） |
| 事件契约 | 统一事件信封、命名与版本规则 |

信息领域之间的差异体现在 Schema、生命周期和事件类型上，平台不会把它们压成一张通用表。

## 5. 观测类信息领域

`INF-STAT` 承接独立来源发布的统计、价格与财务数据。它与采购派生统计的分界是来源：从采购公告、中标结果等领域事实算出的统计（例如某品类的成交单价区间、某采购人的历年采购额）仍由 `domain-intelligence` 从 `INF-PROC` 派生，不放进本领域；统计部门、价格机构或交易所直接发布的数值才属于本领域。

观测类数据的核心对象是**观测序列**与**观测值**，领域 Schema 至少表达：

| 要素 | 说明 |
|---|---|
| 指标与口径 | 指标定义、统计口径、覆盖范围（地区、行业、品类或企业）；口径变化产生新的序列版本，不在原序列上改写 |
| 期间与频率 | 观测所属期间（月、季、年或日）与发布频率；期间与发布时间分开记录 |
| 修订批次 | 初值、修正值、终值等发布批次；后一批次是新的观测版本，旧值保留，按时点查询取当时已发布的批次 |
| 单位与币种 | 计量单位、币种、数量级；跨币种比较需记录换算所用汇率版本 |
| 价格口径 | 含税或不含税、出厂价、到货价或市场价、现货或合约、计价单位 |

本领域的来源清单、Schema 与质量规则随首个依赖它的应用领域包定义，目录登记不代表已接入（服务状态见[可扩展性](../03-architecture/04-extensibility.md#4-加载版本与发布)）。
