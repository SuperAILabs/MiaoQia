# 术语表

> 状态：评审中 · 版本：1.0 · 更新：2026-10-12 · 负责人：产品负责人

本表是全体文档的术语基准。文档、代码、接口和界面文案中的概念必须与本表一致。英文标识符用于代码与契约。

## 1. 业务层级

| 术语 | 英文标识 | 定义 |
|---|---|---|
| 平台 | Platform | 妙洽本身：跨领域的商业机会研究与决策系统。不绑定任何行业或应用领域。 |
| 应用领域 | Application Domain | 一类商业活动场景，由一组商业目标、业务流程和判断框架构成，例如“招投标与政企采购”“企业客户开发”“招商引资”。一个应用领域消费一个或多个信息领域。 |
| 信息领域 | Information Domain | 一类外部信息及其数据语义，例如“公共采购公告”“企业工商”“知识产权”“司法信用”。信息领域在数据侧，可被多个应用领域复用。 |
| 客户细分 | Customer Segment | 某应用领域内具有相似商业目标和流程的客户群体，由**价值链角色 × 行业 × 规模/区域**等维度组合定义。 |
| 价值链角色 | Value Chain Role | 客户在某应用领域交易链条中的位置，例如招投标中的直接投标人、总包、材料设备厂商、经销商、金融机构。 |
| 行业 | Industry | 客户所属的产品或服务行业，例如建材管材、信息化、医疗器械。行业是客户细分的一个维度，与价值链角色正交。 |
| 商业目标 | Commercial Objective | 客户希望达成的商业结果类型，例如直接投标获取、进入供货、规格入围、竞争情报。目标定义在平台层，由应用领域实例化。 |
| 机会路径 | Playbook | 在某应用领域中实现某商业目标的标准业务流程，包含阶段、研究模板、判断框架、决策门和行动类型。 |
| 目标对象 | Subject | 研究、判断或推进所针对的对象，类型包括项目、组织、交易事件、市场、关系等。 |

## 2. 数据与证据

| 术语 | 英文标识 | 定义 |
|---|---|---|
| 来源 | Source | 一个具体的信息来源及其访问契约，例如某省公共资源交易平台的某个栏目。 |
| 来源权利 | Source Rights | 某来源数据在采集、存储、加工、展示、再分发和模型使用上的许可范围。 |
| 抓取尝试 | Fetch Attempt | 对来源的一次访问及其结果记录。 |
| 原始制品 | Raw Artifact | 抓取得到的原始响应、附件或文件，按内容哈希不可变存储。 |
| 来源观察 | Source Observation | 系统在某时间观察到来源发布的某个内容，是事实链的起点。 |
| 来源快照 | Source Snapshot | 来源内容的一个不可变版本。来源实际发生变化才产生新快照。 |
| 解析修订 | Extraction Revision | 对同一来源快照的一次解析结果。解析器升级产生新修订，不产生新快照。 |
| 规范化文档 | Normalized Document | 对来源快照处理后的统一文档表示（正文、版面、表格、分块、坐标），存放于对象存储，是证据定位的坐标系。 |
| 分块 | Chunk | 规范化文档中用于检索和 Agent 研究的段落级片段，带证据定位。 |
| 内容增强 | Enrichment | 由规则或 AI 对规范化内容产生的检索增强结果：分类、标签、抽取、实体提及、摘要、向量。概率性、带置信度、按增强器版本管理，与领域事实字段区分。 |
| 增强器 | Enricher | 产生某类内容增强的处理器，带版本与标签体系版本，可整体重算与回退。 |
| 标签体系 | Tag Taxonomy | 平台与行业包定义的业务标签与分类集合，版本化。 |
| 语料快照 | Corpus Snapshot | 按月汇总的规范化文本与元数据（Parquet），用于批量重算增强与评估。 |
| 索引版本 | Index Version | 检索索引的一个构建版本，由映射、分析器、词表与增强器版本决定，通过别名切换生效。 |
| 证据 | Evidence | 可定位、不可变、可复核的原始材料片段及其版本引用。 |
| 字段溯源 | Field Provenance | 某个结构化字段值对应的证据位置、提取方法和置信度。 |
| 领域事实 | Domain Fact | 由证据解析得到、属于某信息领域的结构化对象，例如招标公告、中标结果、专利授权。 |
| 领域事件 | Domain Event | 领域事实发生的有业务意义的变化，例如公告更正、中标公示、企业变更。 |
| 领域生命周期 | Domain Lifecycle | 某信息领域对象自身的状态演进，例如采购项目从意向到履约。与客户侧生命周期分离。 |
| 实体 | Entity | 跨领域共享的主数据对象：组织、项目、地点、品类等。 |
| 关系 | Relationship | 实体之间带时间、证据和置信度的关联，例如“采购人—项目”“项目—中标人”。 |
| 实体解析 | Entity Resolution | 判断不同记录是否指向同一实体并进行合并或拆分的过程，必须保留合并历史。 |
| 公共域 | Public Zone | 可在来源权利范围内被所有租户复用的数据区域。 |
| 租户域 | Tenant Zone | 仅属于某个租户的数据区域。 |

## 3. 客户智能

| 术语 | 英文标识 | 定义 |
|---|---|---|
| 租户 | Tenant | 一个签约客户组织在平台中的隔离单位。 |
| 客户上下文 | Customer Context | 租户的产品、能力、资质、业绩、区域、目标、风险偏好和知识资产。 |
| 策略 | Policy | 租户用于监测和判断的结构化规则与参数集合，必须版本化。 |
| 监测订阅 | Watch | 租户对某类领域事件、实体或市场的持续关注定义，由策略驱动。 |
| 信号 | Signal | 某领域事实或事件经租户策略匹配后，对该租户可能有意义的候选。信号属于租户域。 |
| 处置 | Disposition | 对信号的分层结论：`pursue_candidate`、`review_candidate`、`watch_signal`、`excluded`、`no_signal`。 |
| 研究案例 | Research Case | 围绕一个具体问题发起的调查，包含研究计划、工具调用、证据集合和研究报告。 |
| 研究模板 | Research Template | 针对一类问题的标准化研究流程定义：允许的工具、步骤、预算和输出 Schema。 |
| 判断 | Assessment | 结合领域事实、研究结果和客户上下文形成的版本化评估：相关性、可信度、可行性、风险、优先级。 |
| 判断框架 | Assessment Framework | 某商业目标下的评估维度、硬门槛和评分规则定义。 |
| 决策 | Decision | 由有权限的人批准的结论，例如跟进、观察、放弃、投入资源。 |
| 推进 | Pursuit | 租户围绕一个目标对象按某机会路径开展的工作实例，即用户口语中的“在跟的商机”。 |
| 结果 | Outcome | 推进的最终业务结果及其原因，例如中标、进入供货、失败、放弃。 |
| 反馈 | Feedback | 用户对信号、判断或研究结果的评价，带原因标签，用于学习与评估。 |
| 商机 | Opportunity（仅界面用语） | 面向用户的统称或聚合视图，不是核心数据实体。系统内部使用信号、推进等精确概念。 |

## 4. 架构

| 术语 | 英文标识 | 定义 |
|---|---|---|
| 平面 | Plane | 子系统的分组：数据供应平面、客户智能平面、交互平面、平台平面。 |
| 子系统 | Subsystem | 拥有独立职责、数据所有权和接口契约的业务能力单元，是将来独立部署的最小粒度。 |
| 部署单元 | Deployment Unit | 一个可独立构建、发布和伸缩的运行制品。首期有两个：`platform` 与 `acquisition`。 |
| 进程角色 | Process Role | 同一部署单元以不同入口运行的进程类型，例如 `api`、`consumer`、`workflow-worker`。 |
| 可组合部署 | Composable Deployment | 通过部署配置决定哪些子系统运行在哪个部署单元和进程角色中，而不修改代码。 |
| 单元（租户单元） | Cell | 一组租户共享的一套客户智能平面运行实例与数据存储，用于水平扩展和专属部署。 |
| 扩展包 | Pack | 平台的扩展机制，包括信息领域包、应用领域包、行业包。 |
| 信息领域包 | Information Domain Pack | 提供一个信息领域的来源处理器、解析器、领域 Schema、生命周期、事件和实体链接规则。 |
| 应用领域包 | Application Domain Pack | 提供一个应用领域的商业目标实例、机会路径、研究模板、判断框架和视图定义。 |
| 行业包 | Industry Pack | 提供某行业的分类体系、产品与能力模板、词表和策略模板。 |
| 受控工具 | Governed Tool | Agent 可调用的、带权限范围、数据分级、预算和审计的功能接口。 |
| 渠道适配器 | Channel Adapter | 把某个通讯或工作平台（企业微信、飞书、钉钉、邮件等）接入妙洽的插件，负责消息收发、能力声明、验签与身份解析。 |
| 渠道会话 | Conversation | 用户在某渠道中与妙洽 Agent 的对话线程，映射到平台中的研究案例。 |
| 模型网关 | Model Gateway | 所有模型调用的统一入口，负责路由、策略、计量和记录。 |
| 事务性发件箱 | Transactional Outbox | 业务数据与待发布事件在同一事务中提交，再由中继发布到事件总线的模式。 |
