# 产品需求与交互设计方案（推荐稿）

> 状态：草案（待决策） · 版本：0.1 · 更新：2026-10-13 · 负责人：产品负责人

本文提出产品体验的推荐方案与需要决策的问题，供项目负责人讨论确定。确定后转为正式的产品设计规范与需求文档。

## 1. 设计前提

1. **数据服务于 Agent，Agent 服务于用户**：用户的主要获得物是 Agent 完成的研究、判断和建议，而不是自己去浏览和筛选海量公告；
2. **两类差异很大的早期客户**：建材供应商（行动导向：找到线索、分派跟进）与投资决策者（研究导向：持续跟踪企业、形成判断）。同一套产品必须同时适用，这正好检验平台的通用性；
3. **证据优先**：任何结论都能一键回到原文；
4. **人做决定**：AI 只给出草案与建议，关键决策由人确认。

## 2. 交互范式：三个选项

| | A 传统工作台 | B 对话为中心 | **C 产物为中心 + Agent 随行（推荐）** |
|---|---|---|---|
| 形态 | 列表、筛选、看板为主，AI 作为辅助按钮 | 以聊天框为主入口，所有事情通过对话完成 | 以简报、信号、研究报告、对象页、推进为主界面；每个界面都有可调用的 Agent；全局“问妙洽”入口发起研究 |
| 优点 | 用户熟悉，实现确定 | 灵活，展示 AI 能力强 | 结果可沉淀、可追溯、可协作；既有确定的工作流，又能随时深入研究 |
| 缺点 | 退化为“又一个信息网站”，Agent 价值被掩盖 | 结论散落在对话中，难以协作、复盘和审计；对行动导向的用户效率低 | 设计复杂度较高，需要统一的产物与证据展示规范 |
| 适合 | 行动导向用户 | 研究导向用户 | 两者兼顾 |

推荐 **C**，理由是：妙洽的价值在于“研究、判断、行动和复盘”的结果能够沉淀下来、可以追溯，而对话只是发起与追问的方式。在 C 中，每次对话都会落成一个研究案例，形成可引用、可分享、可复盘的产物。

## 3. 推荐方案的产品结构

### 3.1 主导航

| 模块 | 作用 | 主要用户 |
|---|---|---|
| **今日简报** | Agent 按租户目标生成的每日/每周简报：新机会、重要变化、待决策事项 | 全部 |
| **信号** | 按目标分层的信号收件箱（建议跟进 / 待复核 / 观察），每条附理由与证据 | 业务开拓者 |
| **关注** | 用户关注的企业、项目、采购人、市场；变化时间线与周期简报 | 投资决策者、客户经营 |
| **研究** | 研究案例与报告：发起、进展、报告、追问、导出 | 研究分析者、投资决策者 |
| **推进** | 推进看板：阶段、任务、负责人、截止、结果 | 项目推进者、决策者 |
| **对象页** | 每个企业、项目、采购人一页：Agent 摘要、事实时间线、关系、证据、相关信号、一键研究 | 全部（从任意位置进入） |
| **设置** | 客户档案、目标、策略（策略实验室）、成员与权限 | 管理员 |

### 3.2 全局“问妙洽”

- 用自然语言提问（如“某公司过去三年在华东的中标情况和主要客户”）；
- 系统匹配研究模板，或直接执行检索；
- 结果以研究案例保存，可以追问、分享、导出，并可转为关注或推进。

### 3.3 统一的结论与证据展示规范

| 元素 | 展示 |
|---|---|
| 事实 | 正常文本，带证据角标，点开后高亮原文 |
| 推断 | 明确标注“推断”，展示所依据的事实 |
| 未知项 | 单独区块，说明为什么未知、如何补全 |
| 建议 | 单独区块，标注“AI 建议”，需要人确认 |
| AI 生成标识 | 所有 AI 生成内容统一标识 |
| 版本与时间 | 显示数据截至时间，可查看判断所依据的版本 |

### 3.4 渠道分工

| 渠道 | 建材供应商 | 投资决策者 |
|---|---|---|
| 企业微信 | **主渠道**：简报、信号卡片、快捷反馈、分派、审批 | 简报提醒 |
| Web | 复核、对象页、推进看板、设置 | **主渠道**：关注、研究、对象页 |
| 报告导出 | 次要 | **重要**：研究报告导出为 PDF / Word |
| 移动端 | 企业微信内网页 | 企业微信内网页或响应式 Web |

## 4. 两类早期客户的关键旅程

**建材供应商（进入供货）**

```text
企业微信早间简报 → 一条中标结果信号：“某市政管网项目，总包为 X，含 PE 管材需求”
  → 打开对象页：项目链、总包画像、历史常用供应商、付款风险
  → 点“跟进” → 指派销售 → 推进进入“接触”阶段 → 截止前提醒
  → 成交或失败后记录结果与原因
```

**投资决策者（目标企业经营跟踪）**

```text
关注一组目标企业 → 每周经营变化简报（新中标、合同、排名、处罚）
  → 对某企业发起深度研究：“订单趋势、客户集中度、与竞对份额对比、风险”
  → 研究报告（事实/推断/未知/建议）→ 追问 → 导出报告
  → 记录投资判断（决策），持续关注
```

## 5. 设计工作计划与产出

| 阶段 | 时间 | 产出 |
|---|---|---|
| D1 概念验证 | M0 第 1–4 周 | 信息架构、两类客户的旅程故事板、低保真原型；每类早期客户 3–5 家做概念测试 |
| D2 设计规范 | M0 第 5–8 周 | 高保真原型；设计规范（基于 Ant Design 的妙洽设计令牌与组件）；结论与证据展示规范；企业微信卡片规范 |
| D3 需求文档 | M1 至 M2 前 | 按功能的产品需求文档（用户故事、业务规则、验收标准、埋点）；可用性测试 |

产品需求文档统一结构：背景与目标 → 用户与场景 → 用户故事 → 业务规则 → 界面与交互 → 数据与接口依赖 → 验收标准 → 指标与埋点 → 非功能要求。
