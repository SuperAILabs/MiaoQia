# 商业模式

> 状态：草案 · 版本：2.0 · 更新：2026-10-14 · 负责人：产品负责人、商务负责人

## 1. 商业逻辑

妙洽的收入来自客户为**更好的商业判断和更高效的机会推进**支付的费用。它的成本结构由四部分构成：数据获取与治理、模型与计算、平台运营，以及专业服务。商业模式设计的核心是：让数据和平台的固定投入被尽可能多的应用领域、客户细分和租户复用。

```text
一次采集、多领域复用  →  一个实体图谱、多目标复用  →  一套研究能力、多租户复用
            ↓                        ↓                         ↓
     数据边际成本下降          研究深度与广度提升          单客户交付成本下降
```

## 2. 客户价值的计量

客户愿意付费的前提是感知价值显著高于价格。产品在每个租户中持续计算并展示以下指标（定义见 [质量与验收](../05-delivery/02-quality-and-acceptance.md)）：

```text
客户可感知年价值 =
    新增有效机会数 × 机会转化率 × 平均毛利
  + 节省的筛选与调研工时 × 人力成本
  + 避免的无效跟进次数 × 单次跟进成本
  + 风险事件规避（按客户确认的案例计）
```

这些指标同时用于续费沟通、定价校准和产品优先级判断。

## 3. 交付模式

| 模式 | 适用客户 | 内容 | 平台要求 |
|---|---|---|---|
| **SaaS 订阅** | 主流企业客户 | 多租户共享单元，按套餐使用 | 标准租户隔离与配额 |
| **托管研究服务** | 需要“结果”而非“工具”的客户；冷启动期客户 | 妙洽分析师使用平台为客户完成研究、调优和简报 | 运营工作台、服务工时记录 |
| **专属单元** | 大型企业、高合规客户 | 独立租户单元（独立数据库与计算），共享公共数据供应 | 单元化部署能力 |
| **私有部署** | 有数据不出域要求的客户 | 客户环境内部署客户智能平面，公共数据以授权方式同步 | 部署包、离线同步、客户自有模型端点 |
| **数据与 API** | 有 IT 能力的客户、合作伙伴 | 按授权提供领域事实、实体与研究 API | 来源权利控制、计量 |
| **合作伙伴嵌入** | CRM、ERP、行业 SaaS、咨询机构 | 白标或嵌入式研究与监测能力 | 多级租户、品牌定制 |

托管研究服务不是临时补丁，而是正式产品线。每一次人工操作都在平台中结构化记录，既保证服务质量，也为自动化提供训练和评估数据。

## 4. 计价结构

```text
平台订阅（按组织与席位档位，含基础用量）
+ 应用领域包（如招投标、企业客户开发）
+ 数据覆盖包（区域、行业、授权数据源）
+ 能力包（深度研究、推进协作、开放 API/MCP）
+ 超量用量（研究任务、报告、导出、存储）
+ 专业服务（托管研究、调优、实施，单独核算毛利）
```

计价原则：

- 不以纯席位或纯 Token 计价：席位不反映价值，Token 不被客户理解；
- **研究任务**是主要的可变计量单位，客户可理解、与成本相关；
- 不以中标或成交佣金为核心收入：归因困难、回款周期长、存在利益冲突；
- 数据覆盖包的价格必须覆盖授权数据成本，并受来源权利约束。

具体价格档位在产品上线前由商务团队基于成本模型和市场调研确定 **[待核验]**。

## 5. 单位经济指标

| 指标 | 定义 | 用途 |
|---|---|---|
| 单租户数据成本 | 授权数据费用与采集运维按使用分摊 | 数据包定价 |
| 单研究任务成本 | 模型、工具调用、检索与人工复核成本 | 研究计量定价、模型路由优化 |
| 单租户模型成本 | 全部模型调用成本 | 毛利监控 |
| 托管服务工时 | 每租户每周人工服务时长 | 服务定价与自动化优先级 |
| 实施周期 | 签约到首个有效信号的时间 | 实施产品化 |
| 毛利率 | 分别核算软件、数据、服务三条线 | 业务健康度 |
| 净收入留存 | 续费与扩展收入 / 期初收入 | 产品价值的最终验证 |

M1首次外部调用起记录技术计量，M2起关联租户；M5商业化把既有记录转换为计费。商业运营指标随相应流程建立，由 [商业化子系统](../03-architecture/subsystems/commerce.md) 和 [运营子系统](../03-architecture/subsystems/operations.md) 负责。

## 6. 应用领域扩展策略

平台的应用范围很广，但每个应用领域只有在满足交付质量标准时才对外销售。扩展顺序由以下因素综合决定：

| 因素 | 问题 |
|---|---|
| 数据可得性 | 所需信息领域是否已在平台中，或可以合法、稳定地获取？ |
| 复用度 | 能复用多少已有的信息领域、实体图谱和研究工具？ |
| 决策价值 | 单次正确判断的商业价值是否足以支撑订阅价格？ |
| 交付可达性 | 能否在合理成本下达到 [质量与验收](../05-delivery/02-quality-and-acceptance.md) 的标准？ |
| 合规风险 | 涉及的数据和输出是否存在难以控制的法律风险？ |

首个应用领域为**招投标与政企采购**：交易规模大、信息公开程度高、团队在前期原型中积累了采集与证据治理的实践经验，并且覆盖多种价值链角色与商业目标，能充分检验平台抽象。候选的后续应用领域见 [应用领域目录](../02-business/04-application-domains.md)。

## 7. 数据权利对商业模式的约束

- 每个来源的商业使用、展示、再分发和模型使用权利必须在来源注册时登记，见 [采集子系统](../03-architecture/subsystems/acquisition.md)；
- 计价中的“数据覆盖包”只能包含权利允许商业提供的来源；
- 客户授权原始数据只服务于该客户，不得进入公共域或其他租户；公共评估只能使用另经明确用途授权、去标识化与治理审批的评估快照，不能包含原始租户文档、策略、上下文或身份；
- 来源权利变更时，平台必须能定位并下线受影响的数据和功能。
