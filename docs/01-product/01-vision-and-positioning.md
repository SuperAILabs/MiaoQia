# 产品愿景与定位

> 状态：评审中 · 版本：1.0 · 更新：2026-10-12 · 负责人：产品负责人

## 1. 愿景

让每一家企业都拥有一个**懂自己业务、会取证、能推理、可协作**的商业研究团队：持续感知外部世界的变化，围绕自己的商业目标完成调查与判断，并把判断转化为可追踪的行动和可复盘的结果。

## 2. 定位

**正式定位：** AI 商业机会研究与决策系统
**简化表达：** AI 商业机会决策系统
**英文：** MiaoQia — AI-native Opportunity Research & Decision System

妙洽是一个**平台**，不是某个行业的专用工具。平台提供跨领域共享的能力：多源数据供应、证据治理、实体与关系图谱、客户上下文、Agent 研究、判断与决策、推进协作和反馈学习。具体的商业场景以**应用领域**的形式接入。

## 3. 业务层级

```text
L0 平台               妙洽：商业机会研究与决策系统
 └─ L1 应用领域        招投标与政企采购 | 企业客户开发 | 招商引资 | 投资研究 | …
     │   └─ 消费 → 信息领域（数据侧）：公共采购、项目审批、企业工商、司法信用、知识产权 …
     └─ L2 客户细分    价值链角色 × 行业 × 规模/区域
         └─ L3 商业目标   直接投标、进入供货、规格入围、竞争情报、风险评估 …
             └─ L4 机会路径  阶段 · 研究模板 · 判断框架 · 决策门 · 行动
                 └─ L5 运行实例  信号 → 研究 → 判断 → 决策 → 推进 → 结果 → 学习
```

关键要点：

- **招投标**是第一个应用领域，不是产品边界。
- **管材/建材**是招投标应用领域中“行业”维度上的一个取值，与“价值链角色”维度正交。一个管材企业可能同时是直接投标人（水务集采）、总包供货商（市政工程）和规格入围对象（设计院选型）。
- **商业目标**定义在平台层，是跨应用领域可复用的抽象。直接投标只是其中之一。

详细定义见 [业务架构](../02-business/01-business-architecture.md)。

## 4. 价值主张

### 4.1 对客户的结果承诺

所有能力最终必须兑现为以下四类可度量结果之一：

| 结果 | 含义 | 典型度量 |
|---|---|---|
| **少漏** | 不错过与自身目标相关的外部变化 | 相关信号召回率、相对原有渠道的新增有效机会数 |
| **早知道** | 在竞争对手之前获知并行动 | 相对公告发布或原有渠道的发现提前量 |
| **少白跟** | 不在不可行、不可信或不值得的机会上投入 | 无效跟进比例、决策前置淘汰率 |
| **判得准、做得快** | 判断有依据、推进有节奏、结果可复盘 | 从发现到决策的时间、判断采纳率、结果反馈覆盖率 |

### 4.2 为什么客户能信任它

- **证据优先**：每个关键事实、判断和建议都能回到具体来源、版本和原文位置。
- **客户可控**：客户的业务理解以结构化、可版本化、可仿真、可回滚的策略表达，而不是黑箱。
- **人做决定**：AI 负责调查、组织证据和提出建议；高影响决策和对外动作由有权限的人批准。
- **数据隔离**：客户的业务资料、判断和结果属于该客户，绝不进入其他客户的检索、模型上下文或分析。

## 5. 差异化

国内已有成熟的招标信息平台和商机工具，海外已有从早期情报延伸到 capture 和提案的全流程产品。妙洽不靠“信息更多”或“也有 AI”竞争，而靠以下组合：

1. **目标驱动而非信息驱动**：系统从客户的商业目标和机会路径出发组织信息，而不是从公告列表出发。同一条中标结果，对投标人是竞争情报，对材料厂商是供货线索，对银行是保函获客线索。
2. **跨信息领域的研究能力**：把采购、审批、工商、信用、知识产权等信息领域通过实体与关系图谱连接起来，回答单一信息源无法回答的问题。
3. **可取证的 Agent 研究**：Agent 通过受控工具调查，输出区分事实、推断、未知项和建议的研究报告，每一项都可追溯。
4. **可控、可演进的客户理解**：策略可用自然语言调整，但必须经过结构化、仿真、审批和灰度。
5. **平台化扩展**：新的信息领域、应用领域和行业以扩展包接入，共享同一套证据、实体、研究和决策能力。
6. **全渠道一致**：Web、企业微信、邮件、API 和 MCP 共用同一套业务服务、权限和审计。

## 6. 产品原则

1. **用户目标优先于技术模块**：每个能力都必须说明它服务于哪个商业目标、产出什么决策产物。
2. **证据优先于结论**：没有证据支撑的结论必须标注为推断或未知。
3. **信息、研究、判断、决策分层**：来源说了什么、系统解析出什么、调查发现什么、对客户意味着什么、客户决定什么，各自独立记录。
4. **领域生命周期与客户生命周期分离**：外部对象的状态变化不会覆盖客户的推进状态，反之亦然。
5. **通用架构不抹平领域差异**：平台统一证据、实体、权限和流程契约，领域保留自己的对象、字段和生命周期。
6. **AI 有边界**：外部内容一律视为不可信输入；AI 不扩大权限、不越过租户边界、不擅自执行高影响动作。
7. **渠道不复制业务逻辑**：入口变化不改变事实、判断或规则。
8. **数据基础设施服务于 Agent**：数据供应平面的首要使用者是 Agent。用户看到的是与自己相关或由自己产生的数据（信号、研究、判断、推进等），以及通过检索、对象页和证据查看按需呈现的**部分**信源数据；全量信源数据不向用户暴露，这既符合产品定位，也是平台数据资产的自我保护。主要价值来自 Agent 完成的研究、判断与建议；历史深度、数据范围等由 Agent 在研究时按需决定，数据基础设施负责按需供给。

## 7. 边界与非目标

妙洽**是**：外部商业机会的研究、判断和推进系统，以及支撑它的数据与证据基础设施。

妙洽**不是**：

- 单纯的信息聚合网站或关键词订阅工具；
- CRM、ERP 或项目管理系统的替代品（通过集成协作，而不是重建）；
- 投标文件自动生成和自动提交工具（可在审批前提下辅助起草）；
- 个人信息贩卖或营销名单工具；
- 承诺中标率或成交率的结果担保服务。

长期不做：

- 不依赖个人账号或规避访问控制的非官方自动化；
- 不采集或出售来源不明的私人信息；
- 不让 AI 替客户作出未经批准的最终决定；
- 不让不同渠道形成各自独立的数据、规则和权限实现。
