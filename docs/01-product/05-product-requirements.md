# 产品需求落地规格

> 状态：评审中 · 版本：1.3 · 更新：2026-10-17 · 负责人：产品负责人、设计负责人

本文细化[产品体验](04-product-experience.md)的实现边界，作为功能PRD和原型的检查依据。总体方向已批准；这里的具体交互规则仍需产品评审，不能当作原型或全部功能PRD已完成。

## 1. 阶段与客户任务

| 阶段 | 可用旅程 | 必须验收 |
|---|---|---|
| M0 | 两类客户概念测试 | 信息架构、低保真旅程、3–5家/类的任务观察；早期客户已确认，名单/协议商务维护 |
| M2 | A01/A02/B03：配置目标→信号→证据→规则判断/必要审批→指派跟进→提醒→结果反馈；首条验证旅程为建材供应商A02 | Web与渠道身份一致；首次策略激活有仿真/审批；研究与完整推进（阶段、路径衔接）尚未交付时入口不可执行 |
| M3 | B05/C01及模板研究、追问、回填 | 数据截至时间、引用、未知项、任务限额、异步完成和报告导出 |
| M4 | 五个R1目标完整旅程，含推进、复盘 | 推进状态、任务分派、权限与支持流程；生产迁移/恢复及正式发布门禁 |

投资客户可在M2验证B03的证据与通知，B05研究旅程在M3验收，不以M2的供应商旅程替代投资客户验收。

## 2. 统一业务与交互规则

| 场景 | 规则 | 验收 |
|---|---|---|
| 登录/渠道绑定 | 租户来自认证身份；账号绑定/解绑经验证；跨租户切换重新授权 | 未绑定渠道仅引导绑定，失效动作不执行，旧会话不泄露其他租户数据 |
| 目标配置 | 行业、角色、地区、品类、能力和排除项记录版本；未知资质不默认为满足 | 展示草案/校验/仿真/审批/激活状态，变更前后可对照 |
| 信号列表 | 按目标独立处置；明确命中/排除理由、截止时间、数据截至时间 | 空列表区分“无结果/来源中断/配置未启用/无权限”；更正导致重新判断时保留版本 |
| 批量动作 | 显示选中数量与影响，逐项授权、幂等执行，返回成功/失败/未处理 | 部分失败可只重试失败项；筛选变化不悄悄扩大选中范围 |
| 证据查看 | 字段→原文定位；事实、推断、未知、建议分开 | 原文不可访问/权利撤回/证据失效时显示原因，不展示失效原文，已有判断保留状态说明 |
| 公开业务联系人 | 公开联系人、法定代表人等按公开数据明文展示/检索/模型输入 | 姓名/电话/邮箱有证据；租户私有联系人按租户分级；删除更正传播至派生数据 |
| 合并采购 | 公告可能含多个项目、采购人和标包 | 项目金额、工程投资额、标包金额、费率分别展示，不累加成错误总价 |
| 研究任务 | 提交返回案例标识，显示排队/运行/等待数据/部分完成/完成/失败/取消 | 显示剩余缺口与任务限制；取消后不再安排新调用；只回传有权限且有效的引用 |
| 研究追问 | 延续案例上下文，新增版本保留原报告 | 明确追问使用的数据时间和新增引用，不能把推断自动变成事实 |
| 回填 | 明确来源可得范围、预计等待与任务限额 | 超时/不可得返回部分结果与未知项，不宣称任意历史完整 |
| 简报 | 按目标分区、区内按该目标排序，另设“待我处理”“关注变化”区；配额可调，24小时内截止与更正不被截断；同一对象只完整出现一次 | 每区显示数据截至时间与空态原因；不同目标分数不混排；简报条目与Top-K评估列表可对照但口径不变，规则见[channels 4.4](../03-architecture/subsystems/channels.md#44-简报) |
| 跟进（M2） | 从信号一键创建跟进，指派负责人与截止时间，到期提醒，关闭时记录结果与原因；可采用按目标分派规则给出的候选负责人，候选只是建议 | 重复点击不重复创建；改派、成员退出、截止变更、提醒失败与关闭见[pursuit 第10节](../03-architecture/subsystems/pursuit.md#10-分阶段交付)；完整阶段与路径衔接随M4 |
| 持续跟踪 | 竞争对手、目标企业以跟踪计划管理：周期、负责人、暂停/恢复/停止 | M2交付变化监测与变化简报（B03）；周期研究与期间对比随M3（B05）；停止跟踪不删除已有简报与报告 |
| 关注 | 关注企业、项目、采购人或市场，也可把保存的检索转为订阅；个人关注不挂目标、只本人可见；关注到的变化单独记录，不都生成信号 | 订阅只提示创建后新出现或更新的事实，检索升级不重复提示；失去权限的变化不再展示（[detection 第11节](../03-architecture/subsystems/detection.md#11-关注)） |
| 通知 | 安静时段、频率、合并、退订、渠道失败站内兜底 | 通知主体与查看权限分开验证；群摘要不含未授权敏感内容；合并按收件人逐人进行，更正与24小时内截止不进入合并（[channels 4.5](../03-architecture/subsystems/channels.md#45-通知合并)） |
| 审批 | 依据权限矩阵与申请/批准分离；高影响动作转Web强认证 | 重复提交不重复执行，权限变化/令牌过期必须重新确认 |
| 导出 | 仅租户产物；公开数据无批量导出；报告PDF/Word保留引用、版本和AI标识 | 排队/失败/失效下载明确；导出时重新授权，不能借导出绕过原文权利 |
| 推进/反馈 | 任务归属、截止、阶段、结果原因可追溯；撤销/修订留记录 | 无权限不可分派；用户反馈与事实修订分别处理 |
| 不可用原因 | 区分未订阅、覆盖范围不足、额度不足、安全上限、来源权利限制，各自给出下一步 | 安全上限与来源权利不显示“升级套餐”；覆盖不足时不展示对象内容；错误代码与提示一致（[commerce 第8节](../03-architecture/subsystems/commerce.md#8-不可用原因)） |
| 漏报反馈 | 在信号收件箱、对象页与手动创建的跟进上报告“这个对象本应出现”：公共对象、目标、当时时点 | 诊断结果区分未采集、未归并、无权益、规则过滤、未入候选、规则排除、未送达，无法诊断的环节标“暂不能诊断”；不展示权益外内容（[learning 第11节](../03-architecture/subsystems/learning.md#11-漏报反馈与诊断)） |
| 人工判断 | 补充信息或不同意系统结果时追加人工判断：显示系统原值、人工值、原因、操作者与依据；硬门槛、来源事实与已批准决策不能被人工判断改写，门槛未通过仍推进须在决策中写明理由并经批准 | 原值始终可见可对照；框架未允许的维度没有人工调整入口；客户提供的事实标为客户提供，不出现在公共事实中（[assessment 第12节](../03-architecture/subsystems/assessment.md#12-人工判断)） |

## 3. 每个功能PRD的必备产出

功能PRD按现有模板编写：用户/目标 → 前置条件 → 主流程 → 业务与权限规则 → 状态转换 → 界面/原型 → 数据字段/接口/事件 → 异常/重试/撤销 → 非功能 → 埋点 → 验收。不能只交页面截图或接口清单。

首批PRD分包：登录与渠道绑定；客户档案/角色/目标；策略编辑/仿真/审批；信号收件箱/批量反馈；对象页/证据查看；渠道摘要/快捷动作；研究/追问/回填/报告；判断审批；推进/复盘；支持与数据权利请求。M2对应功能在实现前完成；M3/M4按相同规则交接。

每份原型必须展示空态、加载、无权限、过期、失败、部分成功、来源中断和数据未知；响应式H5验证关键任务可完成。证据高亮、键盘导航与表格交互纳入可用性测试。

## 4. 指标与验收证据

埋点只记录租户/用户标识、版本、动作、耗时、结果与原因码，不记录敏感正文。重点观察首次目标配置完成、信号查看→证据→判断→反馈转化、研究部分完成原因、客户任务耗时及可用性失败点。质量门槛以[质量与验收](../05-delivery/02-quality-and-acceptance.md)为准，功能PRD不另建相互冲突的阈值。

功能关闭需要原型/PRD版本、产品评审、用户任务观察、验收用例与缺陷处置记录。客户名单已确认不代表每份原型已经经过客户验证。
