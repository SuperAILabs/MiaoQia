# 产品体验

> 状态：已批准 · 版本：2.0 · 更新：2026-10-14 · 负责人：产品负责人

本文定义产品体验的总体设计；[产品需求落地规格](05-product-requirements.md)细化业务、权限、状态和异常检查。设计规范、原型与各功能PRD仍按第5节交付。

## 1. 设计前提

1. **数据服务于 Agent，Agent 服务于用户**：用户的主要获得物是 Agent 完成的研究、判断和建议，而不是自己去浏览和筛选海量公告；
2. **两类差异很大的早期客户**：建材供应商（行动导向：找到线索、分派跟进）与投资决策者（研究导向：持续跟踪企业、形成判断）。同一套产品必须同时适用，这正好检验平台的通用性；
3. **证据优先**：任何结论都能一键回到原文；
4. **人做决定**：AI 只给出草案与建议，关键决策由人确认。

## 2. 交互范式：工作台 + 产物为中心

工作台（A）与 Agent（C）是同一产品的两层：Agent 产生和深化产物，工作台负责查看、筛选、比较、批量处理和管理这些产物。产品不以对话为唯一中心。

### 2.1 两层如何共存

```text
┌──────────────────────── 工作台层（A）────────────────────────┐
│ 每类产物都有列表 / 表格 / 看板：筛选、排序、分组、列配置、   │
│ 保存视图、批量操作、导出                                      │
├──────────────────────── Agent 层（C）────────────────────────┤
│ 每个列表和详情页都可调用 Agent：总结、比较、追问、发起研究、  │
│ 生成草案；全局“问妙洽”入口；Agent 的每次产出都落成一条记录， │
│ 回到工作台的列表中                                            │
└──────────────────────────────────────────────────────────────┘
```

| 产物 | 工作台视图（A） | Agent 能力（C） |
|---|---|---|
| 信号 | 收件箱列表：按目标、处置、地区、品类、金额、截止时间筛选；批量分派、批量反馈 | 解释命中理由、比较多条信号、对选中信号批量发起研究 |
| 研究案例与报告 | 研究列表：按模板、对象、发起人、状态、时间筛选；报告库 | 追问、对比两份报告、基于报告生成决策草案 |
| 关注对象 | 关注列表：企业、项目、采购人、市场；变化计数与最近变化 | 周期简报、异常变化说明 |
| 推进 | 看板与表格两种视图：阶段、负责人、截止、金额；批量调整 | 下一步建议、风险提示、复盘总结 |
| 判断与决策 | 决策记录列表：待审批、已批准、按目标与时间筛选 | 决策草案、理由汇总 |
| 公共数据 | 受控检索：按需查看部分公告、项目、企业信息（结果数量、翻页深度与查看配额受限，不提供批量导出） | 用自然语言转为检索条件；对检索结果做归纳 |
| 简报 | 简报历史列表 | 生成与追问 |

### 2.2 统一列表能力

所有列表共用一套工作台组件与交互规范：

- 筛选（结构化条件 + 全文 + 自然语言转条件）、排序、分组、列显示配置；
- 保存视图（个人与团队共享），可设为默认；
- 批量操作（分派、反馈、关注、发起研究、导出），高影响批量操作需授权；
- 导出（Excel / CSV）仅限租户自身产物（信号、研究、推进、决策等），受权限与审计控制；公共信源数据不提供批量导出；
- 列表与详情之间保持上下文（上一条、下一条、返回原筛选）。

## 3. 产品结构

### 3.1 主导航

| 模块 | 工作台（A） | Agent（C） | 主要用户 |
|---|---|---|---|
| **今日简报** | 简报历史列表 | 按租户目标生成每日/每周简报：新机会、重要变化、待决策事项 | 全部 |
| **信号** | 按目标分层的收件箱列表与表格 | 理由解释、比较、批量研究 | 业务开拓者 |
| **检索** | 公告、项目、企业的受控检索（结构化与全文），保存检索条件；按暴露策略限制结果规模 | 自然语言检索、结果归纳 | 全部 |
| **关注** | 关注对象列表与变化时间线 | 周期简报、异常说明 | 投资决策者、客户经营 |
| **研究** | 研究案例列表、报告库 | 发起、追问、对比、导出 | 研究分析者、投资决策者 |
| **推进** | 看板与表格 | 下一步建议、复盘 | 项目推进者、决策者 |
| **决策** | 待审批与决策记录列表 | 决策草案 | 决策者 |
| **对象页** | 企业、项目、采购人的结构化信息、事实时间线、关系、相关信号与推进 | Agent 摘要、一键研究 | 全部（从任意位置进入） |
| **设置** | 客户档案、目标、策略（策略实验室）、成员与权限 | 自然语言策略调优 | 管理员 |

### 3.2 全局“问妙洽”

- 用自然语言提问（如“某公司过去三年在华东的中标情况和主要客户”）；
- 系统匹配研究模板，或直接执行检索；
- 结果以研究案例保存，出现在研究列表中，可以追问、分享、导出，并可转为关注或推进；
- M3开放该入口，M4完整R1首发包含；M2不展示可执行的研究入口。

### 3.3 统一的结论与证据展示规范

| 元素 | 展示 |
|---|---|
| 事实 | 正常文本，带证据角标，点开后高亮原文 |
| 推断 | 明确标注“推断”，展示所依据的事实 |
| 未知项 | 单独区块，说明为什么未知、如何补全 |
| 建议 | 单独区块，标注“AI 建议”，需要人确认 |
| AI 生成标识 | 所有 AI 生成内容统一标识 |
| 版本与时间 | 显示数据截至时间，可查看判断所依据的版本 |

### 3.4 渠道分工

渠道采用多渠道双向接入架构：用户既能在渠道中收到简报与信号，也能直接向 Agent 提问、追问和反馈。渠道分批见 [channels](../03-architecture/subsystems/channels.md#2-渠道分批)。

| 渠道 | 建材供应商 | 投资决策者 |
|---|---|---|
| 企业微信 / 飞书 / 钉钉 | **主渠道**：简报、信号卡片、渠道内提问、快捷反馈、分派、审批 | 简报提醒、渠道内提问与追问 |
| Web | 复核、对象页、推进看板、设置 | **主渠道**：关注、研究、对象页 |
| 报告导出 | 次要 | **重要**：研究报告导出为 PDF / Word |
| 移动端 | 响应式 H5（不依赖任何工作平台，任意浏览器可用）；后续可升级为 PWA，首发不做原生应用 | 同左 |

## 4. 两类早期客户的关键旅程

**建材供应商（进入供货）**

```text
企业微信早间简报 → 一条中标结果信号：“某市政管网项目，总包为 X，含 PE 管材需求”
  → 打开对象页：项目链、总包画像、历史常用供应商、付款风险
  → 点“跟进” → 指派销售 → 推进进入“接触”阶段 → 截止前提醒
  → 成交或失败后记录结果与原因
```

**投资决策者（目标企业经营跟踪）**

```text
关注一组目标企业 → 每周经营变化简报（新中标、合同、排名、处罚）
  → 对某企业发起深度研究：“订单趋势、客户集中度、与竞对份额对比、风险”
  → 研究报告（事实/推断/未知/建议）→ 追问 → 导出报告
  → 记录投资判断（决策），持续关注
```

## 5. 设计工作计划与产出

| 阶段 | 时间 | 产出 |
|---|---|---|
| D1 概念验证 | M0 第 1–4 周 | 信息架构、工作台列表规范与 Agent 嵌入方式、两类客户的旅程故事板、低保真原型；每类早期客户 3–5 家做概念测试 |
| D2 设计规范 | M0 第 5–8 周 | 高保真原型；设计规范（基于 Ant Design 的妙洽设计令牌与组件，含统一列表组件）；结论与证据展示规范；企业微信卡片规范 |
| D3 需求文档 | M1 至 M2 前 | 按功能的产品需求文档（用户故事、业务规则、验收标准、埋点）；可用性测试 |

设计资源：自建设计团队（2 人起），概念阶段可引入外部设计公司加速。

产品需求文档统一结构：背景与目标 → 用户与场景 → 用户故事 → 业务规则 → 界面与交互 → 数据与接口依赖 → 验收标准 → 指标与埋点 → 非功能要求。
