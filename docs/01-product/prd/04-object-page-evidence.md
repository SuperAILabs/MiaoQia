# PRD 第4段：对象页与证据

> 状态：评审中 · 版本：1.1 · 更新：2026-10-18 · 负责人：产品负责人、招投标领域负责人、数据负责人 · 原型：[prototypes/04-object-page-evidence.html](prototypes/04-object-page-evidence.html)

本段让销售从一条 A02 信号进入采购项目、上位项目、中标方（总包）与采购人的对象页，看清“这个项目是什么、谁中了标、这家总包和这家采购人过去做过什么”，并让页面上的每个关键字段都能回到原文。它承接第3段（信号详情中的证据角标与“查看对象”入口），为第6段的跟进提供判断依据。对象页展示的是公共事实，叠加本租户自己的信号、清单标记与跟进；公共事实不因客户反馈改变，本租户的内容不出现在其他租户的页面上。

## 1. 用户与目标

| 用户 | 角色 | 本段要完成的事 |
|---|---|---|
| 销售 | 业务开拓者 `business_developer` | 从信号进入对象页，判断总包是否值得接触，核对金额、标的与中标方的原文 |
| 销售负责人 | 决策者 `decision_maker` | 看采购人与总包的历史，决定是否跟进（第6段） |
| 研究分析者、项目推进者、业务专家 | `research_analyst`、`pursuit_lead`、`domain_expert` | 查看对象与证据；业务专家核对资质、品牌相关字段 |
| 租户管理员 | `admin` | 可查看公共对象；看不到未参与目标的信号 |

公共数据（公告、企业、项目，含其中公开的业务联系人信息）对租户全体成员按[公共数据暴露控制](../../03-architecture/06-security-and-tenancy.md#7-公共数据暴露控制)提供，不另设权限（[identity 7.2](../../03-architecture/subsystems/identity.md#72-权限矩阵) 说明）；数量、翻页与查看配额受暴露控制约束。页面上叠加的本租户内容按各自权限过滤：信号按目标的 `can_view_signals`（第3段），企业清单标记按 `can_view_profile`，跟进按第6段。外部协作者没有 `can_search_public`，不能访问对象页。

**成功标准**：销售从信号进入总包页，在 3 分钟内说出“这家总包近 3 年中了哪些含我方品类的项目、主要在哪里、用过谁家的品牌”，并能把中标金额、中标方、标的各自点回原文；任何不可用、未知、已撤回、已更正的情况都能看懂原因与数据截至时间。

## 2. 范围

| M2 包含 | 不在 M2 |
|---|---|
| 采购项目页（`pp_`，含标包）：当前状态、各类金额、标的、中标结果、公告时间线 | 投资项目、施工许可与项目链的完整展示（INF-INVP 上线后，见第13节第9项） |
| 项目页（`prj_`）：按归属边组装的采购项目与时间线 | 组织画像中的信用与司法（INF-CRED 上线后） |
| 组织页：基本登记信息、公示的主要人员与出资人（只读文本）、作为中标方与作为采购人的历史、供过的品牌及品牌归属 | 自然人页面、以自然人为入口的检索与关系图（[entity-graph 4.2](../../03-architecture/subsystems/entity-graph.md#42-自然人关系端点)） |
| 证据查看：字段 → 原文定位与高亮；记录证据与派生证据逐层展开 | 研究报告与 Agent 摘要（随 M3 研究入口；研究报告只属于本租户，见第5节） |
| 本租户叠加：相关信号、企业清单标记、报告漏报入口；“跟进”入口随第6段 | 关注对象（随关注功能，第13节第10项）；公共数据导出（不提供） |
| 版本与时间轴：当前（业务有效）与信号判断时（当时已知）两种视角，更正与撤回历史 | 运营人员的归并、合并与人工修正界面（属于数据运营工具） |
| Web 与响应式 H5 | 渠道内对象卡片（第5段只跳转 Web） |

## 3. 前置条件

- 第1段：成员与角色；第3段：信号详情、证据角标与“查看对象”入口、报告漏报（F8）；
- `domain-intelligence` 的采购项目聚合、公告事实与版本链、`GetCoverage`；INF-ORG 就绪（[M2-P11](../../05-delivery/06-stage-baseline.md#4-m2-前置条件与能力交接)）；
- `entity-graph` 的组织解析、合并历史、`part_of` 归属边与 `won`、`procures`、`supplied_brand` 等关系；品牌归属 `brand_owned_by` 与品牌词表随 M2-P13 交付，未就绪时相关区块读取为未知；
- `evidence` 的规范化文档、文档证据与 `ResolveEvidence`；记录证据与派生证据在第一个结构化来源或派生字段启用前通过 [ADR-0011](../../04-decisions/0011-immutable-evidence-dual-versioning.md#决策) 的首次启用门禁；
- 查看限额与来源权利判断已接入（[M2-P8](../../05-delivery/06-stage-baseline.md#4-m2-前置条件与能力交接)）：`gateway` 执行结果上限与翻页深度，`commerce` 执行对象查看与原文查看配额。

## 4. 主流程

### F1 从信号进入对象

1. 第3段信号详情中的项目名称、中标方、采购人与证据角标都是入口。A02 信号的求值单位是采购项目 `pp_` 及标包（或结果、合同所在的公告），因此“项目”入口先到**采购项目页**，并定位到信号所在的标包与结果；上位项目 `prj_` 通过归属边在采购项目页中给出；
2. 从信号进入时，页面顶部显示信号上下文条：“来自信号：A02 进入供货 · 跟进候选 · 按公告版本 v2 判断 · 求值时间 10-16 22:10 · 信号生成 10-16 22:11”。求值时间是信号的逻辑求值时间（`evaluated_at`，触发事件的时间），生成时间是信号写入平台的时间（`created_at`）；两者分别标注，回填产生的信号生成时间可能晚很多天。上下文只对能看到该信号的用户显示；信号不属于本租户或用户看不到它时，上下文条不出现，页面只显示公共部分，不提示该信号是否存在；
3. 公告在信号判断之后被更正或撤回时，上下文条提示“信号判断后公告已更正（v3），当前显示更正后的值，可切换到‘信号判断时’查看”，与第3段已确认事项第11项的提示一致；
4. 对象页也可从对象页之间的链接、地址栏直接打开，此时没有信号上下文。

### F2 页面结构与分区

1. 每个对象页由若干**分区**组成，每个分区独立加载、独立给出状态（正常、空、加载、不可用及原因、数据截至时间）。一个分区失败或受限不影响其他分区，页头汇总“2 个分区暂不可用”；
2. 每个分区显示自己的数据截至时间与时间轴（第5节“时间轴必须标明”），例如“公告截至 10-17 08:40（按来源发布时间排序）”“企业登记信息观察于 10-16 21:05”“统计截至 10-17 03:00，覆盖 2024-01 起”；
3. 所有字段按第 F6 节的字段状态展示；金额区分预算、最高限价、中标金额、合同金额、投资额与费率，不跨类型、不跨标包相加（[产品需求落地规格第2节](../05-product-requirements.md#2-统一业务与交互规则)“合并采购”）；
4. 页面带租户与用户水印，不提供公共数据导出；
5. **缓存与每次响应的检查**：平台内部可以在租户之间共用的只有不可变的公共事实版本、实体版本与证据内容（按对象标识与版本为键，不含任何租户、用户或裁剪结果）。返回给用户的每个分区都按本次请求的调用方现场裁剪：身份与授权、覆盖范围、用途与来源权利（展示级别）、查看配额与安全上限，缓存命中也同样执行这些检查；水印、按本租户档案品类的筛选与本租户叠加内容只在响应时加上，不进入共享层。已裁剪的响应只按租户（含用户与权利、权益版本）缓存，不跨租户复用（[安全与租户第3节](../../03-architecture/06-security-and-tenancy.md#3-隔离层次)）。

### F3 采购项目页（`pp_`）

1. **概要**：项目名称、项目编号、采购人、代理机构、地区、采购方式、阶段（意向 / 公告 / 更正 / 候选人公示 / 结果 / 合同 / 终止）、首次发布时间；
2. **标包**：每个标包的标的明细、品类（来自品类增强，带置信度，第 F6 节）、预算与最高限价、中标结果（每家中标方一行：中标方、中标金额、名次、联合体成员），合同；信号所在标包展开并高亮；
3. **所属项目**：`part_of` 归属边给出的上位项目 `prj_`，显示建立方式（显式标识 / 匹配）、置信度与复核状态；合并采购可属于多个项目，逐个列出（[entity-graph 4.1](../../03-architecture/subsystems/entity-graph.md#41-关系的端点约束与版本)）；候选边的展示见第13节第8项；
4. **公告时间线**：本项目的全部公告（意向、招标、更正、澄清、候选人公示、结果、合同、终止、撤回），按来源发布时间排序，每条显示发布时间（保留原精度与时区，如“2026-10-09（仅到日）”）、平台记录时间与公告类型；更正公告列出它改了哪些字段（前值 → 后值），点开到原文；
5. **本租户**：本项目的信号（按用户能看的目标过滤）与跟进（第6段）；“报告漏报”入口（第3段 F8，预填对象与时点）。

### F4 项目页（`prj_`）

1. 概要：项目实体的名称、地区、建设单位（如有）、关联标识（项目代码、审批代码）；
2. **归属的采购项目**：按当前有效的 `part_of` 边列出采购项目与标包，每条显示边的方式、置信度与复核状态；
3. **跨采购项目时间线**：把各采购项目的公告、本租户信号与跟进合并到一条时间线（按来源发布时间，信号按发现时间），并标明默认使用“当前有效的归属边”；从信号进入时可切换为“信号判断时已记录的归属边”（第 F7 节）；
4. 投资审批、施工许可等 INF-INVP 事实在该领域上线前显示“投资项目数据未接入”。

### F5 组织页：中标方（总包）与采购人

组织页是同一个 `org_` 的页面，按进入角色默认展开对应分区（从“中标方”进入展开中标历史，从“采购人”进入展开采购历史）。

1. **登记信息**：名称、曾用名、统一社会信用代码、类型、状态（存续 / 注销等）、成立日期、注册资本、地区、经营范围，带证据；
2. **主要人员与出资人**：只显示登记来源公示的法定代表人、股东与出资比例、主要人员与职务，作为本企业登记信息的一部分，不可点击，不跨企业汇总，不提供以人名检索（[安全与租户第6节](../../03-architecture/06-security-and-tenancy.md#6-个人信息)、[entity-graph 4.2](../../03-architecture/subsystems/entity-graph.md#42-自然人关系端点)）；
3. **作为中标方**：近 3 年中标的项目列表（项目、采购人、地区、品类、中标金额、时间）与汇总（按年、地区、品类的项目数；金额按类型分别汇总），以及“含我方品类的项目”快捷筛选（品类来自本租户档案，筛选在本租户会话内完成，不写入公共数据）；联合体中标单列；
4. **供过的品牌**：沿 `supplied_brand` 列出该组织在中标或合同明细中供过的品牌及次数，并沿平台级 `brand_owned_by` 显示品牌归属的厂商。归属只来自品牌词表中带证据的声明或运营复核，不按制造商或供应商推断；同一时点多个归属并存时都显示并标“归属冲突”；品牌数据未就绪时显示“品牌数据未就绪”（M2-P13）；
5. **作为采购人**：近 3 年的采购项目与统计（按年、品类、采购方式、地区；常用代理机构），显示统计口径版本与截至时间；
6. **信用**：INF-CRED 上线前显示“企业信用数据未接入”；
7. **本租户**：本租户企业清单标记（客户 / 竞争对手 / 禁合作，[customer-context](../../03-architecture/subsystems/customer-context.md#4-拥有的数据租户域)）、与该组织相关的本租户信号（该组织为中标方或采购人的信号，按用户能看的目标过滤）、跟进（第6段）。研究报告只属于本租户，M2 不展示研究入口。

### F6 字段与证据

1. **字段状态**：每个字段显示以下之一，不把未知显示为空或零：

   | 状态 | 显示 | 依据 |
   |---|---|---|
   | 有值 | 值 + 证据角标；方法为模型时标“模型识别 · 置信度 0.86” | `FieldEvidence` 的方法与置信度 |
   | 已更正 | 当前值 + “已更正”；展开显示原值、更正公告与两处原文 | 采购项目聚合按更正应用后的当前值，更正公告的 `amendment.changes` |
   | 低置信 | 值灰显并标“低置信，待核对”，默认折叠（门槛见第13节第1项）；不作为事实陈述 | 方法、置信度、质量状态“可疑” |
   | 冲突 | 并列显示各候选值及各自证据，标“待核对” | 解析或聚合产生的冲突候选 |
   | 原文未提供 | “原文未提供” | 来源确实没有该字段 |
   | 未能识别 | “未能识别”，与“原文未提供”区分 | 解析失败或低于增强器发布门槛（品类低于 0.7 不出现） |
   | 不适用 | “不适用” | 例如框架协议第一阶段没有单项中标金额 |
   | 不可用 | 原因文案与下一步 | 来源权利限制、覆盖不足、数据未接入（第5节） |

2. **证据查看**：点证据角标打开证据面板（Web 右侧、H5 全屏），经 `ResolveEvidence`：
   - **文档证据**：规范化文档中高亮原文片段，显示快照保存时间、页码或段落、来源链接；
   - **记录证据**：显示来源记录的键与字段原值；
   - **派生证据**：显示转换（例如“区划新旧代码对照 2024 版”）与逐项输入，可逐层展开到文档或记录证据；
3. **展示级别**：按字段全部输入来源的权利逐维取最严格的结果（[数据架构第12节](../../03-architecture/02-data-architecture.md#12-来源权利与数据权益)）：全文 → 高亮并显示上下文；摘要 → 只显示被引用的片段；仅引用与链接 → 显示来源名称、公告标题与原文链接；不展示 → 不显示内容，显示“来源权利不允许展示（`rights.restricted`）”与可用的替代。派生字段的可见性取全部输入的交集；
4. **原文来源不可达**：证据来自平台保存的快照，来源网站暂不可达不影响查看，只在“打开来源页面”旁标“来源网站暂不可达（10-17 08:00 起）”；来源权利只允许保存元数据时没有快照正文，显示引用信息与来源链接；
5. **原文查看计量**：打开证据面板计入原文查看配额（第 F9 节）。

### F7 版本、更正与撤回

1. **两种视角**（[domain-intelligence 第11节](../../03-architecture/subsystems/domain-intelligence.md#11-事实撤回与恢复)）：
   - **当前**（默认）：业务有效口径，显示截至现在的业务有效值；撤回的公告显示为已撤回，并标注撤回是后来才发现的；
   - **信号判断时**（只在从信号进入时可选）：当时已知口径，用来解释“当时为什么这样判断”。历史锚点是信号实际固定的求值输入（[策略 DSL 4.3](../../03-architecture/11-policy-dsl.md#43-确定性与记录)）：求值单位及其版本（`subject`）、视图快照（`view_snapshot_hash`）、客户上下文快照版本（`context_snapshot_version`）、策略版本（`policy`）与**逻辑求值时间 T**（`evaluated_at`，触发事件的时间；回填时为被回放事件的时间）。
     - **先读固定的输入**：求值单位、视图快照中的各项与客户上下文快照，按信号记录的版本直接显示；这些版本就是规则求值所用的输入，即使某项版本的记录时间晚于 T（在线求值排队期间写入），也按快照显示；
     - **其余公共数据以 T 为记录截止**：没有固定在快照里的分区，取 `recorded_at` 不晚于 T 的版本与边（[entity-graph 4.1](../../03-architecture/subsystems/entity-graph.md#41-关系的端点约束与版本)）。这与求值和回放选取事实、实体与关系版本的方式相同（[learning 8.1](../../03-architecture/subsystems/learning.md#81-时点正确)），不使用信号的生成或写入时间：回填在 10-18 为 10-09 的事件求值，锚点是 10-09，不是 10-18；
     - **还原不了就标“历史不可用”**：视图快照已过保存期、固定的版本无法读取，或某分区无法按同样的输入还原时，该分区标“历史不可用”，不用更晚的版本补齐；
     - 页面顶部始终显示当前所用视角与锚点，求值时间与生成时间分别标注（“信号判断时 · 求值时间 2026-10-16 22:10 UTC+08:00 · 信号生成 2026-10-16 22:11”）。各分区在该视角下的取值见第 F7 节第5条；
2. **版本历史**：每个公告事实可展开版本历史，按平台记录时间列出版本（来源更正、解析修订、撤回、恢复），每个版本显示记录时间、原因与证据；
3. **撤回**：发布方撤回的公告在时间线与项目页上标“已撤回”，显示撤回原因、撤回生效时间（未声明时标“推定”）与平台发现时间；由该公告得出的当前值不再显示为当前事实，原值与原文在历史中按展示级别仍可查看并标“已撤回的原文”；
4. **恢复**：撤回被证明有误或重新发布时，显示“已恢复（恢复自 v2）”；
5. **“信号判断时”视角的分区取值**：信号已固定的输入直接按固定版本读取；其余支持历史的分区用当时已知口径查询，请求带口径与记录截止时点 T（信号的 `evaluated_at`），响应返回同样的口径与 T，页面据此标明；不支持历史或无法按同样输入还原的分区标“历史不可用”，不得以当前数据或更晚的版本代替：

   | 分区 | 历史视角下的取值 |
   |---|---|
   | 对象解析（组织） | 视图快照中有该组织的，按快照记录的实体版本解析；没有的，`GetEntity` 按当时已知口径与 T 解析：T 时 A 仍独立就显示 A，即使 A 现已并入 B；T 时 A 已并入 B 就显示 B，即使之后合并被撤销。当前的合并或撤销只在页头另行提示（“该企业现已并入 B”），不替换历史主体 |
   | 采购项目概要、标包与中标结果 | 信号固定的事实版本（`subject` 的版本）；同一项目的其他标包取 T 时已记录的版本 |
   | 公告时间线 | 只列 T 时已记录的公告与版本；之后才记录的不显示，只提示“之后另有 2 条，切换到当前查看” |
   | 所属项目、项目时间线 | T 时已记录的 `part_of` 边（`GetProjectChain`、`GetRelationships` 按 T 查询）；之后新增的不出现，之后撤销的仍出现 |
   | 登记信息、主要人员与出资人 | 视图快照中有的按快照版本；其余取企业登记事实在 T 时已记录的版本 |
   | 中标项目列表、采购项目列表 | 按当时已知口径与 T 查询事实（`QueryFacts`）；“含我方品类”筛选用信号固定的上下文快照版本中的品类 |
   | 供过的品牌与品牌归属 | 视图快照中有的按快照版本；其余取 T 时已记录的 `supplied_brand` 与 `brand_owned_by` 边 |
   | 汇总统计、组织画像 | 视图快照中有的统计项（如“采购人的历史采购摘要”）按快照值显示并标“求值所用”；其余 M2 不支持历史，标“历史不可用”（统计汇总表与画像读模型只维护当前值），不显示当前统计 |
   | 信用 | 数据未接入（与当前视角相同） |
   | 本租户：清单标记 | 信号固定的上下文快照版本中的清单（即规则求值所用的清单） |
   | 本租户：其他信号与跟进 | 标“历史不可用”，切回当前查看 |
   | 证据 | 指向固定版本的证据内容不可变；展示级别、覆盖与配额仍按当前的权利与权益判断（第 F2 节第5条），历史视角不放宽当前的边界 |

   固定输入从 `detection.ExplainSignal` 读取（视图快照中各项的对象与版本，以及上下文快照版本、策略版本与逻辑求值时间）；视图快照已过保存期时，原本靠快照还原的分区标“历史不可用”，不改用 T 截止的查询结果冒充求值所用的输入。

### F8 合并、拆分与归属变化

1. **打开时已合并**：用旧组织标识打开时，经合并历史解析到存续组织，页头显示“由 A 合并而来（10-18 09:30，依据：统一社会信用代码一致）”；
2. **查看期间发生合并**：页面不自动跳转，顶部提示“该企业已于 10-18 09:30 并入 B，当前页面内容截至打开时，刷新后显示合并后的企业”；在提示出现后发起的分区加载按新结果返回并标出；
3. **合并撤销（拆分）**：存续组织页提示“此前并入的 A 已恢复为独立企业，部分历史项目已移回 A”；旧标识的链接重新指向 A；已固定版本的引用（例如信号）按记录的版本仍可解释；
4. **归属边变化**：`part_of` 边被修订或撤销时，项目页时间线随之变化并提示“项目归属已调整（10-18）”；已有信号与跟进不改写，仍按 `pp_` 显示；
5. **信号中的实体变化**：信号记录的中标方因合并而变化时，第3段的信号更新与本页一致显示合并后的组织，信号详情保留原记录。

### F9 查看计量与配额

1. 对象查看与原文查看按套餐配额计量（[安全与租户第7节](../../03-architecture/06-security-and-tenancy.md#7-公共数据暴露控制)）。每次计量有一个固定的**计量操作标识**（租户、用户、被查看的对象或证据、计量日），每次页面请求是带自己请求标识的一次尝试；`commerce` 以计量操作标识去重，同一用户同一对象在同一计量日只计一次，刷新、返回、网络重发都不重复计（计量日的时区见第13节第3项）；
2. 额度用完时返回 `quota.exhausted`，显示已用量与重置时间；单次查看规模与列表翻页超过安全上限时返回 `limit.safety_cap`，说明缩小范围的办法；对象所在区域或信息领域不在覆盖范围时返回 `entitlement.coverage_insufficient`，不展示对象内容（[commerce 第8节](../../03-architecture/subsystems/commerce.md#8-不可用原因)）；
3. 计量服务暂不可用时按第13节第3项放行查看并事后补记。补记只补计数，不补授权：查看前的身份与授权、覆盖范围、来源权利与安全上限照常检查，任一不通过都不放行，计量不可用不放宽任何一项；安全上限与来源权利由 `gateway`、`evidence` 自己判断，不受计量可用性影响。

### F10 本段的写操作

本段以查看为主，只有以下写操作，各自沿用已有语义：

| 操作 | 语义 |
|---|---|
| 查看计量 | F9：计量操作标识去重，只有“计一次”这一个部分；已计过的为无变化 |
| 报告漏报 | 第3段 F8 与 F9：预填对象与时点（对象发布时间，保留原精度与时区）；操作标识与请求幂等键分开 |
| 跟进 | 第6段交付后出现，语义由第6段定义 |
| 报告数据问题 | 打开支持渠道表单，预填公共对象与字段引用；不修改公共事实，不传递本租户的信号或清单 |

## 5. 业务与权限规则

| 规则 | 说明 |
|---|---|
| 公共与租户分开 | 共享层只有不可变的公共事实、实体与证据版本；每个响应按调用方现场裁剪（授权、覆盖、用途、来源权利、配额与安全上限），缓存命中也执行；已裁剪或渲染的响应、水印、按本租户品类的筛选与本租户叠加内容不进入共享层，不跨租户复用。权利或权益变化后，相关租户的响应缓存失效，且因每次响应都现场检查，失效延迟也不会放出被拒绝的内容（F2 第5条） |
| 租户隔离 | 用其他租户的信号标识进入时，与不存在的信号一样只显示公共部分，不提示其存在；本租户叠加查询带租户上下文，跨租户访问失败 |
| 研究报告只属本租户 | 对象页将来展示研究报告时只展示本租户、用户有权查看的报告；M2 不展示 |
| 自然人只作登记信息 | 法定代表人、股东、主要人员只作为企业登记信息中的文本出现，不链接、不汇总、不检索；不对评标专家、监管人员展示任何汇总 |
| 品牌归属只取平台级关系 | 品牌归属只来自 `brand_owned_by`（词表声明或运营复核）；制造商、供应商、本租户清单都不作为归属依据 |
| 派生可见性 | 字段与证据的展示级别按全部输入来源逐维取最严格的结果；统计按其权利条目，没有“聚合后可展示”声明的按原权利 |
| 未知不显示为空 | 原文未提供、未能识别、低置信、冲突、不适用、不可用分别显示，不显示为空、零或“无” |
| 时间轴必须标明 | 每个时间线、历史与统计都写明所用时间轴：公告时间线按来源发布时间（同时显示记录时间），版本历史按平台记录时间，撤回按业务生效时间并显示发现时间，信号按发现时间，归属边按“当前有效”或“某时点已记录”；时间保留原精度与时区 |
| 两种视角不混用 | “当前”用业务有效口径，“信号判断时”以信号固定的求值输入为锚点：固定版本直接读取，其余以逻辑求值时间 T（`evaluated_at`）为记录截止，不以信号生成时间为截止；同一屏幕不混排两种口径的值。支持历史的查询带并返回口径与记录截止时点（或固定版本）；不支持历史或无法按同样输入还原的分区标“历史不可用”，不以当前数据或更晚的版本代替；旧标识按指定的历史时点解析，当前的合并状态只另行提示（F7 第5条） |
| 数据截至时间 | 每个分区显示数据截至时间；来源中断时显示受影响来源与中断起点 |
| 合并与归属变化 | 旧标识经合并历史解析；查看期间的变化以提示呈现，不静默替换已显示内容 |
| 反馈不改事实 | 用户发现的数据问题经支持渠道报告，不修改公共事实（[业务不变量第12条](../../02-business/01-business-architecture.md#7-业务不变量)） |
| 暴露控制 | 列表有翻页深度与条数上限，统计不提供明细导出；页面带水印；配额与安全上限按 F9 |

## 6. 状态

```text
字段：      有值 / 已更正 / 低置信 / 冲突 / 原文未提供 / 未能识别 / 不适用 / 不可用（原因）

公告事实（时间轴：平台记录时间）：
  版本 n ──来源更正或解析修订──► 版本 n+1
         ──发布方撤回──► 已撤回（业务生效时间可早于记录时间）──恢复──► 已恢复（恢复自版本 k）

组织（时间轴：合并事件的记录时间）：
  独立 ──合并──► 已并入存续组织（旧标识解析到存续组织）──合并撤销──► 独立

归属边 part_of（时间轴：有效区间与记录时间）：
  候选 ──复核──► 已确认 ──修订──► 已修订（指向新边）
                         └──撤销──► 已撤销

分区：      加载中 ──► 正常 / 空（原因）/ 不可用（原因码）/ 失败（可重试）

查看计量（每个计量操作标识）：
  未计 ──首次成功的尝试──► 已计（之后同一标识为无变化）
       └──尝试失败──► 未计（重试为新的尝试，同一标识）
```

## 9. 异常、重试与撤销

| 情况 | 处理 |
|---|---|
| 某个分区查询失败 | 该分区显示“暂不可用，可重试”，其他分区照常显示；重试只重新加载该分区 |
| 来源权利不允许展示 | 字段或证据显示 `rights.restricted` 文案与替代（来源链接）；不显示超出展示级别的内容 |
| 覆盖不足 | 整页只显示对象名称与原因 `entitlement.coverage_insufficient`，不展示内容 |
| 配额用完 / 安全上限 | `quota.exhausted` 显示已用量与重置时间；`limit.safety_cap` 说明缩小范围的办法，不提示升级套餐 |
| 来源网站不可达 | 证据照常从快照显示，标注来源不可达的起点；数据截至时间按最近一次成功采集 |
| 公告被撤回 / 更正 | 按 F7 显示；从信号进入时提示信号判断后的变化 |
| 查看期间合并、拆分或归属变化 | 按 F8 提示；已显示内容不静默替换 |
| 证据解析失败 | 显示“原文定位暂不可用”与快照链接，不显示猜测的片段 |
| 计量请求超时 | 客户端用同一请求标识重发；服务端以计量操作标识去重，不重复计 |
| 本租户分区查询失败 | 只影响信号、清单、跟进分区；公共部分照常显示 |

本段没有可撤销的写操作：计量不可撤销；报告漏报与跟进的撤销按第3段与第6段。

## 10. 非功能要求

- 对象页首屏（概要与首个分区）p95 ≤ 1.5 秒，其余分区 p95 ≤ 3 秒；证据面板 p95 ≤ 1.5 秒；
- 页面保持打开时每 60 秒检查一次对象的事实版本、实体版本与归属边版本（第13节第5项），变化在下一次检查内提示；

## 13. 已确认事项

以下事项由项目负责人 Sean 于 2026-10-18 确认（[PR #22 决策记录](https://github.com/SuperAILabs/MiaoQia/pull/22#issuecomment-6252574382)），附带的约束来自同一 PR 的技术评审。

| # | 事项 | 确认方案 | 理由 |
|---|---|---|---|
| 1 | 低置信字段的展示门槛 | 方法为模型且置信度低于 0.8，或质量状态为“可疑”，显示为“低置信，待核对”，默认折叠；品类沿用增强器发布门槛 0.7，低于的不出现 | 与 A02 模板默认证据门槛 0.8 一致，用户在页面上看到的“事实”与规则求值所用的一致；低于门槛仍可展开，便于核对 |
| 2 | 从信号进入时的默认视角 | 默认“当前”，有差异时上下文条提示，可切换到“信号判断时” | 销售要据最新事实行动；解释旧判断是次要需求，不应让用户默认看到过期值 |
| 3 | 查看计量的口径与故障处理 | 对象查看与原文查看按（租户、用户、对象或证据、计量日）计一次，计量日按租户所在时区（默认 Asia/Shanghai）；`commerce` 暂不可用时放行查看并在本地记录，恢复后按计量操作标识补记；补记只补计数，身份、覆盖、来源权利与安全上限照常检查，不因计量不可用放宽 | 刷新与返回不应消耗配额；计量故障不应阻断已签约客户的日常使用，反爬取由不依赖计量的安全上限保护 |
| 4 | 列表条数与翻页上限 | 组织页列表每页 20 条，最多翻到 200 条；统计不受此限，不提供明细导出 | 近 3 年的中标或采购在多数总包、采购人上不超过 200 条；上限防止借对象页遍历公共数据 |
| 5 | 打开页面时的变化检查 | 每 60 秒检查一次版本，变化以提示呈现，不自动刷新 | 用户正在看的内容被静默替换会造成误判；60 秒足够让查看期间的合并或撤回被发现 |
| 6 | 已撤回公告的原文是否可看 | 可看，在历史中按展示级别显示并标“已撤回的原文”；当前视角不再把它作为当前事实 | 撤回本身是需要解释的事实；隐藏原文会让已有信号与判断无法解释 |
| 7 | 主要人员与出资人的展示范围 | 只显示登记来源公示的法定代表人、股东与出资比例、主要人员与职务，作为本企业登记信息文本；不链接、不跨企业汇总 | 满足销售判断“这家企业是谁在管”的需要，同时守住不建个人画像、不以人为入口的边界 |
| 8 | 归属边候选的展示 | 已确认或置信度 ≥ 0.9 的边显示为“所属项目”并进入项目时间线；其他候选边只在采购项目页显示为“可能相关的项目（待复核）”，不进入时间线 | 错误的归属会把别的项目的公告拼进时间线；候选可见但不混入，便于用户自行判断 |
| 9 | M2 项目页的范围 | M2 项目页只由采购项目经归属边组装；INF-INVP 上线前，没有归属边的采购项目只有采购项目页，不新建空的项目页 | M2 没有投资项目数据，多数采购项目没有上位项目；空项目页没有信息量 |
| 10 | 对象页是否提供“关注” | 本段不提供，随关注功能 PRD（B03 变化监测）一起交付 | 关注涉及个人与目标两种归属、数量权益与变化简报，单独设计更完整 |
| 11 | 统计窗口 | 中标与采购历史默认近 3 年，按覆盖起点截断并写明；金额按类型分别汇总 | 与 A02“近三年”规则一致；不同金额类型相加会得出错误总价 |
