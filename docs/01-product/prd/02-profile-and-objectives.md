# PRD 第2段：客户档案、角色与目标

> 状态：评审中 · 版本：1.2 · 更新：2026-10-15 · 负责人：产品负责人、客户智能负责人、招投标领域负责人 · 原型：[prototypes/02-profile-and-objectives.html](prototypes/02-profile-and-objectives.html)（[在线预览](https://claude.ai/artifact/6D47XeNuNcu9vLWPmvhn9o)）

本段让建材供应商把“我们是谁、卖什么、在哪卖、和谁打交道”录成结构化档案，并按角色模板启用 A02 进入供货目标。它承接第1段（管理员和成员已就位），产出第3段信号所需的两样东西：客户上下文快照（`GetContextSnapshot`）和 A02 目标的策略草案。策略草案的首次激活要经过仿真与审批，流程在第7段；在旅程顺序上，第7段的首次激活发生在本段之后、第3段之前。

## 1. 用户与目标

| 用户 | 角色 | 本段要完成的事 |
|---|---|---|
| 客户 IT 或负责人 | 租户管理员 `admin` | 关联本企业的公共组织、选择价值链角色与行业、导入客户和竞争对手清单 |
| 产品或技术负责人 | 业务专家 `domain_expert` | 维护产品品类、品牌、服务区域与资质；也可做管理员的档案工作 |
| 销售负责人 | 决策者 `decision_maker` | 启用 A02 目标，指定负责人与参与人，确认参数，提交首次激活（第7段） |
| 销售 | 业务开拓者 `business_developer` | 作为目标参与人，查看目标与命中规则（◐） |

权限依据 [identity 7.2](../../03-architecture/subsystems/identity.md#72-权限矩阵)：维护档案需 `can_edit_profile`（业务专家、管理员），创建目标需 `can_create_objective`（决策者），管理参与人需 `can_manage_participants`。小型客户常由一人兼任，管理员给其同时绑定业务专家与决策者角色即可。

**成功标准**：一家建材供应商在半天内完成档案与 A02 目标配置；配置后客户能在目标页看懂每条规则用到了档案里的哪一项、哪些规则因数据未接入暂不生效。

## 2. 范围

| M2 包含 | 不在 M2 |
|---|---|
| 关联本企业的公共组织（统一社会信用代码或名称检索）；集团客户可关联多个我方法人 | 个人主体档案（见第13节第5项）；按组织单元覆盖档案的界面（数据模型已支持，见 F3） |
| 价值链角色多选（MFR、DEALER、BIDDER、PRIME）、行业包多选（建材管材先行） | 投资与研究机构角色 `ROLE-INVESTOR` 的档案（随 M3 B05） |
| 产品品类、品牌、服务区域、资质（手工录入并附证书文件） | 资质与业绩的批量导入（随 A01 的交接，见第13节第6项） |
| 客户、竞争对手、禁合作三类企业清单的手工维护与表格导入 | 伙伴、跟踪对象、交易对手清单（随 B03/B05/C01） |
| 按角色模板列出可启用目标；启用 A02、配置参数、负责人与参与人；停用目标 | 自然语言调优与追加规则（第7段） |
| 目标页逐条展示规则、所用档案字段与数据可用性 | 知识资产上传（随研究，M3） |

## 3. 前置条件

- 第1段已交付：成员、角色与组织单元可用；
- APP-TENDER 包含角色模板与 A01/A02/B03 目标实例，建材管材行业包含完整品类、词表与默认排除（[阶段基线 M2-P2](../../05-delivery/06-stage-baseline.md#4-m2-前置条件与能力交接)）；
- INF-ORG 企业数据可检索（M2-P11），`entity-graph.ResolveEntity` 可用；
- `domain-intelligence` 按信息领域发布服务状态，目标页据此标示“数据未接入”（M2-P3）。

## 4. 主流程

### F1 关联本企业

1. 管理员或业务专家在“设置 / 客户档案”输入统一社会信用代码或企业名称，系统经 `ResolveEntity` 返回候选（名称、代码、注册地、成立时间、匹配置信度）；
2. 统一社会信用代码精确命中时直接给出唯一候选；仅名称检索时，最多列出 10 个候选，由操作人选择，不自动选中；
3. 确认后写入档案的我方主体列表（`org_ids`）。集团客户可依次关联多个法人（例如母公司与各子公司），每个主体可指定所属组织单元。A02 的 X-SELF 规则（我方即中标方）对全部我方主体生效，任一我方主体中标都按“我方中标”处理；模板随契约批次从 `profile.org_id` 改为 `profile.org_ids`。X-SELF 是排除规则，按[策略 DSL 4.2](../../03-architecture/11-policy-dsl.md#42-处置决策)，排除规则结果为未知时不生效、只记入轨迹，处置仍由其他规则决定。所以未关联时我方自己中标的项目可能以供货线索出现。档案总览与目标页提示“未关联本企业，X-SELF 暂不生效，我方中标的项目可能出现在信号中”，信号解释中 X-SELF 显示为“未知，未生效”；提交首次激活（第7段）时再次提示，不阻断；
4. 我方主体可增删，变更写入新档案版本并审计；删除最后一个主体前提示 X-SELF 将暂不生效。

### F2 角色与行业

1. 选择价值链角色（可多选）与行业包（可多选，例如管材加阀门的厂商选两个包，品类树按包分区）。投资与研究机构角色可以不选行业包，使用平台跨行业品类。建材管材在 M2 完整可用；信息化、环保水务行业包未交付时显示“暂未开放”，不可选；
2. 角色决定第 F5 步可启用的目标与默认参数：MFR 默认 A01、A02、B03；DEALER 默认 A01、A02；多选时合并（[发布计划 3.1](../../02-business/application-domains/tendering/05-release-plan.md#31-首发提供的价值链角色模板)）。C01 等 M3 目标显示为“M3 开放”。目标目录中与建材商家相关的后续目标也列出并标开放批次，不可启用，让客户看到完整的目标版图：A04 规格与品牌入围（向设计院、业主推介产品与样品，进入选型与品牌库）、A05 合作组队（联合体与伙伴）、B02 市场研究与布局（市场规模与趋势）、B04 价格与报价基准，均为 R2（[发布计划第2节](../../02-business/application-domains/tendering/05-release-plan.md#2-商业目标分批)）。

### F3 产品、品牌、区域与资质

1. **品类**：从行业包品类树中勾选（例如 管材 → PE 管）。勾选上级等于包含全部下级，与 `category.any_match` 语义一致；
2. **品牌**：录入自有或授权品牌，用于识别中标方是否使用我方或竞争对手品牌；
3. **服务区域**：按行政区划选择省、市、区县，选上级包含全部下级；
4. **资质**：选择资质所属的我方主体，录入资质类型（行业包资质模板）、等级、证书编号、有效期，并上传证书文件（经 `evidence` 文档处理保存）。客户录入与公共记录（`INF-QUAL` 上线后）作为两份来源观察分别保存，不合并：按证书编号、所属主体、发证机构、资质类型与有效期匹配；公共记录引用固定版本，并记录核验时间与核验状态（一致 / 待核对 / 未查到）。不一致时显示“待核对”并保留双方证据，不自动覆盖；公共数据未接入或未查到时，不推断客户没有该资质。到期前 30 天提醒业务专家；过期资质在快照中标为过期。未录入的资质一律视为“未知”，不默认满足；
5. 每次保存形成新的档案版本（`ProfileVersion`），带乐观并发版本号；两人同时编辑时后提交者收到冲突提示并看到差异，不覆盖他人修改；
6. **按组织单元覆盖**：数据模型支持某个组织单元覆盖品类、区域与资质（例如只做燃气管的子公司）。目标求值使用目标所在单元的合成档案：单元覆盖优先，未覆盖的项取租户档案，快照记录合成结果与各来源版本。M2 界面只维护租户档案，单元覆盖在集团客户试点时开放。

**档案变更对目标的影响**：策略参数中带 `default_from` 的项（如 A02 的品类、区域）在求值时从客户上下文快照读取，档案变更对之后的新求值立即生效，不需要重新激活策略。“立即”的边界见第5节“生效边界”；已有信号保留发现时的快照版本，解释不变（[策略 DSL 4.3](../../03-architecture/11-policy-dsl.md#43-确定性与记录)）。因此保存会影响判断的字段（品类、区域、品牌、资质、本企业关联）前，页面列出受影响的目标与规则，提示“保存后新到达的公告按新档案判断”，并写审计。

### F4 企业清单

1. 三类清单：客户（A02 加分：中标方是我方已有客户）、竞争对手（A02 减分：中标方使用过竞争对手品牌）、禁合作（A02 排除）；
2. 手工添加：同 F1 的检索与确认；
3. 表格导入：下载模板（企业名称、统一社会信用代码可选、备注，以及可选的属性列，如经销商的授权品牌与区域；属性列在 M2 保留原文、不进入规则，随租户私有关系模型启用），上传 CSV 或 Excel，单次最多 5000 行。导入是异步作业（`202` 与作业标识），完成后逐行给出结果：
   - 统一社会信用代码精确命中：自动匹配，免逐条选择，但同样要在第 4 步提交后才写入；
   - 仅名称且只有一个高置信候选（≥ 0.9）：标为“待确认”，默认勾选，需人工确认；
   - 多个候选或置信度不足：标为“需选择”；
   - 无候选：标为“未匹配”，保留原文，不进入规则；
4. 匹配完成不改变清单与快照。操作人在结果页看到影响提示（同 F3，列出受影响的目标与规则）后点“提交”，代码命中行与已勾选确认的行一次写入 `TenantEntityList` 并进入快照；需选择的行逐条选定后同样经提交写入。同一企业重复导入不产生重复项；
5. 手工添加与删除同 F3，保存前提示受影响规则；所有清单变更写审计。

### F5 启用 A02 目标

1. 决策者在“目标”页看到按角色模板列出的可启用目标，每个目标说明它找什么、用哪些数据、在哪个阶段可用；
2. 点“启用 A02 进入供货”进入向导：
   - **范围**：选择目标所属组织单元（目标及其信号、判断归属该单元，见 [identity 7.1](../../03-architecture/subsystems/identity.md#71-主体角色与范围)）；
   - **负责人与参与人**：负责人默认为当前决策者；参与人从该单元成员中选择，参与人可查看目标与信号（◐），业务开拓者成为参与人后才能收到本目标信号；
   - **参数**：品类、区域默认来自档案（显示“随档案”），可改为仅本目标使用的子集；最低金额、大额阈值使用模板默认值；
   - **规则预览**：逐条列出模板规则（硬条件、排除、观察、加分、减分），每条显示说明文字、用到的档案字段或清单、所需数据及其可用性。M2 中 B-PERMIT（施工许可）与 P-CREDIT（中标方信用）所需信息领域未上线，标“数据未接入，暂不生效”，不显示为已生效（M2-P3）；
3. 完成向导后创建 `TenantObjective`（状态“未激活”）和第一版策略草案。目标页显示下一步“提交首次激活”，进入第7段的仿真与审批；首次激活前目标不产生信号；
4. 同一租户同一组织单元下，同一目标模板只能启用一次；需要不同参数时在第7段调整策略，而不是再启用一份。

### F6 调整与停用目标

1. 负责人、参与人和参数可调整：负责人与参与人变更即时生效并审计；参数变更形成新的策略草案，按第7段仿真与审批后生效；
2. 停用目标需 `can_edit`，确认页说明“停用后不再产生新信号，已有信号、跟进与反馈保留”。停用后可重新启用，重新启用沿用最近的策略版本，并按第7段重新激活。

## 5. 业务与权限规则

| 规则 | 说明 |
|---|---|
| 未知不等于满足 | 未录入的资质、未关联的本企业、未匹配的清单行在规则中都是“未知”，按 [策略 DSL 4.2](../../03-architecture/11-policy-dsl.md#42-处置决策) 处理：硬条件按其 `missing`；排除规则为未知时不生效、记入轨迹；加分、减分规则为未知时不计分。界面如实显示“未知”，不显示为满足或不满足 |
| 档案是事实，策略是判断 | 档案描述客户事实，变更即时影响新求值，不走策略审批；策略规则和阈值的变化走第7段 |
| 生效边界 | 档案或清单的每次提交在同一事务中递增租户的上下文版本。`UpdateProfile`、清单提交返回后才开始的求值一律使用不低于该版本的快照：detection 每批求值前读取当前上下文版本，本地缓存较旧时先按版本重新加载快照；变更事件只用于提前刷新缓存，丢失或迟到不影响正确性，版本不高于缓存的事件被忽略。读取版本失败时该批求值重试，不用可能过期的缓存求值。提交前已开始的求值使用旧版本，信号记录所用快照版本 |
| 影响提示与审计 | 保存会影响判断的档案字段或清单前，列出受影响的目标与规则；所有档案、清单、目标变更写审计，记录前后值 |
| 版本与并发 | 档案、清单、目标配置都有版本号，并发编辑以版本冲突返回，不静默覆盖 |
| 自动匹配只认确定标识 | 只有统一社会信用代码精确命中可自动匹配；名称匹配一律人工确认 |
| 数据可用性如实显示 | 规则所需信息领域未上线时标“数据未接入”，按启用领域集合固定在策略版本中（[策略 DSL 3.3](../../03-architecture/11-policy-dsl.md#33-模板与租户策略的合成)） |
| 目标可见性 | 目标归属一个组织单元。目标列表与详情按 `can_view`：参与人，以及目标单元（含上级单元继承）的决策者、研究分析者、管理员；信号按 `can_view_signals`，管理员能看目标不等于能看信号。业务开拓者等依赖参与关系的角色未加入参与人时看不到目标；兄弟单元的成员按授权关系判断，不按人的所属部门判断（[identity 7.2](../../03-architecture/subsystems/identity.md#72-权限矩阵)） |
| 租户私有 | 档案、清单、目标均为租户私有，启用行级安全；跨租户不可见 |

## 6. 状态

```text
档案：      新建 ──保存──► 版本 n ──保存──► 版本 n+1（每次保存一个版本，可查看历史与差异）

清单导入：  已上传 ──解析──► 匹配中 ──► 待提交 ──看过影响提示后提交──► 已完成（逐行：已匹配 / 待确认 / 需选择 / 未匹配；提交前快照不变）
                      └──文件无效──► 失败

目标：      未激活 ──首次激活（第7段）──► 生效 ──停用──► 已停用 ──重新启用──► 未激活
                                               └──参数调整──► 生效（新草案待激活，旧版本继续生效）

资质：      有效 ──到期前30天──► 即将到期 ──到期──► 已过期
```

## 7. 界面与原型

原型：[prototypes/02-profile-and-objectives.html](prototypes/02-profile-and-objectives.html)。原型只演示各页面的状态与文案，完整任务流程以第 12 节的走查为准。

| 页面 | 正常 | 空态 | 加载 | 无权限 | 过期 | 失败 | 部分成功 | 来源中断 | 数据未知 |
|---|---|---|---|---|---|---|---|---|---|
| 客户档案总览 | ✓ | 未填写档案 | ✓ | 只读（无 `can_edit_profile`） | 档案已被他人修改（版本冲突）；资质即将到期/已过期 | 保存失败 | — | — | 未关联本企业；资质未录入 |
| 关联本企业 | ✓ | 无候选 | ✓ | 无 `can_edit_profile` | — | 检索失败 | — | 企业库不可用 | 候选置信度不足 |
| 品类与区域 | ✓ | 未选择 | ✓ | 只读 | 版本冲突 | 保存失败 | — | — | — |
| 企业清单与导入 | ✓ | 清单为空 | ✓ | 只读 | — | 文件无效 | 部分行未匹配 | 企业库不可用，导入暂停 | 需选择、未匹配的行 |
| 目标列表 | ✓ | 未选角色，无可启用目标 | ✓ | 无 `can_view`（如非参与的业务开拓者）看不到该目标 | — | — | — | — | — |
| 启用 A02 向导与目标页 | ✓ | — | ✓ | 非决策者不能启用 | 策略草案基于旧模板版本 | 创建失败 | — | — | 规则“数据未接入”；参数随档案但档案为空 |

“—”表示按实际流程不会出现：档案与目标的单次保存没有部分成功；品类与区域取自行业包与行政区划，本地数据不依赖外部来源；目标列表只读本租户数据。所有错误文案说明原因与下一步。

## 8. 数据、接口与事件

实体与接口语义以 [customer-context](../../03-architecture/subsystems/customer-context.md) 为准，本段新增项已同步写入。

| 所有者 | 实体 / 接口 | 本段用途 |
|---|---|---|
| customer-context | `CustomerProfile` / `ProfileVersion`：主体类型（M2 仅企业）、我方主体列表 `org_ids`（可挂组织单元）、价值链角色、行业包列表、品类、品牌、服务区域、单元覆盖、版本号 | F1–F3 |
| customer-context | `Qualification`：类型、等级、证书编号、有效期、证书文件引用、状态 | F3 |
| customer-context | `TenantEntityList` 与 `EntityListImport`（导入作业：文件、逐行结果、状态） | F4 |

## 9. 异常、重试与撤销

| 情况 | 处理 |
|---|---|
| 企业库或 `ResolveEntity` 不可用 | 关联与手工添加不可用并说明；导入作业暂停，恢复后继续，不丢已上传文件 |
| 导入文件格式错误或超过 5000 行 | 整个文件拒绝，说明原因与模板下载入口，不做部分写入 |
| 导入部分行未匹配 | 已匹配与已确认的行可先提交生效；未匹配行保留原文，可下载结果表修改后重新导入；重复导入不产生重复项 |
| 档案并发编辑 | 后提交者收到版本冲突，看到他人修改的差异，选择基于新版本重新编辑 |
| 证书文件处理失败 | 资质记录保留，文件状态显示“处理失败，可重新上传”；资质不因文件失败而视为有效 |
| 启用目标时模板已有新版本 | 默认使用当前模板最新版本；已启用目标的模板升级在第7段提示 |
| detection 读取上下文版本失败 | 该批求值重试，不用可能过期的缓存求值；超过重试上限进入死信并告警，恢复后重放 |
| 误删清单企业 | 删除写审计，可从变更历史中恢复该条 |
| 停用目标 | 可重新启用；重新启用后按第7段重新激活 |

## 10. 非功能要求

- 档案与目标页面 p95 ≤ 1.5 秒；`ResolveEntity` 单次检索 p95 ≤ 1 秒；5000 行导入在 10 分钟内完成匹配；
- 档案、清单提交返回后开始的求值使用新版本（第5节生效边界）；`GetContextVersion` p95 ≤ 50 毫秒，detection 每批求值读取一次；
- 档案与清单为租户私有数据，跨租户负向用例覆盖档案、清单、导入作业、目标与快照接口；
- 导入文件只用于本次导入，结果生成后原文件按租户数据保留期限清理。

## 11. 埋点

记录租户、用户、动作、耗时、结果与原因码：档案各部分完成时间、本企业关联方式（代码或名称）、导入行数与各类匹配结果占比、启用目标向导各步耗时与放弃点、规则预览中“数据未接入”规则数、档案变更影响提示的展示与取消次数。重点看从第一次打开档案到 A02 目标提交首次激活的总耗时。
