# PRD 第1段：登录与渠道绑定

> 状态：评审中 · 版本：1.0 · 更新：2026-10-15 · 负责人：产品负责人、身份与渠道负责人 · 原型：[prototypes/01-login-and-channel-binding.html](prototypes/01-login-and-channel-binding.html)（[在线预览](https://claude.ai/artifact/5Fo8kJ5Y3FzdrMMTr1apiY)）

本段让一家建材供应商从开通到“销售在企业微信收到妙洽消息、点开卡片在手机上看到同一账号下的内容”。它是首条旅程（A02 进入供货）后续各段的前提：第2段的客户档案由本段激活的管理员录入，第5段的简报与卡片只发给本段绑定的成员。

## 1. 用户与目标

| 用户 | 角色 | 本段要完成的事 |
|---|---|---|
| 平台运营 | 妙洽内部 `operator` | 为签约客户开通租户并指定首位管理员（M0 已实现） |
| 客户 IT 或负责人 | 租户管理员 `admin` | 激活账号，安装企业微信应用，邀请销售与决策者并分配角色和组织单元 |
| 销售 | 业务开拓者 `business_developer` | 接受邀请，绑定企业微信，从卡片进入 Web 不需要反复登录 |
| 销售负责人 | 决策者 `decision_maker` | 同上；首次审批前完成多因素认证登记 |

**成功标准**：管理员在一个工作日内完成开通到首批成员绑定；成员从企业微信卡片打开 Web 页面时，在企业微信内置浏览器中不需要输入密码。

## 2. 范围

| M2 包含 | 不在 M2 |
|---|---|
| 首位管理员激活；邮件邀请成员（含组织单元与角色）；邀请的撤回与重发 | 自助注册、跨租户自动加入 |
| 账号密码登录、多因素认证（TOTP）登记与按需强认证；会话与退出 | 一个账号属于多个租户及租户切换（见待决事项2） |
| 企业微信、飞书、钉钉的租户级安装与停用；邮件渠道 | SAML、通用 OIDC 企业身份源；海外渠道 |
| 成员绑定与解绑渠道账号；管理员查看与强制解绑 | 外部协作者登录（随 M4 推进） |
| 在已绑定渠道的内置浏览器中打开妙洽链接免登（见待决事项1） | 服务账号、API 凭证、MCP 客户端（按需单独交付） |
| 响应式 H5 | 原生应用 |

## 3. 前置条件

- [M0 身份生命周期](../../05-delivery/07-m0-identity-acceptance.md)已验收：租户创建、成员加入退出、角色变更、撤权与 cell 路由；
- 渠道方案 C10 已批准，各渠道按[阶段基线 M2-P7](../../05-delivery/06-stage-baseline.md#4-m2-前置条件与能力交接)完成官方应用、回调、验签与真实客户测试安装；未验收的渠道在安装页不可选；
- 生产 IdP（Keycloak）的认证流程、TOTP 与身份代理配置通过部署验收；
- 邮件渠道可发送；不可发送时管理员可复制邀请链接（第 9 节）。

## 4. 主流程

### F1 首位管理员激活

1. 平台运营在 IdP 为管理员建立账号并开通租户（M0 的 `POST /v1/tenants` 以该账号的 IdP 主体为首位管理员），系统向管理员邮箱发送激活邮件，链接 72 小时有效；
2. 管理员打开链接，设置密码，并必须登记 TOTP（管理员命令要求已签名的 `amr=mfa`，见 [identity 第8节](../../03-architecture/subsystems/identity.md#8-安全要点)）；
3. 激活完成后进入“开始设置”页：安装渠道 → 邀请成员 → 客户档案（第2段）。三项可跳过，但页面始终显示未完成项。

### F2 邀请成员

1. 管理员在“设置 / 成员”点“邀请”，填写邮箱、姓名、组织单元和角色（可多选，租户管理员角色只能绑定在租户上，见 [identity 7.1](../../03-architecture/subsystems/identity.md#71-主体角色与范围)）；可一次粘贴多行批量邀请，逐行返回成功或失败原因；
2. 系统创建邀请并发送邮件，邀请 7 天有效；同一邮箱在本租户只能有一个有效邀请，重复邀请返回已有邀请并可重发；
3. 受邀人打开链接，新用户设置密码，已有妙洽账号的用户登录后确认；确认时页面展示租户名称、组织单元和角色；
4. 接受后写入成员与角色（沿用 M0 的成员命令），邀请变为“已接受”，同时以登录邮箱建立邮件渠道绑定；
5. 管理员可撤回未接受的邀请，可重发（重发使旧链接失效）。

### F3 登录与强认证

1. 登录页提供账号密码登录；已登记 TOTP 的账号登录时验证 TOTP；
2. 需要强认证的动作（成员与角色管理、渠道安装与停用、策略激活的申请与批准、凭证管理）要求当前会话在 15 分钟内完成过 TOTP，否则弹出强认证框，完成后继续原动作，不丢失已填写的内容；
3. 决策者首次执行需要强认证的动作时，引导登记 TOTP；未登记时动作不可提交，页面说明原因；
4. 退出登录使 Web 会话失效；成员被停用或退出租户后，下一次请求即被拒绝（M0 撤权边界）。

### F4 安装渠道（管理员）

1. “设置 / 渠道”列出企业微信、飞书、钉钉、邮件，每项显示状态与已绑定人数；
2. 管理员选择企业微信 → 跳转企业微信官方授权页 → 授权回调成功后进入“待验证”；
3. 管理员点“发送测试消息”，选择自己的企业微信账号（此时同时完成管理员本人的绑定），收到测试消息后点消息中的“确认”，渠道变为“已启用”；
4. 已启用后，管理员可设置“可见范围提示”（告诉成员在企业微信哪里找到妙洽应用），可停用渠道。停用使该渠道的全部绑定失效、不再投递，已投递的消息不撤回。

### F5 成员绑定渠道账号

两种入口，结果相同：

- **从渠道发起**：成员在企业微信中打开妙洽应用或给妙洽发消息 → 未绑定时只收到绑定引导卡片（不回答任何业务内容）→ 点“绑定账号”，打开一次性绑定链接（10 分钟有效）→ 在浏览器中登录妙洽 → 确认页展示“企业微信账号（显示名、所属企业）将绑定到 妙洽账号（姓名、租户）” → 确认后渠道内收到“绑定成功”；
- **从 Web 发起**：成员在“个人设置 / 渠道”点“绑定企业微信” → 页面给出二维码与步骤，扫码后进入上一种流程的确认页。

绑定规则：

- 渠道账号所在企业必须是本租户已安装的那个企业应用，否则拒绝并说明“该企业微信账号不属于本租户已安装的企业”；
- 一个渠道账号只能绑定一个妙洽成员；一个成员在同一渠道只能绑定一个账号；
- 确认时 Web 会话的用户必须与登录用户一致，绑定链接被转发给他人后，他人登录确认也只能绑定到链接所属的渠道账号，且渠道内会通知原渠道账号“该企业微信账号已绑定到 X”，以便发现误绑。

### F6 解绑与失效

- 成员可在“个人设置 / 渠道”解绑，解绑立即生效，渠道内收到一次“已解绑”通知；
- 管理员可在“设置 / 渠道 / 已绑定成员”强制解绑，记录原因；
- 成员停用、退出租户或渠道停用时，其绑定自动失效，不再投递，渠道内的动作按钮全部失效；成员重新加入后需重新绑定。

### F7 从渠道卡片进入 Web

1. 卡片上的详情链接是短时授权链接，只指向对象，不携带登录身份（[channels 4.1](../../03-architecture/subsystems/channels.md#41-渠道无关的消息表示)）；
2. 在已绑定渠道的内置浏览器中打开：用渠道的网页授权取得渠道账号，经绑定关系找到成员，直接建立 Web 会话（免登）；渠道账号未绑定或绑定已失效时，转到登录页并说明原因；
3. 在普通浏览器中打开：已有会话直接进入；无会话先登录，登录后回到原页面；
4. 已登录的是另一个成员时，不自动切换账号，提示“链接是发给 A 的，当前登录的是 B”，提供“退出并以 A 登录”；
5. 进入后按当前成员的权限读取对象，无权限时显示无权限页，不显示对象标题以外的内容；
6. 免登会话不满足强认证，执行强认证动作时仍按 F3 验证 TOTP。

## 5. 业务与权限规则

| 规则 | 说明 |
|---|---|
| 租户只来自认证身份 | 绑定、免登、卡片动作的租户都从已验证身份派生，链接、请求参数中的租户一律不信任 |
| 管理动作 | 邀请、撤回、角色变更、渠道安装与停用、强制解绑只由租户管理员执行（`can_manage_members`），并要求 15 分钟内的 TOTP |
| 渠道内只有绑定的成员 | 未绑定账号只收到绑定引导，任何查询与动作都不执行 |
| 渠道动作再次授权 | 卡片按钮执行时以绑定成员的当前权限再次 `Check`，令牌一次性（[channels 第10节](../../03-architecture/subsystems/channels.md#10-安全要点)） |
| 邀请不授予权限 | 邀请只是待接受的成员资格；接受前不能访问租户任何内容 |
| 末位管理员 | 不能撤销最后一位管理员的角色或使其退出（沿用 M0） |
| 审计 | 激活、邀请、接受、撤回、登录失败、TOTP 登记与重置、渠道安装停用、绑定解绑、强制解绑、免登建立会话均写审计 |

## 6. 状态

```text
邀请：  待接受 ──接受──► 已接受
          ├──撤回──► 已撤回
          ├──重发──► 待接受（新链接，旧链接失效）
          └──过期──► 已过期 ──重发──► 待接受

渠道安装：未安装 ──授权──► 待验证 ──测试消息确认──► 已启用 ⇄ 异常（凭证失效、回调失败，系统检测）
                                                    └──停用──► 已停用 ──重新授权──► 待验证

渠道绑定：未绑定 ──确认──► 已绑定 ──解绑 / 强制解绑 / 成员停用 / 渠道停用──► 已失效
```

“异常”由渠道健康检测置位，恢复后自动回到“已启用”；异常期间消息改投站内，并在管理员的渠道页显示原因与最近一次失败时间。

## 8. 数据、接口与事件

实体与接口的语义以子系统规格为准，本段新增项已同步写入 [identity](../../03-architecture/subsystems/identity.md) 与 [channels](../../03-architecture/subsystems/channels.md)。

| 所有者 | 实体 / 接口 | 本段用途 |
|---|---|---|
| identity | `Invitation`：邮箱、姓名、组织单元、角色、状态、邀请人、过期时间、接受人主体 | F1、F2 |
| identity | `CreateInvitation` / `ResendInvitation` / `RevokeInvitation` / `AcceptInvitation`、`ListInvitations` | F2；批量邀请逐行调用，每行带 `Idempotency-Key` |
| identity | 现有成员命令 `PUT /v1/identity/members/{subject}` | 接受邀请时写入成员与角色 |
| identity | `LinkFederatedIdentity` / `UnlinkFederatedIdentity` | 绑定或解绑时同步 IdP 的渠道身份关联，供 F7 免登 |
| channels | `ChannelInstallation`（状态、所属企业标识、健康状态）、`ChannelBinding`（渠道账号、成员、状态、失效原因） | F4–F6 |
| channels | `InstallChannel` / `VerifyInstallation` / `UninstallChannel`、`StartBinding` / `BindAccount` / `UnbindAccount`、`ListBindings` | F4–F6 |
| gateway BFF | 当前会话：成员、租户、角色、组织单元、TOTP 是否登记与最近验证时间、已启用能力、各渠道绑定状态 | 导航、强认证判断、“开始设置”未完成项 |

事件：

- 消费 `identity.member.changed.v1`（已实现）：channels 据此使停用或退出成员的绑定失效；
- 新增 `identity.invitation.changed.v1`（创建、接受、撤回、过期）与 `channels.binding.changed.v1`（绑定、解绑、失效），供审计、运营看板与第5段的投递名单使用。契约随实现写入 `contracts/events/`。

## 9. 异常、重试与撤销

| 情况 | 处理 |
|---|---|
| 邀请邮件发送失败 | 邀请仍创建，状态旁显示“发送失败”，可重发或复制邀请链接自行发送 |
| 批量邀请部分失败 | 逐行返回结果；失败行保留在输入框，可只重试失败行；同一 `Idempotency-Key` 重试不重复创建 |
| 重复点击接受邀请 / 确认绑定 | 返回同一结果，不重复写入或重复通知 |
| 绑定确认时渠道账号已被他人绑定 | 拒绝，提示联系管理员；管理员可在已绑定成员列表中查看并强制解绑 |
| 渠道回调重放或验签失败 | 丢弃并计入渠道健康，不改变任何状态 |
| IdP 不可用 | 登录页显示服务暂不可用，已有会话的只读页面继续可用，写操作返回可重试错误 |
| TOTP 设备丢失 | 成员联系管理员重置；管理员本人丢失时由另一位管理员重置，只有一位管理员时由平台运营经内部支持访问流程处理 |
| 渠道异常期间 | 消息改投站内；恢复后不补发已过期的提醒，简报按第5段规则处理 |

## 10. 非功能要求

- 登录、绑定确认、免登建立会话 p95 ≤ 2 秒（不含渠道平台与 IdP 自身耗时）；渠道回调 1 秒内确认、异步处理；
- 会话空闲 12 小时、绝对 7 天失效；强认证有效期 15 分钟（见待决事项3）；
- 登录失败 5 次锁定 15 分钟；绑定链接、激活与邀请链接一次性使用；
- H5 在企业微信、飞书、钉钉内置浏览器和主流手机浏览器中可完成 F2 接受邀请、F5、F7；
- 跨租户负向用例覆盖绑定、免登和卡片链接（[安全与租户第9节](../../03-architecture/06-security-and-tenancy.md#9-安全测试要求)）。

## 11. 埋点

只记录租户、用户标识、渠道类型、动作、耗时、结果与原因码：激活完成、邀请发出/接受/过期、渠道安装各步骤、绑定发起/完成/失败原因、免登成功/失败原因、强认证触发与完成、“开始设置”各项完成时间。重点看从开通到首批成员完成绑定的耗时，和卡片跳转中需要输入密码的比例。

## 12. 验收

**可运行**：在测试企业微信企业中，用真实管理员和两名成员（业务开拓者、决策者）走完 F1→F2→F4→F5→F7，留存走查记录。

**可解释**：第 7 节每个状态的原型文案经产品评审；未绑定、绑定冲突、账号不一致、渠道异常四种情况在走查中实际触发并截图。

**可验证**，自动化用例至少覆盖：

1. 重复接受同一邀请、重复确认同一绑定只产生一次成员写入与一次通知；
2. 撤回、过期、重发后的旧链接均不可用；
3. 非管理员或无 15 分钟内 TOTP 的管理员调用邀请、角色变更、渠道安装被拒绝；
4. 其他租户企业的企业微信账号不能绑定到本租户；同一渠道账号不能绑定第二个成员；
5. 成员退出后，其绑定失效，渠道内动作按钮执行被拒绝，免登被拒绝，旧 Web 会话的下一次请求被拒绝；
6. 渠道停用后全部绑定失效，消息改投站内；
7. 卡片链接在另一成员会话中打开时不切换账号，在无权限成员会话中只显示无权限页；
8. 回调重放、验签失败不改变状态；
9. 免登会话执行强认证动作时要求 TOTP。
