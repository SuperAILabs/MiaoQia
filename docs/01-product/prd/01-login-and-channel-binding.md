# PRD 第1段：登录与渠道绑定

> 状态：评审中 · 版本：1.4 · 更新：2026-10-15 · 负责人：产品负责人、身份与渠道负责人、安全负责人 · 原型：[prototypes/01-login-and-channel-binding.html](prototypes/01-login-and-channel-binding.html)（[在线预览](https://claude.ai/artifact/5Fo8kJ5Y3FzdrMMTr1apiY)）

本段让一家建材供应商从开通到“销售在企业微信收到妙洽消息、点开卡片在手机上看到同一账号下的内容”。它是首条旅程（A02 进入供货）后续各段的前提：第2段的客户档案由本段激活的管理员录入，第5段的简报与卡片只发给本段绑定的成员。

## 1. 用户与目标

| 用户 | 角色 | 本段要完成的事 |
|---|---|---|
| 平台运营 | 妙洽内部 `operator` | 为签约客户开通租户并指定首位管理员（M0 已实现）；在唯一管理员无法认证时执行管理员账号恢复 |
| 客户 IT 或负责人 | 租户管理员 `admin` | 激活账号，安装企业微信应用，邀请销售与决策者并分配角色和组织单元 |
| 销售 | 业务开拓者 `business_developer` | 接受邀请，绑定企业微信，从卡片进入 Web 不需要反复登录 |
| 销售负责人 | 决策者 `decision_maker` | 同上；首次执行强认证动作前登记验证码 |

**成功标准**：管理员在一个工作日内完成开通到首批成员绑定；成员从企业微信卡片打开 Web 页面时，在企业微信内置浏览器中不需要输入密码。

## 2. 范围

| M2 包含 | 不在 M2 |

| 账号密码登录、验证码（TOTP）登记与按需强认证；会话与退出 | 一个账号属于多个租户及租户切换（见第13节第2项） |

| 成员在渠道内绑定与解绑渠道账号；管理员查看与强制解绑 | 外部协作者登录（随 M4 推进） |

| 唯一管理员的账号恢复 | 原生应用 |

## 3. 前置条件

- [M0 身份生命周期](../../05-delivery/07-m0-identity-acceptance.md)已验收：租户创建、成员加入退出、角色变更、撤权与 cell 路由；
- 渠道方案 C10 已批准，各渠道按[阶段基线 M2-P7](../../05-delivery/06-stage-baseline.md#4-m2-前置条件与能力交接)完成官方应用、回调、验签、网页授权与真实客户测试安装；未验收的渠道在安装页不可选；
- 生产 IdP（Keycloak）的认证流程、TOTP、强认证时间声明与受控会话签发配置通过部署验收；
- 邮件渠道可发送；不可发送时管理员可复制邀请链接（第 9 节）。

## 4. 主流程

### F1 首位管理员激活

1. 平台运营在 IdP 为管理员建立账号并开通租户（M0 的 `POST /v1/tenants` 以该账号的 IdP 主体为首位管理员），系统向管理员邮箱发送激活邮件，链接 72 小时有效；
2. 管理员打开链接，设置密码，并必须登记 TOTP 后才完成激活（管理员命令要求已签名的强认证，见 [identity 第8节](../../03-architecture/subsystems/identity.md#8-安全要点)）；
3. 激活完成后进入“开始设置”页：安装渠道 → 邀请成员（建议至少再设一位管理员，第 9 节）→ 客户档案（第2段）。三项可跳过，但页面始终显示未完成项。

### F2 邀请与接受

1. 管理员在“设置 / 成员”点“邀请”，填写邮箱、姓名、组织单元和角色（可多选，租户管理员角色只能绑定在租户上，见 [identity 7.1](../../03-architecture/subsystems/identity.md#71-主体角色与范围)）；可一次粘贴多行批量邀请，逐行返回成功或失败原因；
2. 系统创建邀请并发送邮件，邀请 7 天有效；同一邮箱在本租户只能有一个有效邀请，重复邀请返回已有邀请并可重发；
3. 受邀人打开链接：新用户设置密码建立账号；已有妙洽账号的用户先登录。确认页展示租户名称、组织单元和角色；
4. 接受时由 identity 的 `AcceptInvitation` 独立授权，不经过成员管理接口（成员管理接口要求调用人是本租户的管理员，受邀人不满足）。`AcceptInvitation` 依次核验：
   - 邀请链接有效、邀请处于“待接受”且未过期，链接是当前这一次发出的（重发后旧链接失效）；
   - 接受人账号的已验证邮箱与邀请邮箱一致；新账号以邀请链接本身完成邮箱验证；
   - 接受人账号不属于任何其他租户（M2 一个账号只属于一个租户），否则拒绝并说明，不迁移、不新增第二个租户资格；
   - 邀请含租户管理员角色时，接受人必须已登记并刚完成 TOTP 验证；
5. 核验通过后，在一个事务中按邀请限定的组织单元和角色写入成员资格、把邀请置为“已接受”，并复用成员写入的内部逻辑（关系写入、审计、`identity.member.changed.v1`）。随后为该账号写入 IdP 中的租户与 cell 归属；写入完成前，该账号的令牌不含租户，访问一律被拒绝（失败关闭），写入失败按第 9 节重试；
6. 邀请上的状态变化以邀请版本串行：接受、撤回、重发、过期并发时只有一个生效，失败的一方按最新状态返回原因，不会写入超出有效邀请的角色或组织单元；
7. 接受后以登录邮箱建立邮件渠道绑定；管理员可撤回未接受的邀请，可重发（重发使旧链接失效）。

### F3 登录与强认证

1. 登录页提供账号密码登录；已登记 TOTP 的账号登录时验证 TOTP；
2. 强认证动作：成员与角色管理、渠道安装与停用、强制解绑、策略激活与回滚的申请和批准、凭证管理。执行时要求当前会话在 15 分钟内完成过 TOTP 验证。15 分钟以 IdP 签发的可信强认证时间计算，服务端执行：仅有 `amr=mfa` 不能证明新鲜度，刷新令牌、免登会话和延长会话都不会延长强认证窗口；
3. 不满足时弹出强认证框，验证后继续原动作，已填写内容不丢失；
4. 任何成员（不限角色）首次执行强认证动作时，若尚未登记 TOTP，先进入登记：扫码 → 输入验证码 → 登记完成即视为本次强认证，继续原动作。取消登记则原动作不执行、已填内容保留；验证码错误按登录失败计数。管理员在激活时、或被授予管理员角色后的首次登录时必须完成登记；
5. 退出登录使 Web 会话失效；成员被停用或退出租户后，下一次请求即被拒绝（M0 撤权边界）。

### F4 安装渠道（管理员）

1. “设置 / 渠道”列出企业微信、飞书、钉钉、邮件，每项显示状态与已绑定人数；
2. 管理员选择企业微信 → 跳转企业微信官方授权页 → 授权回调成功后进入“待验证”；
3. 管理员点“发送测试消息”，在企业微信中打开测试消息，按 F5 的同一绑定规则完成本人绑定后点“确认”，渠道变为“已启用”；
4. 已启用后，管理员可设置“可见范围提示”（告诉成员在企业微信哪里找到妙洽应用），可停用渠道。停用使该渠道的全部绑定失效、不再投递，已投递的消息不撤回。

### F5 成员绑定渠道账号

绑定只在渠道自己的内置浏览器中完成，同时需要“当前渠道身份”和“妙洽登录”两项证明，不能凭链接持有权完成：

1. 成员在企业微信中打开妙洽应用或给妙洽发消息 → 未绑定时只收到绑定引导卡片（不回答任何业务内容）。Web“个人设置 / 渠道”只给出这一入口的说明，不提供可被他人扫码的绑定二维码；
2. 点“绑定账号”打开一次性绑定链接（10 分钟有效），链接记录发起它的渠道账号；
3. 页面先通过渠道的网页授权取得**当前**渠道账号。它必须与链接记录的渠道账号一致，否则拒绝（链接被转发到另一人的企业微信时在这里失败）；在渠道内置浏览器以外打开时，只提示“请在企业微信中打开”；
4. 成员在同一内置浏览器中用妙洽账号密码登录（已登记 TOTP 的需验证）。绑定请求在首次登录时与本次 Web 会话固定：之后会话被替换或退出再登录为他人，确认均被拒绝；
5. 确认页展示“企业微信账号（显示名、所属企业）将绑定到 妙洽账号（姓名、租户）”，确认后链接作废，渠道内收到“绑定成功”；
6. 绑定规则：渠道账号所在企业必须是本租户已安装的那个企业应用；一个渠道账号只绑定一个成员，一个成员在同一渠道只绑定一个账号。

### F6 解绑与失效

- 成员可在“个人设置 / 渠道”解绑，管理员可强制解绑并记录原因；成员停用、退出租户或渠道停用时绑定自动失效；
- 绑定的权威在 channels：失效即时生效，此后渠道内的动作按钮、新的免登都被拒绝；
- 免登签发与绑定失效按下面的规则协调。目标是：一次失效被报告为“已完成”之后，该绑定不存在、也不会再出现可用的免登会话：
  1. **签发凭据有时限**：channels 核对绑定有效后，签发一张签发凭据（绑定标识、绑定版本、成员、到期时间为签发后 30 秒），随 `IssueChannelSession` 发给 identity。identity 只接受未过期的凭据（按 5 秒时钟偏差从严计算），因此任何延迟到凭据过期后才到达的签发请求都不会产生会话；channels 不在凭据有效期外重试签发；
  2. **水位核验与写入原子**：identity 为每个绑定保存一行撤销水位。签发在一个事务中锁定该行，核验凭据未过期且绑定版本高于水位，再写入会话；撤销在一个事务中锁定同一行，抬高水位并作废版本不高于水位的会话。两者在同一行上串行，不存在签发读到旧水位、撤销随后完成、签发最后写入的交错；
  3. **失效的两个阶段**：channels 提交失效后，绑定立即进入“失效中”，此后 channels 不再签发凭据，新的免登在 channels 处即被拒绝；随后 channels 同步调用 `RevokeChannelSessions(绑定标识, 新版本)`，失败时经 `channels.binding.changed.v1` 事件重试；
  4. **何时算完成**：只有同时满足两条，channels 才把失效标为“已完成”：identity 已确认撤销（水位已抬高、已有会话已作废）；该绑定最后一张签发凭据已过期加时钟偏差。此前成员与管理员看到的状态是“解绑处理中”；
  5. 重新绑定产生新的绑定标识，旧绑定的迟到签发与重试一律低于旧标识的水位或凭据已过期而被拒绝；identity 还定时与 channels 的有效绑定对账，撤销不在其中的免登会话；
- 撤销送达前，已有的免登会话仍可能被使用：网关每次请求都要经 identity 核验会话与水位，identity 不可用时请求一律失败关闭，可用时撤销重试会在下一个重试周期送达。成员退出仍按“下一次请求即拒绝”的既有边界；成员重新加入后需重新绑定。

### F7 从渠道卡片进入 Web

1. 卡片上的详情链接是短时授权链接，只指向对象，不携带登录身份（[channels 4.1](../../03-architecture/subsystems/channels.md#41-渠道无关的消息表示)）；
2. 在已绑定渠道的内置浏览器中打开：channels 用渠道网页授权取得当前渠道账号，在自己的绑定表中确认绑定有效，再请 identity 为对应成员签发免登会话（`IssueChannelSession`）。IdP 中不保存长期的渠道身份关联，因此不存在“解绑后残留关联仍可免登”的情况；绑定无效、渠道网页授权不可用或 identity 不可用时，转到登录页并说明原因；
3. 在普通浏览器中打开：已有会话直接进入；无会话先登录，登录后回到原页面；
4. 已登录的是另一个成员时，不自动切换账号，提示“链接是发给 A 的，当前登录的是 B”，提供“退出并以 A 登录”；
5. 进入后按当前成员的权限读取对象。无权限或对象不存在时显示同一个通用页“无法打开此内容：内容不存在，或你没有查看权限”，不返回对象标题、目标归属、组织单元或负责人；
6. 免登会话不带强认证，执行强认证动作时仍按 F3 验证 TOTP。

### F8 唯一管理员账号恢复

租户只有一位管理员且其无法完成 TOTP 或登录时，不能走内部支持访问（它需要租户管理员批准）。恢复走独立流程：

1. 客户通过签约或开通时登记的联系渠道提出恢复申请，平台运营核验申请人有权代表该租户。核验方式不固定，任何能可靠证明身份的方式均可（签约联系人回呼、营业执照或授权书、开通时登记的联系方式等）；个人客户以本人身份核验为准。所用方式与核验记录写入审计；
2. 由一名平台运营发起、另一名批准（双人控制），两人都须 MFA；发起后 24 小时内未批准自动关闭；
3. 恢复只做三件事：清除该管理员的 TOTP 登记、要求重设密码、撤销该账号全部会话；不授予平台人员任何租户数据访问，也不改变角色；
4. 管理员按激活流程重设密码并重新登记 TOTP；
5. 申请、批准、执行全程审计，并通知该管理员邮箱与签约（或开通时登记的）联系人。

## 5. 业务与权限规则

| 规则 | 说明 |
|---|---|
| 租户只来自认证身份 | 绑定、免登、卡片动作的租户都从已验证身份派生，链接、请求参数中的租户一律不信任 |
| 管理动作 | 邀请、撤回、角色变更、渠道安装与停用、强制解绑只由租户管理员执行（`can_manage_members`），并要求 15 分钟内的强认证 |
| 邀请不授予权限 | 接受前不能访问租户任何内容；接受只能写入邀请限定的角色和组织单元 |
| 绑定需要双重证明 | 当前渠道身份与妙洽登录在同一内置浏览器会话内完成，绑定链接一次性、与会话固定 |
| 渠道内只有绑定的成员 | 未绑定账号只收到绑定引导，任何查询与动作都不执行 |
| 渠道动作再次授权 | 卡片按钮执行时以绑定成员的当前权限再次 `Check`，令牌一次性（[channels 第10节](../../03-architecture/subsystems/channels.md#10-安全要点)） |
| 无权限不泄露关联 | 无权限与不存在使用同一提示，不显示标题、归属或负责人 |
| 末位管理员 | 不能撤销最后一位管理员的角色或使其退出（沿用 M0） |
| 审计 | 激活、邀请、接受、撤回、登录失败、TOTP 登记与重置、渠道安装停用、绑定解绑、强制解绑、免登会话签发与撤销、管理员账号恢复均写审计 |

## 6. 状态

```text
邀请：  待接受 ──接受──► 已接受
          ├──撤回──► 已撤回
          ├──重发──► 待接受（新链接，旧链接失效）
          └──过期──► 已过期 ──重发──► 待接受

渠道安装：未安装 ──授权──► 待验证 ──测试消息确认──► 已启用 ⇄ 异常（凭证失效、回调失败，系统检测）
                                                    └──停用──► 已停用 ──重新授权──► 待验证

绑定请求：已发起 ──渠道身份一致 + 登录──► 已固定会话 ──确认──► 已完成
            └──过期 / 渠道身份不一致 / 会话替换──► 已作废

渠道绑定：未绑定 ──确认──► 已绑定 ──解绑 / 强制解绑 / 成员停用 / 渠道停用──► 失效中 ──撤销已确认且签发凭据已过期──► 已失效
```

“异常”由渠道健康检测置位，恢复后自动回到“已启用”；异常期间消息改投站内，并在管理员的渠道页显示原因与最近一次失败时间。

## 7. 界面与原型

原型：[prototypes/01-login-and-channel-binding.html](prototypes/01-login-and-channel-binding.html)。原型只演示各页面的状态与文案，完整任务流程的验证以第 12 节的走查为准。页面与必须展示的状态：

| 页面 | 正常 | 空态 | 加载 | 无权限 | 过期 | 失败 | 部分成功 | 来源中断 | 数据未知 |
|---|---|---|---|---|---|---|---|---|---|
| 登录 / 强认证 / TOTP 登记 | ✓ | — | ✓ | 账号已停用 | 会话或强认证过期 | 密码或 TOTP 错误、锁定 | — | IdP 不可用 | — |

实体与接口的语义以子系统规格为准，本段新增项已同步写入 [identity](../../03-architecture/subsystems/identity.md) 与 [channels](../../03-architecture/subsystems/channels.md)。

| identity | `CreateInvitation` / `ResendInvitation` / `RevokeInvitation` / `ListInvitations`（管理员，强认证） | F2；批量邀请逐行调用，每行带 `Idempotency-Key` |

- channels 消费 `identity.member.changed.v1`（已实现），使停用或退出成员的绑定失效；
- 新增 `identity.invitation.changed.v1`（创建、接受、撤回、过期）与 `channels.binding.changed.v1`（绑定、解绑、失效，带绑定版本）；identity 消费后者撤销对应的免登会话，按版本忽略迟到的旧事件。契约随实现写入 `contracts/events/`。

## 9. 异常、重试与撤销

| 情况 | 处理 |
|---|---|
| 邀请邮件发送失败 | 邀请仍创建，状态旁显示“发送失败”，可重发或复制邀请链接自行发送 |
| 批量邀请部分失败 | 逐行返回结果；失败行保留在输入框，可只重试失败行；同一 `Idempotency-Key` 重试不重复创建 |
| 重复点击接受邀请 | 同一账号重复接受同一邀请，返回原结果，不重复写入或通知 |
| 重试确认绑定与重放绑定链接 | 区分两种情况：同一绑定请求、同一固定会话、同一渠道身份、内容未变的重试（例如首次确认成功但响应丢失），只读取并返回原结果“已绑定”，不新建绑定、不再通知；其他会话、其他渠道身份或改变了内容的请求，以及链接作废后在新会话中的再次使用，都按重放拒绝，不产生绑定或通知 |
| 接受后写入 IdP 租户归属失败 | 成员资格已写入，账号暂时无法访问；identity 重试直至成功并告警，页面提示“正在开通访问，请稍后重新登录” |
| 绑定确认时渠道账号已被他人绑定 | 拒绝，提示联系管理员；管理员可在已绑定成员列表中查看并强制解绑 |
| 解绑后同步撤销失败 | 绑定停在“解绑处理中”，新的免登已被 channels 拒绝；撤销经 `channels.binding.changed.v1` 重试直至送达，送达且最后一张签发凭据过期后才显示“已解绑”；identity 还定时对账，撤销不在有效绑定中的免登会话 |
| 渠道回调重放或验签失败 | 丢弃并计入渠道健康，不改变任何状态 |
| IdP 不可用 | 登录与免登不可用并说明原因；已有会话的只读页面继续可用，写操作返回可重试错误 |
| 成员丢失 TOTP 设备 | 由管理员重置（强认证动作）；重置后该成员下次强认证前重新登记 |
| 唯一管理员丢失 TOTP 或无法登录 | 走 F8 管理员账号恢复；“开始设置”提示至少设两位管理员以避免依赖该流程 |
| 渠道异常期间 | 消息改投站内；恢复后不补发已过期的提醒，简报按第5段规则处理 |

## 10. 非功能要求

- 登录、绑定确认、免登建立会话 p95 ≤ 2 秒（不含渠道平台与 IdP 自身耗时）；渠道回调 1 秒内确认、异步处理；
- 会话空闲 12 小时、绝对 7 天失效；强认证 15 分钟有效且不随刷新延长；免登会话绝对时长不超过 12 小时（见第13节第3项）；
- 登录与 TOTP 连续失败 5 次锁定 15 分钟；绑定链接、激活与邀请链接一次性使用；
- H5 在主流手机浏览器中可完成 F2 接受邀请与 F7；F5 绑定只在企业微信、飞书、钉钉内置浏览器中完成，在其中验证 F5 与 F7 免登；
- 跨租户负向用例覆盖邀请接受、绑定、免登和卡片链接（[安全与租户第9节](../../03-architecture/06-security-and-tenancy.md#9-安全测试要求)）。

## 13. 已确认事项

以下事项由项目负责人 Sean 于 2026-10-15 确认。

| # | 事项 | 结论 |
|---|---|---|
| 1 | 渠道内置浏览器免登是否进 M2 | 进 M2。channels 每次核对权威绑定后，请 identity 签发不带强认证的免登会话，IdP 不保存长期渠道关联 |
