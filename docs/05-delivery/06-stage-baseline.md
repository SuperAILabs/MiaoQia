# 范围与阶段交接基线

> 状态：已批准 · 负责人：项目负责人、首席架构师

本文是 E5 范围与阶段基线、E6 阶段依赖交接与当前主线的唯一定义；A02 各能力缺口的状态以 [A02 真实贯通验收线第4节](09-a02-end-to-end-acceptance.md#4-缺口清单) 为唯一定义。批准依据为项目负责人已确认的首发范围与主线决议。批准的是范围、顺序、证据要求与变更权限，不是对未交付能力的验收。当前结论：**基线已收口，M0 尚未整体退出，M1 允许按能力切片做设计和离线开发，真实来源及供应商接入须先关闭相应前置项；当前主线是真实数据链路与最薄研究切片（第1.1节）。**

### 1.1 当前主线

数据平面是研究与决策的地基：没有真实、已关联的事实，研究报告没有可引用的证据，判断也没有输入。A02 服务端切片与回放贯通已建立上层闭环，当前工程重心转向以下两条主线，按优先级排列：

| 主线 | 交付与验收 | 前置与阻断 |
|---|---|---|
| 1. 真实数据链路 | 在试点区域安徽选少量 P0 来源（[D1b 试点来源启用验收](11-d1b-anhui-pilot-sources.md)），打通采集 → 证据 → 领域事实 → 实体解析（中标方、总包到企业主体）→ 检索与 data-api 读取，替代 A02 的回放语料与企业夹具；用真实数据验证契约与解析器，关闭 M1-P1、M1-P2、M1-P6、M1-P7，并按 M1-P4 度量 | D1b 来源启用与来源跟踪；企业主体先用公开信息并标明覆盖范围（M1-P3） |
| 2. 最薄研究切片 | A02“研究这个中标总包”：一个研究模板、只读研究工具（事实、实体、检索）、带引用校验的报告，区分事实、推断、未知项与建议（[ADR-0010](../04-decisions/0010-governed-agent-runtime.md)）；先在已验收语料上离线跑通，再接主线1的真实数据；research 与 assessment 子系统的首个实现 | C3 模型主备选型是本主线的阻断项（M1-P5，供应商已定，按评测选主备）；评测按[模型供应商评测方案](08-model-vendor-evaluation.md) |

不占主线的工作：A02 L2 Web 只完成已开工的页面与已登记的 W 缺口，不扩展新页面；L3 真实渠道按原前置条件推进；其他上层功能的扩展等主线1提供真实数据后再排期。主线调整不放宽任何首次使用门禁。

### 2.1 M0 关闭规则

M0 是一次性工程基线，不是持续运行的总门禁。M0-01、M0-07、M0-08 必须针对同一个候选版本快照各关闭一次：

- M0-01 只证明开发 VPS 的非敏感配置、组件版本、连接边界和重建步骤可复现；生产高可用、备份恢复、值班和远程公共服务持续健康属于 C11 与上线门禁。
- M0-07 只证明模型网关骨架、预算/输出校验、错误语义和本地绑定；供应商适配、OCR、持久化计量和远程绑定属于 M1 首次调用前门禁。
- M0-08 只保留候选版本标识、对应 CI 制品、M0 E2E 日志和追踪/审计证据；A02、M1 或 Web 的后续改动不重新打开已关闭的 M0 门，除非改动触及 M0 组件或出现 M0 回归。

客户任务观察和可用性记录由 M2-P9/L5 验收；远程 OpenFGA、生产渠道和外部供应商健康不作为 M0 的隐含重试条件。开发验收可按运行时验收文档使用本地 OpenFGA 替代网络长尾。

## 4. M2 前置条件与能力交接

M2 的验收单位是**首条客户旅程逐环节可运行、可解释、可验证**，不是文档补齐。首条旅程为建材供应商 A02：目标配置 → 信号 → 证据 → 判断／必要审批 → 指派跟进 → 提醒 → 结果反馈。A01、B03 按同一结构逐段交接。下表各项按首次使用节点触发，与第3节同样不构成统一阻断。

设计与实现并行（项目负责人 2026-10-17 确认，[PR #17 决策记录](https://github.com/SuperAILabs/MiaoQia/pull/17#issuecomment-6232158680)）：每段的第一份实现 PR 同时提交该段的 OpenAPI 与事件契约；开工前核查相关工作区、合并与依赖状态，避免重复实现或覆盖。第1–7段的贯通级别与界面缺口以 [A02 真实贯通验收线](09-a02-end-to-end-acceptance.md) 为准。并行安排不放宽任何首次使用门禁：真实供应商接入、客户试用与上线仍按本节与第3节逐项验收。“设计交接通过”只表示允许实现，不代表功能验收或真实接入已通过。
