# 范围与阶段交接基线

> 状态：已批准 · 版本：1.1 · 更新：2026-10-15 · 负责人：项目负责人、首席架构师

本文是 E5 范围与阶段基线、E6 阶段依赖交接的唯一定义。批准依据为项目负责人已确认的首发范围及阶段基线收口的执行指示。批准的是范围、顺序、证据要求与变更权限，不是对未交付能力的验收。当前结论：**基线已收口，M0 尚未整体退出，M1 允许按能力切片做设计和离线开发，真实来源及供应商接入须先关闭相应前置项。**

## 1. 范围、顺序与变更权限

| 项目 | 当前基线 |
|---|---|
| 对外范围 | 全国、四个首发信息领域、商业目标分批及行业包以[首发范围](../02-business/application-domains/tendering/05-release-plan.md)为准；全国是发布范围，不是当前覆盖事实 |
| 近期产品切片 | 建材供应商 A02“中标结果→总包→供货窗口”为首条旅程方向；功能PRD、原型及客户任务验证待独立设计工作交付，本基线不定义具体交互方案。投资客户与其他R1目标保留 |
| M0 | 完成工程基座、最小身份生命周期与路由、可复现开发环境、产品概念及设计规范；完整探针只是其中一项 |
| M1 | 采购与企业数据供应；来源、授权交付、质量和模型能力按首次使用节点交接。允许已就绪来源先行，不把单来源通过写成整个 M1 完成 |
| M2 / M3 / M4 | 阶段范围按[路线图](01-roadmap.md)交接；功能需求、交互和验收用例由对应产品设计交付 |
| 部署与资源 | 开发使用不限厂商的 VPS；生产云、迁移与高可用按正式运行节点验收。人员编制与项目预算不作为门禁 |
| 契约 | C4a/C4b 首批冻结记录保留；当前集成安全配置为 3.0.0，identity接口为1.1.0。新增业务接口/事件按兼容规则交付，不预先冻结未实现能力 |
| 变更权限 | 项目负责人决定范围、阶段目标及风险接受；产品负责人决定功能规则与设计；首席架构师决定 ADR/契约；质量负责人提交证据，项目负责人决定阶段退出。来源启用由数据负责人决定并由法务确认权利 |

周数是规划窗口；下一阶段的开始日期不构成前置能力验收。未交付、未核验与验收失败分别登记，不通过修改指标或扩大已通过测试的含义放行。

## 2. M0 逐项核对

“已有证据”引用已接受的验收或当前源码；本次基线核对不重新签发运行时测试结论。CI 文件存在不等于某次流水线已通过，工作站验证不等于 VPS 已部署。

| ID / 路线图交付 | 当前状态与证据 | 剩余关闭条件 / 责任 |
|---|---|---|
| M0-01 开发基础设施 | 本地组件配置、数据库/主题生成和角色清单已存在：[Compose](../../deploy/local/compose.yaml)、[启动入口](../../deploy/local/up.sh)、[清单校验](../../tools/dev/gen_local.py)。未提供共享 VPS 部署与重建验收记录 | 平台：完成开发 VPS/网络/凭证隔离、基础配置版本化、导出及重建验证；交付地址、配置版本和操作记录。持续运行前另关 C11 |
| M0-02 代码与进程骨架 | Go/Python/TypeScript 工作区、18 子系统骨架、三个部署单元及进程角色已有：[结构](../03-architecture/09-codebase-structure.md)、[部署清单](../../deploy/subsystems.yaml)、[Go入口](../../services/cmd/platform/main.go)。多数业务子系统仍是骨架 | 架构/平台：保持生成、依赖边界、迁移分发和各角色启动检查通过；不得把骨架登记当业务接口交付 |
| M0-03 契约工具链 | C4a/C4b 已冻结，三语言生成、兼容与往返有[明确证据](../03-architecture/13-contract-readiness.md) | 首席架构师：后续变更执行现有检查。此项不要求反复补样本重新冻结 |
| M0-04 平台横切与完整探针 | 上下文、绑定、发件箱/中继、消费框架、审计/授权 SDK、HTTP 认证和完整探针已通过[运行时验收](05-m0-runtime-acceptance.md)；四个现有消费者通过 | 平台/数据：保持既有门禁；新增处理函数补载荷、业务语义与真实组件证据。此项已完成的验收不重开 |

| M0-06 最小身份生命周期与 cell 路由 | 实现及真实组件验收通过：[身份验收](07-m0-identity-acceptance.md)及[记录](../../contracts/reviews/m0-identity-acceptance.yaml)。租户创建/停用/恢复、成员加入/退出/角色、末位管理员、权威cell-01核验及旧/新令牌撤权；真实PG/FGA/HTTPS Keycloak/mTLS/Kafka验证 | identity/安全：维持回归门禁；审批、服务账号/协作者、组织层级及多cell迁移分阶段验收。实际生产IdP/MFA流程、客户端和部署不由测试签发方或本地realm代证 |
| M0-07 最小模型网关骨架 | [ai-platform模块](../../services/subsystems/aiplatform/aiplatform.go)仅注册名称与数据库，尚无供应商适配/调用控制实现 | AI/平台：M0 交付可测试的网关边界、配置、输出校验/计量接口与故障桩；实际模型、OCR/嵌入及限额控制在 M1 首次调用前按 C3/C7a 验收，骨架不代证供应商可用 |
| M0-08 CI与一键环境 | [services](../../.github/workflows/services.yml)、[data](../../.github/workflows/data.yml)、[contracts](../../.github/workflows/contracts.yml)、[开发E2E](../../.github/workflows/e2e.yml)已有。开发E2E显式明文策略，HTTPS/mTLS由运行时真实组件测试覆盖 | 平台：提交候选版本的实际CI结果；从干净环境启动组件、迁移、启动全部需要的角色、执行开发E2E并保留日志。无组件的skip不能关闭相应门禁 |
| M0-09 产品概念与设计规范 | 两类客户已确认；总体体验和落地规则已有；功能PRD、原型和客户任务观察待交付 | 产品/设计：两类客户故事板与概念测试、统一列表/证据/渠道卡片规范及对应可用性记录。客户已确认不等于完成任务观察 |

**M0 当前剩余重点**：M0-01、M0-07、M0-08 的实际环境/流水线交接、M0-09。M0-02/03/04/05/06 已有成果按变更持续验证，不扩张为未来所有能力均通过。关闭上述剩余项后，由质量负责人汇总与项目负责人决定整体退出；本次不宣布 M0 退出。

## 3. M1 前置条件与能力交接

| ID / 首次使用节点 | 对应清单 / 当前状态 | 必备交付与验收 / 责任 |
|---|---|---|
| M1-P1 首次启用具体来源 | D1b、B1；候选盘点已完成，逐来源启用执行中 | 数据/法务：确定P0、地区/体系/类型、共同平台标识、权利登记、频率与历史窗口；验证列表/分页/正文/更正/附件/健康。保存失败与不可得范围；40入口不等于全国覆盖 |
| M1-P2 首次真实数据处理 | B6/B9；处理规则已批准，执行登记待验收 | 安全/数据：个人信息和处理活动目录、用途/访问/保留映射、来源撤回与删除更正的受控操作流程和验证记录。公开业务联系人/法定代表人可明文检索及进入模型的规则继续有效 |
| M1-P3 企业供应商接入 | B2b；法律授权已通过，交付仍执行中 | 采购/数据：实际供应商接口、字段/更新/历史/用途覆盖、限额、原始测试响应与字段证据验收。网页人工样本不能替代接口交付；未关此项不宣称INF-ORG就绪 |
| M1-P4 首批测量与标注 | D1c/D2/D4；方案批准、实物待验收 | 质量/领域：首批独立来源参照集、标注手册与工具试用、双标裁决、按项目/转载分组的开发/验证/盲测版本。规模与方法引用[数据质量计划](04-data-quality-organization.md)，契约发现集不能充当独立盲测 |
| M1-P5 首次模型调用/扫描件处理 | C3/C7a；待决策 | AI/数据：主备API真实评测、数据用途与处理地域、输出格式/证据坐标、每任务限额/并发/超时/计量/故障降级；扫描件达到OCR评估要求后启用。纯HTML离线设计可先行，不代证OCR |
| M1-P6 每个持久化/事件切片实现前 | C4b及语义门禁；首批Schema已冻结，实现待验收 | evidence/领域/实体：先确认接口/事件及存储版本；实现原文快照→规范化→事实→引用完整性；更正原子应用、并发幂等、跨源冲突、恢复重放补真实链路证据 |
| M1-P7 持续采集和开发运行前 | C11及M0相关环境项；方案批准 | 平台/数据：来源中断告警、队列/错误/死信监控、运行责任、备份导出/恢复及失败重放。生产RPO/RTO和正式迁移另按上线条件复验 |
| M1-P8 数据/检索阶段退出 | D3及M1路线图；阈值待校准 | 质量：以独立分层样本冻结适用字段/分母/版本，报告覆盖、时效、字段、实体/项目聚合与检索；缺层明确未验证，未达标层不能由整体均值抵消 |

P1/P2 是来源真实启用前置，P3 是企业接入前置，P4 是可信测量前置，P5 按实际能力使用触发，P6 按开发切片触发，P7 在持续运行前关闭，P8 是阶段退出条件。不能把全部项误当作开始编写 M1 代码的统一阻断，也不能因已开始开发省略任何首次使用门禁。

## 4. 阶段依赖交接

产品设计、数据供应与工程实现按各自交付证据交接。功能PRD与原型待交付，不以本次阶段基线收口替代产品设计或客户验证。M1具体能力按第3节的首次使用条件验收，M2及后续阶段按路线图依赖已验收的能力切片。

## 5. 更新与验收约束

本文只维护当前有效状态；实现完成后在原行更新证据与关闭结论，不追加历史纪要。验收记录继续存放于对应审计材料。范围、规则、阶段或阈值变更须同时检查立项清单、路线图、PRD、架构、契约、配置、测试与示例的受影响引用。来源能力和客户验证由各自证据关闭，不能以文档完成替代。
