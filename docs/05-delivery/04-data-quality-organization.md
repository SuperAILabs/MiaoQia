# 数据、质量与组织

> 状态：已批准 · 版本：2.0 · 更新：2026-10-14 · 负责人：项目负责人

本文定义数据基线、评估、责任与评审机制。人员编制、招募和项目预算灵活安排，不作为立项准入条件；能力验收和运行控制按阶段落实。

## 1. 数据基线

### 1.1 来源治理

- 候选来源唯一定义在 [source-inventory.yaml](../../packs/information_domains/procurement/source-inventory.yaml)：本地 Tender Intel 的40个入口（37个原型启用、3个未启用）已盘点；这些状态仅供参考，不代表妙洽已启用或获得商业使用权。
- 覆盖顺序：国家级政府采购/公共资源 → 省级 → 主要央企/国企 → 地市按交易量排序。40个入口不等于全国覆盖，政府采购、工程建设、国企自主采购分别验收。
- 同站多入口和镜像登记共同平台标识，来源覆盖不按入口数重复计数；每个来源确认 P0/P1/P2、地区、公告类型、可访问历史、频率、责任角色、权利与更新时间。
- 每个来源启用前验证列表、详情正文、分页、公告更正、附件下载与格式；仅首页窗口可见的入口不得承诺完整历史或全量覆盖。登录入口只有授权完成并通过接入验收后启用。
- 来源权利登记分别明确采集、保存、展示、再分发、模型处理与撤销后的下线责任。每日按省份/类型监控来源健康与采集量；中断时记录数据截至时间和覆盖缺口。

### 1.2 评估集

| 评估集 | 构建与初始规模 | 完成时点 / 责任 |
|---|---|---|

| 字段标注集 | 2000篇，含 HTML/PDF/扫描件、附件、未知/冲突、多标包与多项目 | M1 中期；领域专家、数据运营 |

| 检索相关性集 | 首批至少200个查询，每查询人工评审候选池；含标识检索、行业术语、时间/地域过滤与困难负例；随后补真实查询 | M1 检索验收前；检索负责人 |

这里的规模是交付计划，不是充分统计证明；验收报告还需列分层样本量与不确定性。50篇公告审查样本属于契约发现集，不当作独立黄金集或全国覆盖参照集。

### 1.3 标注与评估规则

- 内部领域专家制定手册与裁决，外包和大模型可预标注，但最终黄金标签由人工确认；标注人员与模型规模灵活配置。
- M1 前验收首版手册与工具：字段定义、适用公告类型、单位/时区、未知、不适用、否定、原文冲突、未选模板、附件缺失和证据定位规则。
- 双人独立标注抽检，目标一致率≥90%，争议由领域专家裁决；报告抽检比例与一致率计算方法。
- 数据按来源、项目链和重复正文分组后拆分开发/验证/盲测，禁止同公告转载或更正泄漏到不同集合；记录版本、许可与修改依据。
- 预标注模型不能独自裁决自己的评估集。标注工具需支持原文定位、复核、导出版本与访问控制；工具选择和试用在 M1 前完成。

### 1.4 指标冻结

数据与检索定义/初始阈值 M1 中冻结；监测 M2 内测前冻结；研究 M3 前冻结。校准只基于独立样本和明确证据，由产品与质量负责人批准，不得在失败后改口径使其通过。定义见 [质量与验收](02-quality-and-acceptance.md)。

## 2. 质量管理

专业评估由能力所有者执行并决定版本门禁，learning 提供授权样本与编排；质量负责人独立复核报告和验收证据；每周复盘数据、检索、监测、研究及可靠性指标。P0：错租户、错误高影响动作、关键字段系统性错误；P1：覆盖缺口、关键来源中断；P2：一般数据质量；P3：体验问题。阶段退出和正式发布分别评审，受影响分层失败不能由整体均值抵消。

## 3. 责任与资源安排

每个子系统有唯一的设计/契约/质量责任角色；人员可兼任或调整，具体人选不作为立项准入项。责任变化应同步评审联系人和运行交接。项目按能力就绪安排迭代，不以固定团队人数推算工期；[路线图](01-roadmap.md)的周数是规划窗口，在每次阶段交接按实际交付重估。

## 4. 决策与评审

| 机制 | 频率 | 决定 / 证据 |
|---|---|---|
| 项目指导会 | 每月及重大范围变更 | 项目负责人决定范围、阶段与重大风险处置 |
| 架构评审 | 每周或契约变更时 | 首席架构师决定ADR/契约，征询受影响子系统及安全负责人 |
| 产品评审 | 每两周 | 产品负责人决定需求与设计，征询设计、领域专家及客户反馈 |
| 阶段与发布门禁 | 每个交接/发布节点 | 质量负责人提供报告，项目负责人决定；失败项记录修复或明确限制 |
| 来源启用 | 每个来源 | 数据负责人决定，法务确认权利，保留能力/健康验收 |

基线包含范围、版本、依赖、门槛、责任和批准记录；预算与人员另行灵活安排。范围或阈值变化更新唯一定义并扫描全文引用，不保留相互冲突的旧说明。

## 5. 技术成本控制

从 M1 首次模型与采集任务起记录调用方、来源/任务、模型/增强器版本、令牌/页数、延迟及费用；M2 起增加租户归属。每类任务在配置中给出单任务上限、并发、超时与回填限速，未配置限额的批量任务不得运行；超限先停止或部分交付，经授权才能继续。计量由最小模型网关和任务执行器完成，M5 的 commerce 消费既有记录形成账单，不是早期成本控制的前提。项目财务预算不在本文件规定固定额度或批准门槛。
