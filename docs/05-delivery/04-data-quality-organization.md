# 数据、质量与组织

> 状态：已批准 · 版本：1.0 · 更新：2026-10-13 · 负责人：项目负责人

本文定义数据基线、质量管理、组织、决策机制与成本护栏（立项准入清单 D 类与 E 类）。

## 1. 数据基线

### 1.1 来源治理

| 事项 | 规则 |
|---|---|
| 初始清单 | 以 Tender Intel 已整理的信源清单作为 P0 初始清单（仅参考清单），由数据负责人评审 |
| 全国覆盖顺序 | ① 国家级政府采购与公共资源交易平台 → ② 31 个省级公共资源交易平台与省级政府采购网站 → ③ 主要央企与省属国企采购平台 → ④ 地市级平台（按交易量排序） |
| 来源分级 | P0：贡献主要交易量或独有信息；P1：补充覆盖；P2：长尾。分级决定采集频率与监控等级 |
| 来源登记 | 每个来源登记访问方式、更新频率、权利、负责人后才能启用 |
| 覆盖监控 | 每日按省份、公告类型统计采集量，与历史同期比对，异常告警 |

### 1.2 评估集

| 评估集 | 构建方法 | 初始规模 | 完成时点 |
|---|---|---|---|
| 来源参照集 | 按省份 × 公告类型 × 采购类别分层抽样官方公告；每月更新 | 每月约 3,000 条（约每省 100 条） | M1 开始前首批 |
| 字段标注集 | 覆盖各公告类型、格式（HTML/PDF/扫描件）与难例 | 2,000 篇 | M1 中期 |
| 分类与标签标注集 | 品类多标签与业务标签 | 5,000 篇 | M1 末 |
| 实体与聚合标注集 | 合并与归并的正例、负例、难例 | 3,000 对 | M1 末 |
| 目标相关性标注集 | 每个 R1 目标 × 每个首发行业包 | 每组 500 条 | M2 中期 |
| 研究黄金集 | 每个研究模板的问题、标准答案、应为未知的问题 | 每模板 50 题 | M3 开始前 |

### 1.3 标注组织

采用内部核心组 + 外包 + 大模型预标注的混合方式：

- 内部核心标注组 3–4 人（含招投标领域专家），负责标注手册、难例裁决、抽检；
- 外包团队按批次承担大规模标注；
- 大模型预标注 + 人工确认，降低成本；
- 质量控制：双人标注一致性抽检（目标一致率 ≥ 90%），不一致由核心组裁决；
- 标注工具在技术选型专题中确定。

### 1.4 指标口径

在 M1 中期冻结 [质量与验收](02-quality-and-acceptance.md) 中全部指标的定义、样本、计算方法和负责人；之后的修改需经质量评审。

## 2. 质量管理

| 机制 | 做法 |
|---|---|
| 质量负责人 | 专职，独立于各开发团队，向项目负责人汇报 |
| 质量看板 | 数据、增强与检索、监测、研究、可靠性各层指标的持续看板（随 M1 建设） |
| 质量例会 | 每周一次，复盘指标变化与缺陷 |
| 缺陷分级 | P0：错租户、错误高影响动作、关键字段系统性错误；P1：覆盖缺口、关键来源中断；P2：一般数据质量；P3：体验问题 |
| 门禁评审 | 里程碑与发布门禁由质量负责人出具评估报告，评审会决定 |

## 3. 组织方案

### 3.1 规模

峰值约 42 人，每个团队能独立负责其子系统；[路线图](01-roadmap.md) 按此规模估算。更大规模在架构与契约成熟前收益有限，更小规模会使路线图延长约 30–50%。

### 3.2 团队配置（峰值）

| 团队 | 人数 | 构成 |
|---|---|---|
| 架构与项目管理 | 2 | 首席架构师、项目经理 |
| 产品 | 3 | 产品负责人、产品经理 2 |
| 设计 | 2 | 交互与视觉设计 |
| 平台工程 | 5 | `kernel`、`sdk`、基础设施、`identity`、`commerce`、`governance` |
| 数据供应 | 6 | `acquisition`、`evidence`、`domain-intelligence`、信息领域包（含来源工程师） |
| 实体与检索 | 4 | `entity-graph`、`search` |
| 客户智能 | 5 | `customer-context`、`detection`、`assessment`、`pursuit`、`learning` |
| AI 与研究 | 5 | `ai-platform`、`research`、增强器、研究模板与评估 |
| 前端与渠道 | 4 | Web 应用、BFF、`channels`（企业微信、飞书、钉钉、邮件适配器） |
| 领域与运营 | 3 | 招投标领域专家、数据运营（含核心标注组） |
| 质量 | 2 | 质量负责人、测试与评估工程师 |
| 安全 | 1 | 安全负责人（等保与安全测试） |
| **合计** | **约 42** | 外包标注不计入 |

### 3.3 M0 启动时的最小团队（约 15 人）

首席架构师、项目经理、产品负责人、产品经理 1、设计 2、平台工程 4、数据供应 2（含数据负责人）、AI 负责人、招投标领域专家、质量负责人、安全负责人。

其余岗位按里程碑逐步到位：M1 前补齐数据供应与实体检索；M2 前补齐客户智能与前端；M3 前补齐 AI 与研究。

### 3.4 子系统负责人

每个子系统指定唯一负责人（对设计、代码、契约与质量负责），由所属团队负责人提名、首席架构师确认，在 M0 第 2 周前公布。

## 4. 决策与评审机制

| 机制 | 频率 | 成员 | 职责 |
|---|---|---|---|
| 项目指导会 | 每月 | 项目负责人、首席架构师、产品负责人、质量负责人 | 范围、预算、里程碑、重大风险 |
| 架构评审会 | 每周 | 首席架构师（主持）、各团队负责人、安全负责人 | ADR 批准、契约变更、跨子系统设计 |
| 产品评审会 | 每两周 | 产品负责人（主持）、设计、领域专家、相关团队 | 需求、设计与范围变更 |
| 里程碑门禁评审 | 每个里程碑 | 项目指导会成员 + 质量负责人 | 依据退出标准与质量报告决定是否通过 |

决策权限（RACI 简化）：

| 决策 | 决定者 | 需征询 |
|---|---|---|
| 范围与里程碑 | 项目负责人 | 产品、架构 |
| ADR 与契约 | 首席架构师（架构评审会） | 受影响团队、安全 |
| 产品需求与设计 | 产品负责人 | 设计、领域专家 |
| 发布 | 项目负责人 | 质量负责人报告 |
| 数据来源启用 | 数据负责人 | 法务（来源权利） |

研发节奏：两周一个迭代；里程碑末进行门禁评审。

## 5. 预算结构与成本护栏

### 5.1 预算分项

| 分项 | 内容 |
|---|---|
| 人员 | 团队编制 |
| 基础设施 | IaaS 资源（计算、云盘、对象存储、带宽），其上自建数据库、检索、消息 |
| 模型 | 模型 API 调用（生成、嵌入、重排、OCR） |
| 数据 | 授权数据采购 |
| 外包 | 标注、设计（概念阶段）、等保测评 |
| 其他 | 工具与软件许可、安全服务 |

### 5.2 成本护栏

- 每个分项设月度预算；达到 80% 预警、100% 需项目负责人审批后才能继续；
- 模型与基础设施成本按子系统、按租户、按增强器与研究模板可见（由 `commerce` 与 `ai-platform` 计量）；
- 历史数据批量增强与大规模回填作为“批量作业”，单次超过设定成本须先审批；
- 每月在项目指导会上复盘成本与单位经济指标。
