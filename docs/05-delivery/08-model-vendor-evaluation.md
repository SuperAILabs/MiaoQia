# 模型供应商评测方案（C3 / C7a）

> 状态：评审中 · 版本：1.1 · 更新：2026-10-17 · 负责人：AI 负责人、数据负责人、质量负责人

本文定义选定模型供应商主选与备选的评测方法，对应立项清单 [C3 模型供应商与最小网关](00-initiation-readiness.md) 与 C7a OCR 与版面。依据是 [ADR-0015](../04-decisions/0015-model-inference-via-api.md)（前期只接境内已备案供应商的 API）和 [ai-platform 第9节](../03-architecture/subsystems/ai-platform.md#9-首次使用门禁)。本方案只确定怎么评；真实调用与采购须先确认候选供应商与数据使用条件（[PR #17 决策记录](https://github.com/SuperAILabs/MiaoQia/pull/17#issuecomment-6232158680) D6），不由本文启动。

## 1. 评测对象

| 能力 | 平台中的用途 | 首次使用 |
|---|---|---|
| 结构化生成 | 公告字段抽取与增强（文档分类、品类分类、业务标签），输出受 Schema 约束 | M1 增强管线 |
| 嵌入 | 分块向量，嵌入模型与版本记入索引版本 | M1 检索 |
| 重排 | 检索候选重排 | M1 检索 |
| OCR 与版面 | 扫描件与图片型 PDF：文字、表格、证据坐标 | M1 首次扫描件处理 |
| 决策：分类与评分 | 固定标签分类与量表评分：公告类型、品类初筛、消息意图与处理路由，以及相关度等量表评分（[ai-platform 第11节](../03-architecture/subsystems/ai-platform.md#11-决策能力类-jev-决策模型)） | 各任务启用自动判断前 |

决策能力的候选包括专用决策模型（类 Jev，Jev 只是参考例子，不预设选定）与通用 LLM 端点：两类都按同一任务契约（候选标签及定义或量表、类型化结果、未知与拒答）接入网关并用同一样本评测，按任务比较，不按榜单或类别预设优劣。每项能力各选一个主选与至少一个备选；备选在主选不可用时由网关同级切换，不降级到不合规模型（[ai-platform 第7节](../03-architecture/subsystems/ai-platform.md#7-路由规则示例)）。同一家供应商可以同时是多项能力的候选。

## 2. 准入条件

以下是硬门槛，不打分。准入按“端点 × 能力”判定并登记结果：共用门槛对每个候选端点都适用；能力专属门槛只核验申请该能力的端点。任一适用门槛不满足的，该端点不进入这项能力的评测；只申请嵌入或分类的端点不因不具备 OCR 坐标被淘汰。按能力拆分不放松共用门槛，ADR-0015、数据地域与禁止训练的约束对每项能力一样适用。

| 条件 | 适用能力 | 核验方式 |
|---|---|---|
| 境内处理，处理地域可在合同中写明 | 全部 | 合同条款与接口文档；地域登记进模型目录（[部署拓扑第11节](../03-architecture/07-deployment-topology.md#11-数据驻留)） |
| 已完成备案，或由准入负责人登记该能力按现行规定不需要备案的依据 | 全部；结构化生成与以生成式模型实现的决策端点必须已备案 | 公开备案信息；不需要备案的依据写入准入记录 |
| 合同与配置禁止使用客户数据训练；敏感数据路由所需的零留存可单独约定 | 全部 | 合同条款；模型目录的 `no_training_on_customer` 只在核实后置为真 |
| 提供兼容协议（OpenAI 兼容优先）或可在一个适配器内完成转换 | 全部 | 接口文档与试调用 |
| 按调用计量与计费，可取得用量明细；按请求等非 token 方式计费的，给出计费单位与价格 | 全部 | 账单样例与报价单；模型目录登记 `billing` 与价格 |
| 返回文字与表格的页面坐标 | OCR 与版面 | 接口文档与试调用 |
| 返回类型化结果（标签或分数、未知或拒答），不需要从自由文本中解析；供应商提供的数值说明其含义（概率、置信分或量表位置） | 决策：分类与评分 | 接口文档与试调用；数值含义登记到模型目录的任务声明 |

候选名单、地域约束与合同条款由项目负责人与采购提供，见第8节。

## 3. 样本

| 任务 | 样本 | 参照答案 | 限制 |
|---|---|---|---|
| T1 字段抽取 | 仓库中的采购语料（`packs/information_domains/procurement/corpus/`，人工核对的 `reviewed.json` 带证据引用）+ 冻结的 50 篇完整公告正文（[契约就绪第2节](../03-architecture/13-contract-readiness.md#2-真实证据与限制)） | 人工核对的字段值与原文位置；50 篇中尚未核对的字段先按标注规则补标 | 两组都是契约发现集，按来源轮询、非随机，只证明初步可行，不代替 [数据质量计划](04-data-quality-organization.md) 的盲测集 |
| T2 品类分类 | 同上，按建材管材行业包品类树补标 | 人工品类与“不属于本行业” | A01 品类条件要求置信度 ≥ 0.7，评测须报告 0.7 处的精确率 |
| T3 嵌入与重排 | 从 T1 样本构造 30 个查询，每查询人工判定候选相关性 | 人工相关性分级 | 正式选型随检索相关性集（首批 200 查询） |
| T5 决策任务（分类） | 每个任务（公告类型、品类初筛、消息意图）各自的开发与校准样本、**独立保留样本**，两者按第3.1节隔离；保留样本须包含标签外、歧义与证据不足的输入，并有人工标注的“应返回未知” | 人工标签或“未知”，标注规则随任务版本保存 | 通用榜单成绩不作为本系统的验收结果 |
| T6 决策任务（评分） | 推荐首个任务：公告与客户经营目标的相关度，1–5 量表，每档有书面定义与示例（任务定义待任务所有者确认）；样本划分同 T5，保留样本须包含目标信息缺失、跨档边界与不相关行业的输入 | 两名标注人独立评分；相差 1 档以内取较低档并记录分歧，相差 2 档及以上由第三人裁决；无法判断的标注为“未知”。标注规则随任务版本保存 | 评分结果不是概率，不用分类指标或校准代替评分验收 |
| T4 OCR 与版面 | 50 篇以 HTML 与文本型 PDF 为主，不能用于 OCR；初评用附件中的扫描件，不足时用文本型 PDF 渲染成图片并标为合成样本 | 原文文字、表格单元格、金额与日期 | 合成样本不代证真实扫描件；正式选型随 OCR 与版面集（首批 100 份） |

### 3.1 决策样本的划分

1. **开发与校准样本**：用于选择提示、模型配置与阈值（含转人工阈值、各类别判定阈值）；
2. **独立保留样本**：在上述配置冻结后才使用，只用于检验第4节的决策指标，不能参与任何选择。保留样本按来源与时间段与开发样本隔离，同一公告或消息不跨两份样本；保留样本的清单哈希在冻结配置前登记；
3. 保留样本检验不通过时，回到开发样本重新调整，并且须用新的保留样本版本（新抽取或尚未使用的样本）再次检验；已看过结果的旧保留样本可并入开发样本，不再作为检验依据。

样本、提示与 Schema 各有版本，所有候选使用同一版本。50 篇原文保存在仓库外，评测前按来源权利登记导入受控位置，评测报告引用其清单哈希。

## 4. 指标

| 维度 | 指标 | 说明 |
|---|---|---|
| 金额 | 数值与币种完全正确率；分别统计小写、大写、万元换算 | 把标包金额累加成项目总价、把费率当金额计为严重错误（[产品需求第2节](../01-product/05-product-requirements.md#2-统一业务与交互规则)） |
| 日期时间 | 精确到分钟的正确率；截止、开标、公告日期分别统计 | 时区按东八区；只有日期没有时间时返回日期，不补时间 |
| 表格 | 单元格级精确率与召回率；行列结构正确率 | 合并单元格、跨页表格单独统计 |
| 证据坐标 | 抽取值能定位回原文的比例：HTML 为字符区间，OCR 为页面框与原文框的交并比 ≥ 0.5 | 定位不到的值不能进入领域事实 |
| 未知处理 | 原文没有的字段返回未知的比例；编造率 | 编造指原文不存在却给出具体值 |
| Schema | 首次输出通过 Schema 的比例 | 网关不对失败输出自动重试（重复计费），由调用方决定 |
| 品类 | 准确率；置信度 ≥ 0.7 时的精确率与覆盖率 | 低于 0.7 转复核 |
| 决策准确性 | 按任务的准确率、各类别精确率与召回率；关键类别漏判率（例如把中标结果判为其他） | 关键类别由任务所有者在任务版本中列出 |
| 未知与拒答 | 标签外、歧义、证据不足输入中返回未知的比例；本应可判的输入被判未知的比例；拒答率 | 未知不计为错误分类，但单独报告其覆盖与代价 |
| 校准（适用时） | 模型提供概率时报告可靠性曲线与 Brier 分数；只提供置信分或不提供数值的不报告校准，也不把置信分当作概率 | 阈值在开发与校准样本上选定并冻结；在独立保留样本上报告该阈值处的精确率、覆盖率与转人工比例 |
| 评分质量 | 按任务：平均绝对误差、与参照评分相差不超过 1 档的一致率、有序一致性（Spearman 或 Kendall 相关）；具体采用哪几项与容差由任务所有者在任务版本中确定 | 只在保留样本上报告；未知与拒答单独统计，不计入误差 |
| 检索 | nDCG@10、Recall@50 | 初评只作排序参考 |
| 稳定性 | 同一样本重复 3 次，结果一致的比例 | 温度设为 0 或供应商的确定性选项 |
| 性能 | p50 / p95 延迟、失败率、限流后的恢复、上下文长度 | 按网关端点时限统计 |
| 成本 | 每千篇公告、每千个分块、每页 OCR、每千次决策的费用 | 按实测用量与计费单位（token 或请求）乘合同价格；价格以报价单为准 |

## 5. 执行

1. 每个候选在模型目录中登记为一个端点（`services/subsystems/aiplatform` 的目录格式），通过模型网关调用；适配器替换故障桩，网关的路由、预算、输出校验与计量不变，计量记录作为用量与延迟的原始数据；
2. 只发送公开数据（数据分级“公开”），不发送任何租户数据；
3. 每个任务固定提示版本与输出 Schema；同一样本按 3 次重复调用；调用预算按样本量预先设置，超出即停止；
4. 评分由脚本对照参照答案完成，金额、日期、坐标的判定规则写入评分脚本并随报告版本保存；人工只裁决脚本标为争议的样本；
5. 每个候选一份报告：准入核验结果、各项指标与置信区间、典型错误样例、成本与限流表现。

## 6. 判定

1. 不满足第2节准入条件的直接淘汰；
2. 每项能力按下表初评阈值筛选（推荐值，待质量负责人与项目负责人确认）：

| 指标 | 初评阈值 |
|---|---|
| 金额完全正确率 | ≥ 98% |
| 日期时间正确率 | ≥ 98% |
| 证据坐标定位率 | ≥ 95% |
| 编造率 | ≤ 1% |
| Schema 首次通过率 | ≥ 97% |
| 品类在置信度 ≥ 0.7 时的精确率 | ≥ 90% |

决策任务不设跨任务的统一阈值：每个任务的可自动处理范围、阈值、关键类别漏判上限（分类）或评分误差上限（评分）与转人工规则由任务所有者在开发与校准样本上提出，在独立保留样本上检验（第3.1节），经质量负责人与项目负责人确认后写入任务版本；确认前该任务只输出建议、全部转人工，不启用自动判断。评分能力在 T6 的任务定义、标注与保留样本检验完成前，不声明评测就绪，也不能用分类成绩代替。

3. 达到阈值的候选中，质量综合最高且满足延迟与成本上限的为主选。备选判定（推荐值，待确认）：
   - 备选本身必须满足该能力的全部绝对门槛（上表阈值；决策任务为任务版本中的阈值），不能因为接近主选而放宽；
   - 每项能力的主要指标：结构化生成为金额、日期时间、证据坐标、Schema 首次通过率；嵌入与重排为 nDCG@10、Recall@50；OCR 为文字与表格单元格的精确率与召回率、证据坐标定位率；分类为任务准确率与关键类别召回率；评分为容差内一致率；
   - 越高越好的主要指标须达到主选数值的 90% 以上；越低越好的指标（编造率、关键类别漏判率、平均绝对误差等）不按比例比较，只要求满足绝对门槛；
   - 决策备选须登记与主选相同的任务版本与数值含义（模型目录校验，[ai-platform 第11节](../03-architecture/subsystems/ai-platform.md#11-决策能力类-jev-决策模型)）；

   只有一家达标时，不宣布 C3 就绪，在报告中写明缺少备选的风险，由项目负责人决定是否以单一供应商加明确失败的方式先行；
4. 结论写入立项清单 C3、C7a 与模型目录，ADR-0015 的“供应商按评测选定主选与备选”据此落地。初评通过不代替正式验收：OCR 须在 OCR 与版面集上、检索须在检索相关性集上复验，结构化生成须在盲测集上复验（[阶段基线 M2-P11](06-stage-baseline.md#4-m2-前置条件与能力交接)）。

## 7. 限额与地域

- 评测与上线都只使用境内处理的端点，模型目录的 `allowed_regions` 只含 `cn`；
- 每次调用设置输入、输出与费用上限（网关 `Budget`），评测总预算由项目负责人确认后配置；
- 并发与速率按供应商合同上限的一半配置，留出余量观察限流行为。
