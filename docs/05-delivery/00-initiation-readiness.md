# 立项准入清单

> 状态：评审中 · 版本：1.5 · 更新：2026-10-13 · 负责人：项目负责人

本文列出进入正式开发（M0 工程基座）之前必须在立项阶段明确的事项，并跟踪每项的状态。

## 1. 等级与状态

| 等级 | 含义 |
|---|---|
| **G0** | 立项前必须完成，否则不应启动 M0 |
| **G1** | 可与 M0 并行，但必须在依赖它的里程碑开始前完成 |

| 状态 | 含义 |
|---|---|
| ✅ 已决定 / 已完成 | 已有决策或书面产出 |
| 🟡 待决策 | 推荐方案已提交，等待项目负责人决策 |
| 🔵 专题对齐 | 另行开展专题讨论 |
| ⬜ 未开始 | 尚无产出 |

## 3. 风险登记（初版）

| 风险 | 影响 | 应对 | 负责 |
|---|---|---|---|
| 主要来源限制访问或条款变化 | 覆盖率下降 | 来源健康监测；授权数据替代；多来源冗余 | 数据负责人 |
| 全国范围来源数量大 | M1 工期压力 | 按覆盖顺序分级接入；来源工程师专职 | 数据负责人 |
| 首发目标过多 | 发布延期 | 商业目标分批发布 | 产品负责人 |
| 两类早期客户需求差异大 | 产品体验割裂 | 产物为中心的统一交互范式；角色模板 | 产品负责人 |
| 关键岗位缺位 | 设计无法落地 | 关键岗位优先到位 | 项目负责人 |
| 评估集不足 | 无法验收质量 | 评估集先于开发建设 | 质量负责人 |
| 按需回填与批量增强成本超预期 | 预算失控 | 成本护栏、批量作业审批、按热度处理 | AI 负责人 |
| 架构复杂度拖慢早期交付 | M0、M1 延期 | `kernel` 与代码生成优先投入；门禁评审 | 首席架构师 |
| Go 与 Python 两套 `kernel`、全部基础组件自建 | 维护与运维负担 | Python `kernel` 只覆盖数据供应平面所需；跨语言契约测试；备份恢复与升级定期演练 | 首席架构师、平台工程负责人 |

## 4. 立项结论条件

1. 全部 G0 事项状态为“已决定 / 已完成”；
2. 技术选型专题完成，ADR 已批准，第一批契约已冻结；
3. 关键岗位到位，子系统负责人明确；
4. 预算批准，成本护栏设定；
5. G1 事项都有负责人和截止时间。
