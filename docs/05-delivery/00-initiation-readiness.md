# 立项准入清单

> 状态：评审中 · 版本：3.8 · 更新：2026-10-17 · 负责人：项目负责人

本文跟踪进入 M0 前的设计准入条件，以及后续能力首次使用前必须关闭的准备事项。人员编制、到岗与项目预算灵活处理，不作为立项准入条件；技术调用的限额、计量与审批仍按运行安全要求设计。

## 1. 等级、状态与证据

- **G0**：M0 开始前必须关闭的范围、设计与决策事项。
- **G1**：可与 M0 并行，必须在表中指定的首次使用或验收节点前关闭。
- **方案批准**：方向与规则已决定；不代表执行产出完成。
- **执行中**：正在交付具体产出。
- **产出完成**：已有可检查的文档、配置或样本，等待验收。
- **验收通过**：满足本项条件，并记录批准或验收证据。
- **待决策 / 未开始**：尚未形成有效决定或产出。

每项记录责任角色、期限、证据与关闭条件。外部维护的客户协议、法律意见、采购合同和登记无需进入代码仓库，但应在相应登记中有版本、编号、批准人和可访问位置。项目负责人确认早期客户已落实；法律授权沿用已确认结论，不用研发审查重新否定。

## 3. 风险登记

| 风险 | 触发条件 | 应对 | 负责 |
|---|---|---|---|
| 来源访问或权利变化 | 来源拒绝访问、条款变化、独有信息缺失 | 暂停来源及受影响输出；授权替代、来源冗余、健康复验 | 数据负责人 |
| 全国覆盖与样本偏差 | 某省/类型覆盖不达标，参照集缺层 | 分层补源与标注，不以当前40个入口宣称全国覆盖 | 数据、质量负责人 |
| 模板和附件导致误解析 | 未选项、空占位被当事实，附件不可读 | 保留未知、正文与附件分别验收、人工复核 | 数据负责人 |
| 外部模型不可用或费用突增 | 超限、限流、质量回归或主供应商故障 | 主备与同级降级、任务限额、部分结果、计量告警 | AI 负责人 |
| 回填影响增量采集 | 队列滞后、任务范围超出来源可得范围 | 在线优先、限速、分批、截止后部分交付 | 数据负责人 |
| VPS 到生产迁移失真 | 数据/索引/事件版本不一致或恢复失败 | 导出校验、重放、影子验证、切换与回退演练 | 平台工程负责人 |
| 双语言内核与自建组件复杂度 | 契约漂移或升级/恢复演练失败 | 限定 Python kernel 范围、跨语言测试、故障与升级演练 | 首席架构师 |
| 首发交付或客户体验不达标 | 关键旅程失败、分层指标不达标 | 分阶段验收、反馈闭环、暂停受影响能力发布 | 产品、质量负责人 |

## 4. 立项结论条件

1. G0 的设计/决策事项有有效批准；要求具体产出的事项完成验收，不能只凭状态图标放行。
2. 首批工程横切契约按明确文件范围冻结；业务领域契约按 C4b 的阶段与样本证据验收。
3. 每个 G1 有责任角色、期限、关闭条件与证据位置；首次使用前检查相应门禁。
4. 范围与阶段基线批准，跨文档的决策、权限、契约和依赖不存在未处置冲突。
5. 人员与项目预算由项目负责人灵活安排，不纳入本清单的准入判断。
