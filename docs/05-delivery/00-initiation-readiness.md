# 立项准入清单

> 状态：评审中 · 版本：1.0 · 更新：2026-10-13 · 负责人：项目负责人

本文列出进入正式开发（M0 工程基座）之前必须在立项阶段明确的事项。现有文档已经确定了业务层级、商业目标、子系统边界、数据分层和技术方向；下面是**尚未确定、但会直接影响开发能否顺利开始或会造成返工**的内容。

## 1. 准入等级

| 等级 | 含义 |
|---|---|
| **G0 立项前必须完成** | 不完成就不应启动 M0：要么决定不了怎么建，要么开工后大概率返工，要么有法律风险 |
| **G1 对应里程碑开始前完成** | 可以与 M0 并行推进，但必须在依赖它的里程碑开始前完成 |

## 3. 业务与产品

### A1 首发范围（G0）

现有文档定义了平台的全部能力，但还没有回答“第一个对外发布版本具体覆盖什么”。这决定了 M1 的来源工作量、M4 的发布节奏和质量门槛的测量范围。需要明确：

| 维度 | 需要决定的问题 |
|---|---|
| 区域 | 全国，还是先覆盖若干省份？中央、省、市、县各级平台覆盖到哪一级？ |
| 来源 | P0 来源清单：政府采购网站、公共资源交易平台、哪些国企采购平台 |
| 信息领域 | 首发是否包含项目审批、企业、信用？还是只含公共采购，其余在 M4 补齐？ |
| 商业目标 | 路线图把十余个目标都放在 M4 发布，建议确定**首发必须有**的目标（例如直接投标、进入供货、竞争情报、交易对手风险）和后续增量目标 |
| 客户细分 | 首发提供哪些行业包、哪些价值链角色模板 |
| 历史深度 | 首发需要回溯几年的历史数据（影响买方历史、竞争分析和存储规模） |

### A2 产品需求与交互设计（M2 前）

目前文档是业务与架构层面的，还没有：

- 关键用户旅程的产品需求文档（PRD），含每个功能的验收标准；
- 信息架构与关键页面原型（信号收件箱、证据查看、研究报告、推进看板、策略实验室）；
- 设计规范（组件、交互模式、AI 内容标识与证据展示的统一样式）；
- 企业微信卡片与消息模板。

这些需要在 M2 开发前完成，并建议在 M0 期间开始，用原型提前和早期使用客户验证可用性。

### A3 早期使用客户（M2 前）

需要明确招募对象（覆盖多种价值链角色）、试用权益，以及协议条款：客户提供哪些资料、数据如何使用、反馈和标注的授权范围、保密义务。

## 4. 法律与合规

这是立项阶段**风险最高、最容易被低估**的部分。下列结论需要由专业法务确认，本文只列出需要回答的问题。

### B1 来源采集的法律意见（G0）

平台的核心数据来自对公开网站的自动化采集并用于商业服务。需要法律意见明确：

- 公开采购信息的采集、存储、加工、展示、再分发是否存在限制；各主要来源网站的使用条款与技术保护措施；
- 自动化采集的合规边界（访问频率、绕过限制的禁止、对网站运营的影响）；
- 数据加工产品可能涉及的不正当竞争风险；
- 原文展示与链接回源的方式；
- 来源权利登记的审查流程与责任人。

产出 P0 来源的权利清单，作为 `acquisition` 来源注册的前置条件。

### B2 授权数据采购（G0）

企业工商、司法信用、资质等信息领域通常需要向商业数据供应商采购。需要比选供应商并评估：价格、覆盖、更新频率，以及条款是否允许**存储、加工、向客户展示和用于模型**。条款限制会直接影响实体图谱与研究工具的设计。

### B3 经营资质（G0）

确认面向企业收费的在线信息服务需要哪些资质（ICP 备案，以及是否需要增值电信业务经营许可证）、办理主体与周期，避免上线时被资质卡住。

### B4 网络安全等级保护（G0）

面向企业客户的 SaaS 平台通常需要完成等级保护测评，大型客户和国企客户也会在采购时要求。定级目标（例如二级或三级）会影响网络分区、日志留存、审计、访问控制、加密与运维管理等基础设施设计，必须在 M0 之前确定，而不是上线前补做。

### B5 算法与生成式 AI 的备案/登记（G0）

需要确认平台以下功能各自适用的监管义务：

- 信号推送与排序是否属于算法推荐服务，是否需要算法备案；
- 通过 API 调用已备案大模型提供生成内容，是否需要进行生成式 AI 应用登记；
- 生成内容的标识方式；
- 私有部署开源模型时的义务。

### B6–B8

- **B6 个人信息保护影响评估**：联系人等个人信息字段的处理目的、存储、展示与导出规则；数据分类分级目录初版；
- **B7 对外协议**：用户协议、隐私政策、数据处理协议（尤其是客户上传资料的使用边界与模型使用）、服务等级协议；
- **B8 知识产权**：“妙洽”商标注册状态；员工与外包协议中的代码权属条款；开源许可合规策略。

## 5. 技术决策

### C1 公有云厂商（G0）

M0 第一周就要创建账号、网络与托管服务，厂商必须先定。评估维度：托管 PostgreSQL / Kafka / OpenSearch / Kubernetes 的成熟度、GPU 资源可得性、等级保护支持、价格、私有化部署的一致性。

### C2 容量规划与非功能指标（G0）

基础设施按终态一次建设，但规格需要有依据。需要给出发布时、一年后、三年后三个时点的估算：

| 项目 | 需要估算的内容 |
|---|---|
| 来源 | 来源数量、每日抓取量、附件比例 |
| 内容 | 每日新增公告与附件、分块数量、历史回溯量 |
| 租户 | 租户数、每租户用户数、每租户监测条件数 |
| 负载 | 每日信号数、研究任务数、检索请求数 |
| AI | 每日增强处理量、研究的模型调用量 |
| 成本 | 基础设施、模型、数据采购的月度成本 |

这些数字决定集群规格、分区策略和成本护栏，也是 [数据架构](../03-architecture/02-data-architecture.md#36-数据规模估算) 中标注“待核验”的规模估算的正式版本。

### C4 核心契约 v1（分批冻结）

| 批次 | 内容 | 冻结时点 |
|---|---|---|
| 第一批（G0） | 标识符规则、请求上下文、事件信封与命名、错误格式、租户与单元标识、审计事件结构 | M0 开始前 |
| 第二批（M1 前） | 原始制品、快照、规范化文档与分块、增强结果、领域事实 `INF-PROC` Schema、实体与关系 | M1 开始前 |
| 第三批（M2 前） | 客户档案、目标、策略 DSL、信号、判断、决策 | M2 开始前 |
| 第四批（M3 前） | 研究模板、受控工具、研究报告 | M3 开始前 |

### C5–C8

- **C5 策略 DSL**：语法、可用字段与函数、执行语义、编译到订阅反查的规则、错误与解释输出；它同时影响 `customer-context`、`detection`、`learning` 和界面，是客户智能平面最关键的设计；
- **C6 权限矩阵**：角色 × 资源 × 动作 × 条件，以及高影响动作的审批规则；
- **C7 选型基准**：OCR 与版面分析方案（M1 前）、图查询引擎（M4 前），用真实样本做基准测试；
- **C8 ADR 批准**：当前 13 份 ADR 都是“提议”状态，需要架构评审会正式批准，作为开发依据。

## 6. 数据、质量与组织

### D1–D3 质量基线

质量门槛（见 [质量与验收](02-quality-and-acceptance.md)）需要评估集才能测量。评估集建设周期长，必须先于开发启动：

- **D1 来源参照集**：按首发范围抽样的官方公告清单，用于测量覆盖率；
- **D2 标注**：字段、分类与标签、实体与聚合、相关性的标注手册，以及标注人员（内部或外包）；
- **D3 指标口径**：每个指标的样本、计算方法和负责人，在 M1 中期冻结。

### E1 团队与负责人（G0）

[路线图](01-roadmap.md#4-团队组织) 定义了八个团队。立项阶段需要明确：

- 关键岗位到位情况：首席架构师、产品负责人、安全与合规负责人、招投标领域专家；
- 18 个子系统各自的负责人；
- 招聘与外包计划，以及 M0 启动时的最小到岗人数。

### E2 决策与评审机制（G0）

- 架构评审会成员与 ADR 批准规则；
- 里程碑门禁评审：每个里程碑的退出标准由谁验收；
- 范围变更流程：新增商业目标、信息领域或功能的决策路径。

### E3 预算与成本护栏（G0）

预算充足不等于成本不需要管控。需要分项预算（人员、基础设施、模型、授权数据、合规与测评、外包标注），并设定月度成本上限与告警，特别是模型调用与历史数据批量增强这两类容易失控的开销。

## 7. 风险登记（初版）

| 风险 | 影响 | 应对 | 负责 |
|---|---|---|---|
| 主要来源限制访问或条款变化 | 覆盖率下降 | B1 法律意见；来源健康监测；授权数据替代；多来源冗余 | 数据负责人 |
| 合规义务未提前识别 | 上线延期或整改 | B3–B5 在 G0 完成 | 法务 |
| 首发范围过大 | 发布延期 | A1 明确首发与增量范围 | 产品负责人 |
| 关键岗位缺位 | 设计无法落地 | E1 关键岗位优先 | 项目负责人 |
| 评估集不足 | 无法验收质量 | D1–D2 先于开发 | 质量负责人 |
| 模型与批量增强成本超预期 | 预算失控 | 成本分级、预算上限、按热度处理 | AI 负责人 |
| 架构复杂度拖慢早期交付 | M0、M1 延期 | `kernel` 与代码生成优先投入；里程碑门禁评审 | 首席架构师 |

## 8. 立项结论条件

满足以下条件即可正式立项、启动 M0：

1. 全部 G0 事项完成，并有对应的书面产出；
2. 13 份 ADR 已批准，第一批契约已冻结；
3. 关键岗位到位，子系统负责人明确；
4. 预算批准，成本护栏设定；
5. G1 事项都有负责人和截止时间。
