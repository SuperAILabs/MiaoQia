# Agent 研究子系统（research）

> 状态：评审中 · 版本：1.1 · 更新：2026-10-17 · 平面：客户智能

## 1. 使命

围绕一个具体的业务问题，按研究模板调用受控工具调查取证、交叉验证，产出区分事实、推断、未知项和建议的可追溯研究报告。

## 2. 职责与非职责

**职责**

- 研究案例：问题、目标对象、目标、发起者、预算、状态；
- 研究模板执行：按模板定义的步骤、工具集、预算和输出 Schema 运行；
- Agent 运行时：规划、工具调用、观察、反思、检查点、恢复（基于 Temporal）；
- 工具注册与执行：受控工具的注册、权限检查、调用与结果记录；
- 证据集合：本次研究使用的证据引用汇总；
- 引用校验：报告中每条事实必须能解析到证据；无法校验的降级为推断或未知项；
- 研究报告：结构化报告 + 可读摘要，固定引用全部版本；
- 报告复用：同一租户内相同问题已有合格报告时复用，不重复调用模型（第 11 节）；
- 人工参与：研究中途向用户请求澄清或确认（中断与恢复）。

**非职责**

- 不形成客户判断与决策（研究报告是 `assessment` 的输入）；
- 不执行任何对外副作用（发送、导出、修改策略）；唯一允许的是向 `acquisition` 提交公共来源的数据获取请求（补采、历史回填），研究可等待结果或以“未知项”继续；
- 不直接访问任何子系统的数据库，只通过工具调用接口。

## 3. 内部组件

| 组件 | 说明 |
|---|---|
| `intake` | 研究入口：把自然语言问题（来自 Web“问妙洽”、渠道内对话、MCP）路由到研究模板或检索，必要时向用户澄清 |
| `case_manager` | 研究案例生命周期 |
| `template_registry` | 研究模板（由应用领域包提供，版本化） |
| `agent_runtime` | Agent 循环：在 Temporal 工作流中执行，每次模型调用与工具调用是活动（activity），可重试与恢复 |
| `tool_registry` | 受控工具目录：名称、输入输出 Schema、所需权限、数据分级、成本、超时 |
| `tool_executor` | 以研究发起者的身份与租户上下文调用工具，执行权限与预算检查 |
| `citation_verifier` | 引用解析与一致性校验 |
| `report_builder` | 报告组装、版本固定、摘要 |

## 4. 拥有的数据（租户域）

| 实体 | 说明 |
|---|---|
| `ResearchCase` | `rsc_`：问题、目标对象、模板与版本、发起者、预算、状态 |
| `ResearchRun` | 一次运行：模型、提示版本、工具调用序列、成本、耗时、检查点 |
| `ToolInvocation` | 工具、参数（净化后）、结果摘要、证据引用、耗时、成本 |
| `EvidenceBundle` | 证据引用集合 |
| `ResearchReport` | 不可变报告：`facts[]`、`inferences[]`、`unknowns[]`、`recommendations[]`，每项带证据引用与置信说明；固定的数据、上下文、模型、工具版本 |

## 5. 接口

| 接口 | 类型 | 说明 |
|---|---|---|
| `Ask` | 命令 | 自然语言问题 + 会话上下文 → 选择模板或检索，返回研究案例或直接答复（Web、渠道、MCP 共用） |
| `StartResearch` | 命令 | 模板、目标对象、问题、预算 → 返回案例与运行标识（异步） |
| `GetResearchCase` / `GetResearchReport` | 查询 | 进展、工具调用轨迹、报告 |
| `ProvideClarification` | 命令 | 回答 Agent 的澄清请求 |
| `CancelResearch` | 命令 | 取消 |
| `ListTools` | 查询 | 当前租户和用户可用的工具 |

## 6. 事件

**发布**：`research.case.requested.v1`、`research.case.awaiting_input.v1`、`research.case.completed.v1`、`research.case.failed.v1`。

**消费**：`assessment.research.requested.v1`（判断需要深度研究）、`pursuit.stage.entered.v1`（机会路径阶段默认研究）。

## 7. 扩展点

- **研究模板**：由应用领域包以声明式定义提供，见 [AI 与 Agent 架构](../05-ai-and-agent-architecture.md)；
- **受控工具**：数据供应平面子系统与 `customer-context` 暴露的查询接口经适配注册为工具；信息领域包可注册领域专用工具；
- **输出 Schema**：模板可声明类型化的研究产物（如 `EligibilityMatrix`）。

## 8. 伸缩与可靠性

- 研究是长时、多步、成本敏感的任务，在独立的工作流任务队列执行，按队列深度伸缩；
- 每次运行有预算（模型成本、工具调用次数、时长），超出即以“部分结果 + 未完成说明”结束；
- 模型或工具失败按活动重试策略处理；工作流可从检查点恢复；
- 按租户与套餐的并发上限，防止单租户占满资源。

## 9. 安全要点

- 工具执行时的租户与权限来自研究发起者的认证上下文，Agent 生成的参数不能指定租户；
- 工具返回的外部文本带不可信标记，不能改变系统指令或触发新工具权限；
- 敏感分级的知识资产只在允许的模型路由下进入上下文；
- 研究轨迹全量记录，可审计。

## 10. 评估责任

research 拥有研究模板的引用、事实质量、完成率与预算指标、回归执行及模板发布门禁；learning 提供授权反馈集并编排/汇总。模型基础能力评测属于 ai-platform，不能代证研究模板质量。

## 11. 报告复用与预算

**报告复用**是在同一租户内把已完成的研究报告提供给新的同类请求，省去重复研究。它与 `ai-platform` 的模型调用缓存是两件事：模型调用缓存只用于公共域确定性任务；报告复用只在租户内，不跨租户，复用的是带固定版本的整份报告，不是单次模型输出。

新请求与已有报告同时满足以下条件才复用，否则重新研究：

| 条件 | 规则 |
|---|---|
| 问题与模板 | 同一研究模板及兼容版本（模板声明哪些版本之间可复用），问题参数一致 |
| 目标对象 | 同一目标对象；持续型推进按本期成员快照比较，成员不同不复用 |
| 客户上下文 | 报告固定的客户上下文快照仍是当前版本，或模板声明不依赖变化的部分 |
| 权限 | 请求者对报告引用的每项租户数据（知识资产、推进、判断）都有读取权限；按请求者逐项检查，不沿用原发起者的权限 |
| 新鲜度 | 报告生成时间在模板声明的新鲜度窗口内，且报告引用的领域事实没有更新版本或撤回（[领域情报第 11 节](domain-intelligence.md#11-事实撤回与恢复)） |
| 撤权 | 报告引用的来源权利与租户授权仍然有效（[数据架构第 12 节](../02-data-architecture.md#12-来源权利与数据权益)）；任一失效则不复用，并标注原报告受影响 |

复用产生新的研究案例，引用被复用的报告并记录复用依据；界面标明“复用 X 日的报告”，用户可以要求重新研究。报告只在租户内共享，不对外发送（[identity 第 7 节](identity.md#7-授权模型)）。

**预算**按目标分配：租户的研究预算（模型成本、工具调用次数）在各目标之间分配额度，研究案例从所属目标的额度扣减，没有目标的临时提问从租户的公共额度扣减；复用不扣模型成本。单次运行的预算上限仍由研究模板声明（[AI 与 Agent 架构第 2 节](../05-ai-and-agent-architecture.md#2-研究模板)）。额度用尽时新研究排队或需要有权限的人追加，不降级为不完整的研究冒充完成。
