# AI 平台子系统（ai-platform）

> 状态：评审中 · 版本：2.2 · 更新：2026-10-17 · 平面：平台

## 1. 使命

为平台中所有 AI 使用场景提供统一、受治理、可计量、可评估的模型能力，使业务子系统无需关心具体模型供应商。

## 2. 职责

- **模型网关**：统一的生成、结构化输出、嵌入、重排、OCR/版面，以及分类与评分两类决策能力（[第11节](#11-决策能力类-jev-决策模型)）的模型调用接口；
- **路由**：按任务类型、数据分级、租户策略、模型备案状态、地域、成本、质量和可用性选择模型；
- **模型目录**：模型供应商、模型版本、能力、计费单位与价格（按 token 或按请求）、备案信息、可用区域、上下文长度，以及决策端点经评测准入的任务版本与数值含义；也是模型产出进入策略视图时“产出者版本”引用的唯一来源（[策略 DSL 5.1](../11-policy-dsl.md#51-变量)），业务评分定义不在此登记；
- **提示注册**：提示模板、版本、输出 Schema、适用模型、评估结果；
- **护栏**：输入净化与不可信内容隔离、输出 Schema 校验、敏感信息检测与脱敏、内容安全检查；
- **计量与记录**：每次调用的模型、提示或任务版本、计费单位与用量（token 或请求数）、延迟、成本、调用方、租户、调用状态与决策结果状态（已决/未知/拒答）；
- **缓存**：对确定性任务（如公共文档解析）的结果缓存，仅限公共域；
- **供应商接入**：前期全部模型能力经供应商 API 获得（ADR-0015），以 OpenAI 兼容协议适配器为主；私有部署客户可配置其自有端点。

## 3. 内部组件

`gateway`、`router`、`model_catalog`、`prompt_registry`、`guardrails`、`embedding_service`、`metering`、`provider_adapters`（供应商适配器）。

## 4. 拥有的数据

`ModelProvider`、`ModelVersion`、`RoutingPolicy`、`PromptTemplate` / `PromptVersion`、`Invocation`（调用记录，敏感内容不落日志，只存哈希与引用）。

## 5. 接口

| 接口 | 说明 |
|---|---|
| `Generate(task, prompt_ref, inputs, schema, context)` | 结构化生成；`context` 包含租户、数据分级、调用方、预算 |
| `Embed(texts, purpose)` | 向量化 |
| `Rerank(query, candidates)` | 重排 |
| `Classify(task, task_version, inputs, labels, context)` | 单标签分类：从带定义的候选标签中选一个，或返回未知/拒答（[第11节](#11-决策能力类-jev-决策模型)） |
| `Score(task, task_version, inputs, scale, context)` | 量表评分：在给定范围与含义的量表上评分，或返回未知/拒答 |
| `GetPrompt` / `RegisterPromptVersion` | 提示管理 |
| `GetModelCatalog` / `UpdateRoutingPolicy` | 目录与路由策略管理 |

**发布**：`ai_platform.invocation.recorded.v1`（计量）、`ai_platform.model.degraded.v1`。

## 7. 路由规则示例

| 条件 | 路由 |
|---|---|
| 数据分级约束 | 按 [安全与租户](../06-security-and-tenancy.md#5-数据分级与处理约束) 的分级表执行 |
| 私有部署租户 | 客户自有端点 |
| 公共域文档解析 | 成本优先的已备案模型，结果可缓存 |
| 研究规划与归纳 | 质量优先的已备案模型 |
| 主模型不可用 | 同等级备用模型；无备用时返回明确错误，不降级到不合规模型 |
| 分类与评分 | 只路由到目录中声明支持该任务版本的端点；同一任务版本的主备端点数值含义必须一致，目录校验拒绝不一致的登记 |
| 费用与输入上限 | 上限约束整次逻辑调用（含主备切换），负值为非法请求；按端点计费单位估算：按请求计费用请求价，按 token 计费用输入上界与输出上限，输出有价格而请求未给输出上限的端点不参与；每次尝试前按已发生费用检查剩余上限，不足即停止（第11.5节） |

默认只使用境内处理的模型。任何境外模型调用需经数据分级、合同与跨境合规评估并在路由策略中显式启用。路由按租户所在 Cell 或私有部署的驻留策略过滤端点，端点的处理位置登记在模型目录中（[部署拓扑第 11 节](../07-deployment-topology.md#11-数据驻留)）。

## 8. 安全要点

- 模型供应商合同与配置均需禁止使用客户数据训练；
- 提示中的外部内容与客户文档以结构化方式隔离，并标注为不可信数据；
- 调用记录不保存敏感原文；需要调试时通过受控的短期采样并审计。


## 9. 首次使用门禁

M1的OCR/增强/嵌入前必须完成最小供应商目录、适配、分级路由、净化/输出校验、限流/超时/费用计量和主备失败处理；模型合同与配置禁止训练客户数据。M3在此基础上扩展研究提示与模型路由，不重新建立另一套调用或计量接口。供应商评测使用同一版本的OCR/检索/结构化输出/决策任务样本，记录质量、延迟、价格单位、上下文限制和失败（C3/C7a 供应商评测方案随后续 PR 提交）；决策能力另按第11.6节的条件启用自动判断；无法同级降级时明确失败或部分交付。

## 10. 评估责任

本子系统拥有模型/提示基础能力的指标、评测执行与路由/提示发布门禁。research、assessment、evidence、search 拥有各自场景质量与发布决定；learning 可提供授权数据集和编排，不替代场景所有者门禁。公共调用基线不直接读取租户反馈。

## 11. 决策能力（类 Jev 决策模型）

本节是分类与评分能力的当前有效定义，网关契约见 [`api/gateway.go`](../../../services/subsystems/aiplatform/api/gateway.go)。能力范围由项目负责人在 [PR #18](https://github.com/SuperAILabs/MiaoQia/pull/18#issuecomment-6232331222) 批准；当前只批准能力设计与离线实现，不包含供应商选定或真实调用。

### 11.1 定义

“类 Jev 决策模型”指一种能力形态，不指某个品牌：输入业务状态或文本，加上明确的问题和候选标签及其定义，或评分量表，输出固定选项、量表上的分数，或模型实际提供的概率等类型化结果。它服务于分类、评分、路由等边界明确的小决策，不承担开放式写作、解释或研究报告。Jev 是参考例子；“类 Jev”不指定底层网络架构，也不意味着必须采购 Jev。任何模型或适配器只要满足同一契约并通过该任务的评测，都可以承担这项能力，通用 LLM 端点也可以。

### 11.2 职责划分

| 任务 | 承担方 | 理由 |
|---|---|---|
| 固定标签分类、评分、消息意图、处理路由（如公告类型、品类初筛） | 决策能力（`classify` / `score`） | 结果是受约束的标签或分数，不靠业务层从自由文本里猜 |
| 金额门槛、权限、审批、策略排除等明确规则 | 确定性规则（策略 DSL、identity 授权、审批） | 模型是统计判断，可能误判；规则必须可复现 |
| 开放式分析、复杂研究、简报撰写与解释 | 通用 LLM（`generate`） | 需要生成文本与结构化内容 |

决策结果只是业务判断的输入。模型不能替代权限校验或审批，也不获得执行业务动作的权限；最终动作仍由业务规则和审批机制决定。决策能力与通用 LLM 受相同的业务权限约束。

决策能力与通用 LLM 的区别在调用契约和职责，不在“能不能输出 JSON”：不能因为 LLM 能输出 JSON，就认为它与某个决策模型在概率语义、校准、延迟、成本和降级行为上可以直接互换。两者能否互为主备，由同一任务版本的评测与目录声明决定（11.4）。

分类模型不会自动给出可信的解释或证据坐标。业务需要证据时，单独定义来源关联与校验，不能从一个分类标签反推出不存在的证据。

### 11.3 在 MiaoQia 中的例子

- **公告类型**：输入正文，候选“招标公告 / 中标结果 / 更正公告 / 其他”，输出标签，以及模型实际提供、含义已声明的分数；证据不足或标签外输入返回未知，不强制归类；
- **品类初筛或消息意图**：从业务定义的固定类别中选择，用于后续处理路由；复杂、歧义或低置信输入按任务策略转复核或升级；
- **金额是否超过已配置阈值**：对已确认的结构化金额用确定性规则计算，不交给模型；
- **简报撰写与复杂研究**：继续使用适合的通用 LLM。

### 11.4 契约

| 项 | 规则 |
|---|---|
| 请求 | 任务名（`task`）与任务版本（`task_version`）、输入、数据分级与预算；分类另带至少两个候选标签及业务定义，评分另带量表（最小值、最大值、含义）。标签集合、定义、量表与阈值都随任务版本固定 |
| 结果 | 结果状态（已决 / 未知 / 拒答）、标签或分数、数值含义、未知原因、任务版本、模型版本、用量与调用标识 |
| 数值含义 | 由模型目录按任务版本声明：分类为 `none`（只给标签）、`probability`（模型提供的概率）或 `confidence`（模型提供、未声明为概率的置信分），评分为 `scale`（量表位置）。网关不把任意分数称为概率或置信度；模型没有提供的数值保持为空，网关与适配器都不生成 |
| 未知与拒答 | 模型可以返回未知（标签外、歧义、证据不足、模型自身置信不足、未说明）或拒答。它们是成功的调用结果，照常计费与计量，不触发主备切换；调用方按任务策略转复核或升级，不能改选标签或默认为否 |
| 输出校验 | 标签不在候选中、分数越界或非数、带了目录声明不提供的数值、未知或拒答结果夹带标签或数值时，返回 `output_invalid`，不改选、不重试、不切换 |
| 供应商故障 | 不可用与超时按主备切换；全部失败返回 `provider_unavailable`。故障与未知分开表达 |
| 路由与主备 | 端点须声明 `classify` 或 `score` 能力并登记经评测准入的任务版本；同一任务版本的所有端点声明的能力与数值含义必须一致，否则目录校验失败。主备切换因此只在输出语义可比的合规端点之间发生 |
| 阈值 | 网关和模型目录不设阈值。阈值与转人工、升级条件属于任务版本，由任务所有者按评测与业务策略确定 |
| 适配器 | 只从供应商响应的类型化字段转换结果，不解析自由文本 |

数据分级、处理地域、备案与禁止训练条款、费用上限、超时、输出校验和计量对决策能力同样生效，不另建供应商调用或治理链路。

### 11.5 计费

本节的计费与预算规则对网关的所有能力生效，不只适用于决策能力。

- **计费单位**：模型目录为每个端点声明 `token`（每千输入/输出 token 价格）或 `request`（每次请求价格）。按请求计费的端点不因没有 token 而视为免费，未登记价格的端点不能通过目录校验。
- **输入上界**：按送给供应商的全部内容估算，包括指令、输入、输出 Schema、候选标签与量表。取 UTF-8 字节数且每段加 1，再加端点登记的适配器附加量 `request_overhead_tokens`。字节级 BPE 与带字节回退的 SentencePiece 分词中每个 token 至少对应 1 个字节，字符数不是通用上界（一个汉字可能拆成多个 token）。真实适配器接入时可换用供应商的精确计数，但不得低于实际发送内容。输入上界超出本次上限或端点上下文的端点不参与本次调用。
- **调用前费用判断**：上限约束一次逻辑调用，包括主备切换中的全部尝试；预算任一项为负即作为非法请求拒绝。按 token 计费且输出有价格的端点，请求未给输出上限时费用无法限定，该端点不参与本次调用。每次尝试前用已发生费用加该端点的估算上界与上限比较，超出则不再调用该端点；已调用端点全部失败且其余端点因此被跳过时返回 `budget_exceeded`。
- **失败尝试的费用**：供应商报告了用量的失败尝试按实际费用扣减并计量；未报告用量的失败尝试按其调用前估算上界扣减剩余上限，计量标为费用未知，不当作已知为零。
- **数值边界**：估算与计量中的乘法、向上取整与求和都检查溢出。费用超出可表示范围的端点不参与本次调用；供应商报告的用量为负或无法换算时，按费用未知处理；已发生费用饱和累加，并以剩余额度比较。
- **实际用量**：每条计量记录计费单位、token 数、计费请求数与费用，同一逻辑调用的记录共享调用标识；按请求计费的成功调用至少计一次请求。成功结果的 `usage` 是成功那次尝试的用量，`call` 是整次逻辑调用的尝试次数、已知费用合计与是否有未知费用，调用方据此追踪总成本。

### 11.6 真实接入与自动判断条件

“纳入决策能力”不等于选定 Jev，也不等于允许真实调用：

1. 决策模型候选与通用 LLM 候选一起进入 C3/C7a 供应商评测方案（随后续 PR 提交），按具体中文业务任务比较准确率、关键类别漏判率、校准（适用时）、拒答与未知覆盖、延迟与成本；阈值用包含标签外、歧义和证据不足输入的独立验证样本检验。通用榜单表现不能当作本系统的验收结果；
2. 一个任务的可自动处理范围、阈值、转人工与升级规则及其版本明确并验证后，才能启用自动判断；
3. 真实供应商调用、数据用途、处理地域、采购与上线继续遵守立项清单 C3、C7a 等门禁和 [PR #17 决策记录](https://github.com/SuperAILabs/MiaoQia/pull/17#issuecomment-6232158680) 的 D5、D6 条件。

### 11.7 调研依据与限制

参考研究：Tobias Deußer、Lorenz Sparrenberg、Rafet Sifa，*Evaluating and Benchmarking the System One Model Jev*，arXiv 预印本 [2609.37647](https://arxiv.org/abs/2609.37647)，2026-09-29。研究对象是 Jev 1.13.0（TypeSafe AI 的商用模型），与 Qwen3.8-27B、Gemma-4-E4B 比较，覆盖 37 个数据集，任务包括分类、路由、自然语言推断、阅读理解、常识推理、内容审核、法律条款分析与量表评分；接口返回固定选择、量表位置或判断概率。

研究给出的限制：三个模型在低资源语言、细粒度或噪声标签、量表式质量判断上都会退化；二元概率排序效果好，但直接用固定 0.5 阈值表现不佳，需要按任务调阈值；测试排除了浅层记忆，但不能排除记住问答对。

因此本项目不把专用决策模型直接等同于更准确、更快或更便宜，也不把供应商称为概率的数字直接当作本业务已校准的置信度。该研究只是特定版本与数据集上的证据，不是本项目的独立复现、供应商准入证明或中文采购业务验收。具体可用性、价格、数据处理地域与供应商条件尚未核实，本文不登记任何性能或价格承诺。
