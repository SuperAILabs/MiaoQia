# 领域情报子系统（domain-intelligence）

> 状态：评审中 · 版本：2.6 · 更新：2026-10-26 · 平面：数据供应

## 1. 使命

把解析结果组织为各信息领域的领域事实、生命周期和领域事件，为监测、研究和判断提供语义清晰、版本可追溯的外部事实。

## 2. 职责与非职责

**职责**

- 领域事实管理：按信息领域 Schema 物化领域事实及其版本；
- 跨记录聚合：把多条记录归并为同一领域对象（如多条公告归入同一采购项目），记录置信度与合并历史；
- 生命周期：执行领域包定义的状态机，记录状态转换与依据；
- 领域事件：检测有业务意义的变化并发布（如更正导致截止时间变化）；
- 覆盖与时效度量：按来源、区域、品类统计覆盖与延迟，发现缺口；按信息领域登记并发布服务状态（未接入 / 内测 / 已上线）与按区域的已覆盖历史起点，供应用领域包判断启用依赖与视图的历史窗口是否满足（见[可扩展性](../04-extensibility.md#4-加载版本与发布)）；
- 领域查询：按领域对象、项目链、时间范围的结构化查询；
- 领域统计：为研究工具提供聚合统计（如某采购人历年采购）。这类统计由领域事实派生，仍归本子系统；来自独立统计、价格或财务来源的观测数据属于单独的信息领域（[信息领域目录第 5 节](../../02-business/03-information-domains.md#5-观测类信息领域)），不混入采购派生统计。

**非职责**

- 不拥有组织、项目等共享实体（属于 `entity-graph`，本子系统只持有实体引用）；
- 不执行全文或语义检索（属于 `search`）；
- 不接触任何租户数据。

## 3. 内部组件

| 组件 | 说明 |
|---|---|
| `fact_store` | 领域事实与版本的存储与查询，按信息领域分 schema |
| `aggregator` | 跨记录聚合：确定性规则 + 候选匹配 + 人工复核接口 |
| `lifecycle_engine` | 通用状态机执行器，状态机定义由领域包提供 |
| `change_detector` | 比较领域事实版本，生成领域事件 |
| `coverage` | 覆盖率、时效、缺口检测 |
| `statistics` | 维护按采购人、品类、区域、时间等维度的统计汇总表，随领域事实增量更新 |

## 4. 拥有的数据（公共域）

- 各信息领域的领域事实表（例如 `proc.notice`、`proc.lot`、`proc.bid_result`、`invp.approval`），每个信息领域一个 schema；只保存结构化字段与证据定位符，正文与附件文本留在对象存储；
- `DomainFactVersion`：领域事实的版本链，引用产生它的解析修订；
- `AggregationLink`：记录到领域对象的归并关系、方法、置信度、状态（自动/候选/已确认/已撤销）；
- `LifecycleTransition`：状态转换、触发事实、时间；
- `CoverageMetric`。

## 5. 接口

| 接口 | 类型 | 说明 |
|---|---|---|
| `GetFact` | 查询 | 指定领域事实的当前或指定版本，含字段溯源。调用方须指明口径（第 11 节）：当前、业务有效（某时点）或当时已知（某记录时点；从信号还原时取信号的 `evaluated_at`）；返回所用口径、版本、撤回与恢复标记，以及更正应用前后的字段值与更正公告引用（[PRD 第4段](../../01-product/prd/04-object-page-evidence.md) F6、F7） |
| `GetFactHistory` | 查询 | 版本历史与变化，按平台记录时间排列，每个版本带原因（来源更正、解析修订、撤回、恢复）、业务生效时间与发现时间 |
| `GetProjectChain` | 查询 | 项目链：跨阶段、跨信息领域的关联对象。调用方须指明口径（第 11 节）：当前、业务有效（某时点）或当时已知（某记录时点），归属边按同一口径取当时已记录或业务有效的边；从信号还原时记录时点取信号的 `evaluated_at`，不取 `created_at`；返回所用口径与截至时间（[PRD 第4段](../../01-product/prd/04-object-page-evidence.md) F3、F4） |
| `QueryFacts` | 查询 | 结构化条件查询（领域包注册的查询模板）；调用方指明口径（当前，或当时已知某记录时点 R），响应返回同一口径与 R，当时已知口径不返回 R 之后记录的版本。从信号还原“信号判断时”视角时，R 取信号的逻辑求值时间 `evaluated_at`（回填时为被回放事件的时间），不取信号的写入时间 `created_at`，与求值和回放选取版本的方式一致（[策略 DSL 4.3](../11-policy-dsl.md#43-确定性与记录)、[learning 8.1](learning.md#81-时点正确)）；信号视图快照中已固定的版本由调用方直接读取，不经本查询重新解析 |
| `GetDomainStatistics` | 查询 | 预定义统计（按采购人、品类、区域、时间）；返回统计口径版本、截至时间与覆盖起点，金额按类型分别汇总、不跨类型相加。统计汇总表只维护当前值，只支持当前口径；收到当时已知口径的请求返回“历史不可用”，不以当前统计代替 |
| `ConfirmAggregation` / `RevertAggregation` | 命令 | 运营人员确认或撤销归并 |
| `GetCoverage` | 查询 | 覆盖与时效，以及各信息领域的服务状态 |

## 6. 事件

载荷唯一定义见[`contracts/events/domain/events.asyncapi.yaml`](../../../contracts/events/domain/events.asyncapi.yaml)。复用公共事件原语，稳定制品引用不含签名URL或凭据；事件正反例及引用兼容检查通过不代表生产发布/消费、事务发件箱或重放已实现。

**发布**

- 通用：`domain.fact.upserted.v1`（载荷：信息领域、对象类型、标识、版本、变化字段、权利标签）、`domain.aggregation.changed.v1`、`domain.coverage.gap_detected.v1`；
- 领域事件：由领域包定义，命名为 `<domain>.<object>.<verb>.v<n>`，例如 `tendering.result.published.v1`。

**消费**：`evidence.extraction.revised.v1`、`entity.merge.applied.v1`（实体合并后更新引用）。

## 7. 扩展点

信息领域包提供：领域 Schema 与迁移、聚合规则、状态机定义、变化检测规则（哪些字段变化构成哪种事件）、查询模板、统计定义、分析投影映射。

## 8. 伸缩与可靠性

- 写入随来源更新量线性增长；领域事实表按时间分区；
- 聚合匹配为批量与增量结合：新事实增量匹配，规则升级后批量重算；
- 事件发布通过事务性发件箱，保证事实写入与事件一致；
- 所有事实可从证据重放生成。

## 9. 安全要点

- 领域事实携带来源权利条目引用，查询接口按调用方用途和组合权利过滤（[数据架构第 12 节](../02-data-architecture.md#12-来源权利与数据权益)）；
- 公开来源中的联系人等个人业务信息按公开数据存储与返回，见 [安全与租户](../06-security-and-tenancy.md#6-个人信息)。

## 10. 项目链职责

`entity-graph`拥有跨信息领域“项目”实体与关系；本子系统提供项目链查询的组装视图。归并与撤销归并保留依据和版本，不重复拥有实体关系。

## 11. 事实撤回与恢复

本节处理[数据架构第 13 节](../02-data-architecture.md#13-来源不可用撤回与失效)中的“内容撤回”。来源暂不可达只进入覆盖度量，停止公示只标注公示状态，业务失效走生命周期，三者都不产生撤回；权利撤销按来源权利处理，由 `acquisition` 发布、`governance` 编排下线。

- **判定**：`acquisition` 的再次抓取发现原页面被发布方明确作废或替换为撤回声明时，生成新快照；解析修订识别出撤回后，本子系统产生新的事实版本，状态为已撤回。仅抓取失败或页面消失不判定为撤回，只记为待复核。
- **版本**：撤回不删除旧版本。新版本保留原有字段，追加撤回原因（发布方作废、发布方以撤回声明替换原内容）、撤回生效时间、发现时间与证据引用；“当前版本”指针移到撤回版本。
- **事件**：撤回发布独立的领域事件，载荷含事实标识、撤回后的版本号、原因、生效时间、发现时间与证据引用；下游（`entity-graph` 以 `source_withdrawn` 撤销关系边、`detection` 重新评估相关信号、`search` 更新投影）据此处理。该事件随首个撤回识别能力一起加入领域事件契约，按追加式升级小版本。
- **恢复**：发布方重新发布相同内容或撤回被证明有误时，产生新的事实版本并发布普通的 `domain.fact.upserted.v1`，新版本记录它恢复的是哪个版本；被撤回期间产生的下游变化不回滚，按恢复后的版本重新评估。
- **时间口径**：撤回版本的 `recorded_at` 是平台记录它的时间（不早于发现时间），撤回生效时间记为该版本业务有效区间的起点（[数据架构第 5 节](../02-data-architecture.md#5-时间模型)）。生效时间可以早于发现与记录时间，两者不能互相替代。恢复版本同样分别记录恢复的业务生效时间和平台记录时间；未声明生效时间的，以发现时间作为生效时间并标注为推定。
- **历史查询**：分两种口径，调用方必须指明：
  - **当时已知**：回测、仿真、漏报诊断与依据链回放（[learning 第 8.1 节](learning.md#81-时点正确)）先只取 `recorded_at` 不晚于逻辑求值时点的版本，再在其中按业务有效区间取值。例如发布方声明 10:00 起撤回、平台 12:00 才记录，回放 11:00 的判断看到的仍是原版本，原判断不被事后改写；
  - **业务有效**：问“该事实在某时点实际是否有效”时，按业务有效区间在全部已记录版本中取值，同一例子中 11:00 返回撤回版本。当前展示用这一口径，并标注撤回是后来才发现的；
  - 研究报告固定引用的版本不受影响，但展示时标注其后已被撤回或已恢复。
- **验收用例**：撤回识别启用前至少覆盖：生效早于发现与记录、在两者之间回放时，当时已知口径返回原版本、业务有效口径返回撤回版本；恢复同样覆盖生效早于记录的情形；仅抓取失败或页面消失不产生撤回版本；恢复后下游按新版本重新评估且不回滚撤回期间的变化。

## 12. 实现状况

A02 贯通验收 L1-1 交付 `fact_store` 与 A02 结果视图投影，代码位于 `data/subsystems/domain-intelligence/`：

- 消费 `evidence.extraction.revised.v1`（只在 `data-consumer` 角色），经 evidence 的 `api.Extractions` 读取修订并核对事件与修订一致；`suspect` 修订不物化；
- 领域事实按（信息领域、对象类型、来源、来源对象键、序号）确定身份，取值（去掉溯源与部分标识）变化才产生新版本；版本不可变，当前版本只能前进；补齐公共字段后按契约模型校验，不合契约时事务失败；
- 同一标包、阶段与投标人原文名称的中标结果跨版本沿用 `bdr_` 标识，信号去重键不因重新抓取或更正而变化；
- 每个新版本与 `domain.fact.upserted.v1` 同事务经发件箱发布；
- `tendering.bid_result` 投影（`domain/views.py`）按视图目录规则产生求值单位，形状与 detection 的 `api.Unit` 一致；采购项目、品类、行政区划与 `org_id` 未接入时不出现（读取为未知）。

未实现：`GetFact` 的业务有效与当时已知口径、`QueryFacts`、`GetCoverage` 与服务状态（L1-2），项目聚合与 `tendering.*` 领域事件（L1-2），生命周期、统计、撤回与恢复。
