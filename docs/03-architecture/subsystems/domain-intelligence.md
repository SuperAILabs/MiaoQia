# 领域情报子系统（domain-intelligence）

> 状态：评审中 · 版本：2.1 · 更新：2026-10-15 · 平面：数据供应

## 1. 使命

把解析结果组织为各信息领域的领域事实、生命周期和领域事件，为监测、研究和判断提供语义清晰、版本可追溯的外部事实。

## 2. 职责与非职责

**职责**

- 领域事实管理：按信息领域 Schema 物化领域事实及其版本；
- 跨记录聚合：把多条记录归并为同一领域对象（如多条公告归入同一采购项目），记录置信度与合并历史；
- 生命周期：执行领域包定义的状态机，记录状态转换与依据；
- 领域事件：检测有业务意义的变化并发布（如更正导致截止时间变化）；
- 覆盖与时效度量：按来源、区域、品类统计覆盖与延迟，发现缺口；按信息领域登记并发布服务状态（未接入 / 内测 / 已上线），供应用领域包判断启用依赖（见[可扩展性](../04-extensibility.md#4-加载版本与发布)）；
- 领域查询：按领域对象、项目链、时间范围的结构化查询；
- 领域统计：为研究工具提供聚合统计（如某采购人历年采购）。

**非职责**

- 不拥有组织、项目等共享实体（属于 `entity-graph`，本子系统只持有实体引用）；
- 不执行全文或语义检索（属于 `search`）；
- 不接触任何租户数据。

## 3. 内部组件

| 组件 | 说明 |
|---|---|
| `fact_store` | 领域事实与版本的存储与查询，按信息领域分 schema |
| `aggregator` | 跨记录聚合：确定性规则 + 候选匹配 + 人工复核接口 |
| `lifecycle_engine` | 通用状态机执行器，状态机定义由领域包提供 |
| `change_detector` | 比较领域事实版本，生成领域事件 |
| `coverage` | 覆盖率、时效、缺口检测 |
| `statistics` | 维护按采购人、品类、区域、时间等维度的统计汇总表，随领域事实增量更新 |

## 4. 拥有的数据（公共域）

- 各信息领域的领域事实表（例如 `proc.notice`、`proc.lot`、`proc.bid_result`、`invp.approval`），每个信息领域一个 schema；只保存结构化字段与证据定位符，正文与附件文本留在对象存储；
- `DomainFactVersion`：领域事实的版本链，引用产生它的解析修订；
- `AggregationLink`：记录到领域对象的归并关系、方法、置信度、状态（自动/候选/已确认/已撤销）；
- `LifecycleTransition`：状态转换、触发事实、时间；
- `CoverageMetric`。

## 5. 接口

| 接口 | 类型 | 说明 |
|---|---|---|
| `GetFact` | 查询 | 指定领域事实的当前或指定版本，含字段溯源 |
| `GetFactHistory` | 查询 | 版本历史与变化 |
| `GetProjectChain` | 查询 | 项目链：跨阶段、跨信息领域的关联对象 |
| `QueryFacts` | 查询 | 结构化条件查询（领域包注册的查询模板） |
| `GetDomainStatistics` | 查询 | 预定义统计（按采购人、品类、区域、时间） |
| `ConfirmAggregation` / `RevertAggregation` | 命令 | 运营人员确认或撤销归并 |
| `GetCoverage` | 查询 | 覆盖与时效，以及各信息领域的服务状态 |

## 6. 事件

载荷唯一定义见[`contracts/events/domain/events.asyncapi.yaml`](../../../contracts/events/domain/events.asyncapi.yaml)。复用公共事件原语，稳定制品引用不含签名URL或凭据；事件正反例及引用兼容检查通过不代表生产发布/消费、事务发件箱或重放已实现。

**发布**

- 通用：`domain.fact.upserted.v1`（载荷：信息领域、对象类型、标识、版本、变化字段、权利标签）、`domain.aggregation.changed.v1`、`domain.coverage.gap_detected.v1`；
- 领域事件：由领域包定义，命名为 `<domain>.<object>.<verb>.v<n>`，例如 `tendering.result.published.v1`。

**消费**：`evidence.extraction.revised.v1`、`entity.merge.applied.v1`（实体合并后更新引用）。

## 7. 扩展点

信息领域包提供：领域 Schema 与迁移、聚合规则、状态机定义、变化检测规则（哪些字段变化构成哪种事件）、查询模板、统计定义、分析投影映射。

## 8. 伸缩与可靠性

- 写入随来源更新量线性增长；领域事实表按时间分区；
- 聚合匹配为批量与增量结合：新事实增量匹配，规则升级后批量重算；
- 事件发布通过事务性发件箱，保证事实写入与事件一致；
- 所有事实可从证据重放生成。

## 9. 安全要点

- 领域事实携带来源权利标签，查询接口按调用方用途过滤；
- 公开来源中的联系人等个人业务信息按公开数据存储与返回，见 [安全与租户](../06-security-and-tenancy.md#6-个人信息)。

## 10. 项目链职责

`entity-graph`拥有跨信息领域“项目”实体与关系；本子系统提供项目链查询的组装视图。归并与撤销归并保留依据和版本，不重复拥有实体关系。
