# 来源采集子系统（acquisition）

> 状态：评审中 · 平面：数据供应

## 1. 使命

合法、稳定、可证明地从外部与授权来源获取原始信息，并以不可变原始制品的形式交给证据子系统。

## 2. 职责与非职责

**职责**

- 来源目录：来源注册、分类、所属信息领域、更新频率、负责人；
- 访问契约：访问方式（HTTP、浏览器渲染、开放 API、授权数据接口、文件投递）、认证方式、限速、时间窗口；
- 来源权利：采集、存储、展示、再分发、模型使用、保留期限的许可范围及依据；再分发与允许用途决定数据能否进入私有部署馈送（[部署拓扑第 10 节](../07-deployment-topology.md#10-私有部署的公共数据馈送)）；
- 调度：增量、回填、补采、按事件触发的采集计划；按第 13.1 节进行初始回填，更早历史由研究按需请求；
- 抓取执行：请求构建、渲染、重试、去重（请求指纹）、出口管理；
- 原始归档：原件字节按内容哈希写入对象存储，采集过程与来源观察登记在 PostgreSQL；
- 来源健康：成功率、延迟、结构漂移、覆盖缺口、告警。

**非职责**

- 不解析业务字段（属于 `evidence` 与领域包解析器）；
- 不感知租户的关键词或策略：采集计划只由来源特性和数据覆盖目标决定；
- 记录来源对象的原件变化。规范化内容是否产生新快照由 `evidence` 判定，更正、撤回等业务含义由 `domain-intelligence` 判定。

M0探针消费者在公共消费框架中先验证operations请求载荷，再核对来源与probe_id/subject；真实跨语言链路及非法载荷死信见[运行时验收](../../05-delivery/05-m0-runtime-acceptance.md)。其他来源采集及业务事件仍按所属里程碑实现。

## 3. 内部组件

| 组件 | 说明 |
|---|---|
| `source_registry` | 来源与访问契约、来源权利的管理 |
| `scheduler` | `acq-scheduler` 按来源声明在 PostgreSQL 登记增量和初始回填窗口；`acq-fetcher` 独立领取。按需跨窗口工作流使用 Temporal 接入计划入口 |
| `fetch_runtime` | 自研请求执行器，负责有界并发、优先级、下载中间件与重试。当前通过 HTTP 获取网页、公开 API 响应及文件；浏览器渲染接入按第 13.4 节单独验收 |
| `egress` | 出口代理与限速：按来源、域名、出口地址的令牌桶 |
| `source_handlers` | 由信息领域包提供的来源处理器：列表发现、详情获取、分页、附件 |
| `archive` | 原始制品写入、内容哈希、元数据 |
| `health` | 来源健康指标、结构漂移检测、告警 |

## 4. 拥有的数据（公共域）

| 实体 | 说明 |
|---|---|
| `Source` | 来源：标识、名称、信息领域、处理器、状态 |

| `FetchPlan` / `FetchTask` | 采集计划与任务，关联来源、栏目、窗口、触发方式与执行预算 |

| `RawArtifact` | 不可变原件。字节在对象存储，内容哈希、对象键与字节数登记在 PostgreSQL |
| `SourceObservation` | 来源对象在一次变化时所见的原件。固定来源对象标识、原件组成、请求尝试、观察时间、顺序与来源权利 |
| `SourceHealth` | 健康快照与告警 |

公共运行时只采集公共与授权数据商来源，不连接客户自己的系统。客户系统集成复用本子系统的连接器代码，以随单元部署的租户集成实例运行，见第 10 节。

采集窗口、原件提交和对下游的交接见[抓取与归档设计](#13-抓取与归档设计)。

载荷唯一定义见[`contracts/events/acquisition/events.asyncapi.yaml`](../../../contracts/events/acquisition/events.asyncapi.yaml)。复用公共事件原语，稳定制品引用不含签名URL或凭据；事件正反例及引用兼容检查通过不代表生产发布/消费、事务发件箱或重放已实现。

**发布**

| 事件 | 说明 |
|---|---|
| `acquisition.fetch.completed.v2` | 公告正文观察已归档；载荷含稳定公告键、观察序号、原件引用与哈希、来源与获取时间 |
| `acquisition.fetch.completed.v3` | 分组响应内的单公告观察已归档；载荷另含成员选择器、摘要、日期和完整响应字节数 |
| `acquisition.fetch.completed.v4` | 浏览器公告观察的原件与惰性投影均已归档；载荷含配对描述及同次导航绑定摘要 |

| `acquisition.source.rights_changed.v1` | 来源权利变化（下游据此调整可见性或下线数据） |

|---|---|

## 7. 扩展点

- **来源处理器 SPI**：由信息领域包提供。`SourceHandler` 实现 HTTP 列表、详情与附件；`BrowserSourceHandler` 使用 HTTP 列表发现，声明单次新页面导航及正文 GET，并校验原件与选中正文的对应关系；
- **连接器 SPI**（`Connector`）：新的访问方式（如某授权数据商的 API）；客户系统的连接器实现同一 SPI，只在租户集成实例中加载（第 10 节）；
- **健康规则**：领域包可提供结构漂移检测规则。

## 8. 伸缩与可靠性

- 负载特征：I/O 密集、突发；浏览器渲染为 CPU/内存密集；
- 伸缩：`fetch_runtime` 按任务队列深度水平伸缩；浏览器池独立伸缩；
- 隔离：单个来源的故障不影响其他来源（按来源的并发与熔断）；
- 幂等：分别按请求、原件和来源观察的身份处理重试，见[身份与版本](#132-身份与版本)；
- 降级：对象存储故障时在有界暂存内保留已收到的原件，Kafka 故障时由发件箱保留已提交的事件。达到预算或无法继续记录时暂停相应采集，见[提交与恢复](#135-提交与恢复)。

## 9. 安全要点

- 只访问来源权利允许的来源与路径；遵守限速与访问时间窗口；
- 不使用个人账号，不规避登录、验证码或技术保护措施；
- 访问凭证存放于密钥管理系统，运行时短期获取；
- 抓取到的内容一律视为不可信输入，不在本子系统执行任何脚本或宏；
- 出口地址与请求日志保留以备合规审查。

## 10. 租户集成

客户自己的系统（CRM、项目管理、ERP、文件投递目录等）按以下分工接入，不新增子系统：

| 环节 | 所有者 | 内容 |
|---|---|---|
| 凭证 | 租户管理员授权（`identity` 的 `can_manage_credentials`，强认证），密钥存于所在单元的密钥管理，数据库只存引用 | OAuth 授权或 API 密钥、作用域、轮换与吊销；吊销后连接立即停止 |
| 连接生命周期与增量同步 | `acquisition` 的租户集成实例（随单元部署，使用单元级凭证、存储与出口，不与公共实例混用） | 连接状态与健康、同步游标、限速与重试、按外部记录标识幂等、外部删除转为“已删除”标记；原始记录写入租户隔离存储，只发布单元内的租户主题事件 |
| 业务映射 | 使用这份数据的业务所有者 | `pursuit`：CRM 商机与推进的映射（`ExternalLink`）及字段归属；`customer-context`：客户、产品、资质与业绩的导入；`evidence` 租户实例：客户文档。映射规则、冲突处理与回写内容由所有者决定，回写只发往该租户已连接的系统并留审计 |
| 通讯录与成员同步 | `identity` | 企业目录、SSO 与成员同步属于身份数据，由 `directory` 直接对接，不经租户集成实例 |

公共采集计划不受租户关键词或业务策略影响；当前权利只读入口仍须核验调用用户、tenant/cell 和 purpose。租户集成实例只运行租户的连接，不读取公共来源计划，也不把租户数据写入公共存储或公共事件。本子系统的 `tenant` 数据域与单元级角色在首个租户集成启用时登记（[子系统索引第 4 节](README.md#4-运行实例的数据域)、[部署拓扑](../07-deployment-topology.md#5-租户单元)）。

## 11. 开放问题

1. 授权数据供应商的选型与接入方式；
2. 每个来源的启用验收与来源跟踪；数据负责人决定启用，特殊来源由法务个案处理，来源变更按治理流程下线。

历史回填仅承诺已登记来源的可访问范围；按任务配置并发、请求范围、时长与费用上限，在线增量优先。来源无法提供、超限或超时返回覆盖缺口，研究使用部分证据并标注未知，不制造完整历史。

## 12. 当前实现边界

公开来源和冻结语料的当前权利由独立 PostgreSQL 登记及 acq-admin mTLS 端口提供。公开来源撤权或恢复时，专用操作命令在同一事务更新权利、写入审计并发布 `acquisition.source.rights_changed.v1` 发件箱记录。站点运行阻断单独记账，仍可按当前权利使用已归档原件。[当前权利与审计](source-rights-runtime.md)

来源目录与各站处理器由采购包维护。运行时只启动 `admission: active` 且通过声明检查的来源。首批目录含 40 个条目。准入按已验收的栏目和制品范围配置。附件路径独立记录，字段质量使用 evidence 的独立解析准入。以 `mq-acquisition-fetch --list-sources --packs packs` 查看现行分布，配置 acquisition DSN 可合并最近增量轮次、运行阻断、覆盖缺口和回填游标。来源当前返回的实际内容和生产覆盖需要逐源观测。[来源目录](../../../packs/information_domains/procurement/source-inventory.yaml) · [逐源验收](../../05-delivery/12-public-source-probe.md) · [解析准入与回放](evidence.md#12-实现状况)

工程验收在获准的运行环境使用 `mq-acquisition-fetch --validate-source <来源> --channel <栏目> --packs packs`。该模式允许显式验证有 HTTP 声明的公开来源（含 `staged`），逐页报告请求指纹、新发现项、稳定键和正文响应哈希。浏览器来源需要专用角色。默认最多两页、一条正文。指定多个正文样本时，单份结构不符会保留为失败，同时继续检查其余样本。访问拒绝、验证码或 429 会立即结束本站探测。JSON 报告记录本轮样本，不落库、不归档、不发布、不改变来源准入状态。首次验收按实际支持的栏目、时段、附件和字段质量补齐证据。[验证入口](../../../data/runtimes/acquisition/src/miaoqia/runtime_acquisition/fetch.py)

运行方可对已确认恢复的 HTTP 来源执行 `mq-acquisition-fetch --source <来源> --since <日期> --until <同一日期> --max-pages <预算>`。该日的列表与必要原件均确认完整时，手工轮次结清对应初始回填日期。原有的范围和失败记录保留在轮次历史中。若旧账本游标已清空而逐日覆盖仍显示列表完整、必需原件缺失，按该来源及日期重跑同一命令，再核对该日的原件状态和观察版本。

共享 PostgreSQL 下载槽协调全局、站点和来源预算。429 在站点级登记冷却。轮次以窗口和租约代次续跑，过时执行者不能覆盖当前观察。每个 `acq-fetcher` 有三个在线执行线程，其中一个优先接管或补做未结窗口。同一来源先领取当前日期的新增量窗口。恢复沿用原轮次、窗口和页数上限。`--list-sources` 展示下次计划水位、在线和历史待执行计划数、全部未结增量轮次数及最多 32 个原轮次标识。

每个 `acq-fetcher` 有一个历史执行线程。增量和历史计划的单次预算分别按来源周期的 80% 和 20% 设置。初始回填先按日扫描预定日期，已尝试但未完成的日期留在缺口队列，首次扫描结束后按最久未重试的日期重试。有限首页、滚动归档末页、验证码分页边界，以及无法按成员日期查询的分组列表，属于已观察的来源边界。仅遇到这些边界时，缺口保留并等待采集契约指纹变更，在线增量仍按计划执行。分组列表到达本轮页数上限且无法证明窗口边界时按同一规则等待。网络、归档和其他单独的页数预算缺口沿用重试队列。调度用原窗口计划的指纹识别已经观察的边界。轮次报告、计划结算、扫描进度、缺口和来源租约释放在同一 PostgreSQL 事务提交。`initial_backfill_pending` 是下一处尚待首次扫描的日期，`initial_backfill_gaps` 列出仍待补齐的日期与轮次，含该次观察是否因可见范围等待后续契约。结清某日之前，在同一事务用覆盖报告的收据规则核对每个栏目。尚不能证明列表范围及必需原件时，保留该日缺口。两个字段均清空才表示初始回填已结清。来源阻断时暂停该来源。列表记录和请求尝试分开持久化，列表响应默认保留 30 天，正文按 SHA-256 归档。正文或附件可用状态变化形成新观察，缺失附件可通过后续复查补齐。同一稳定公告键的 HTTP 正文原字节不变时，后续核实的发布日期补齐或更正也追加一版观察，复用原件并保留原观察。新列表缺失日期时，同一原件已核实的日期继续有效，列表当日覆盖仍按该次发现收据判定。

`runtime.historical_coverage` 按日和栏目展示最新的单日历史回填或历史手动轮次，含轮次 ID、结算标志、列表覆盖、必需原件状态和列表收据。每个来源最多展示 32 个日期，每条展示完整的收据数量和最多 50 个收据尝试 ID。指定 `--list-sources --since 日期 --until 日期` 时，按指定区间核对已有运行状态的来源。无轮次的日期和栏目显示 `unknown`，该行无轮次 ID。缺少运行状态的来源仍显示 `runtime: null`。

列表状态 `complete` 与 `proven_empty` 均要求可核对的终点和收据。范围已证实且窗口内发现为零时报告 `proven_empty`。缺少终点时报告 `incomplete`，旧轮次及证据不足时报告 `unknown`。单日回填出现无法确定发布日期的列表行时保留覆盖缺口，仍可归档通过校验的原件。必需原件状态可为 `archived`、`missing`、`not_required` 或 `unknown`，反映当前已提交观察和必需附件账本。补扫只有在对应公告日期和附件清单已有可核实的归档记录时才可略过正文。分组成员仅登记为旧任务时，保留当日原件待复查。对象字节回读和恢复通过冻结与恢复入口验收。原有回填游标和缺口列继续决定补扫计划。

采集和证据共用文件系统或 S3 兼容原件存储。列表、正文和附件请求登记为持久化任务，每次 HTTP 实发记录与原任务关联。启用私有暂存目录后，HTTP 运行时在发包前预留本机配额，边接收边写入并计算 SHA-256。完整响应关联已登记的尝试后可恢复，随后由各来源处理器校验。挑战页、截断响应及结构校验失败的内容不会进入正式归档。对象存储故障或元数据回滚后，续跑复用原轮次和尝试编号，重新核对当前来源权利与响应校验要求，确认最终对象的字节后再提交 PostgreSQL 与发件箱。复用先前的列表页可以补齐该页的归档和正文，覆盖继续标记为待重新扫描。暂存盘丢失或过期时重取，使用新请求的实际字节记录结果。`--list-sources` 显示最新增量轮次的待恢复报告和任务状态计数。单条请求由持有源租约的窗口执行。目标环境的多副本、连接峰值和实际恢复仍待验收。[抓取执行](../../../data/subsystems/acquisition/src/miaoqia/acquisition/application/fetch.py)

`mq-acquisition-frozen-batches` 的 v1 清单支持固定、验证、读取及按原哈希恢复单公告正文或可用附件。测试服务在受控数据环境以 `read --manifest batch.json --index 0` 读取固定原件。命令核对目录绑定、当前授权及字节哈希，成功时标准输出为原件字节，错误单独写入标准错误。部署端以受信回调决定选取、读取与恢复权限。冻结、读取和验证以只读方式打开归档。恢复时只读备份并对目标执行条件写入。文件系统的只读入口保留目录缺失状态；目标已有正确原件时，恢复返回 `already_present`，缺少所需备份时返回 `backup_missing`。独立 S3 备份可使用另一端点及只读身份，部署配置见[恢复手册](../../../deploy/vps/data-plane/recovery.md#2-在空目标恢复)。

分组公告使用 `freeze-records --selection selection.json` 生成 v2 清单。每项固定来源、公告键、版本、原件哈希、选择器、成员摘要和公告日期。`read-record --manifest records.json --index 0` 按目录与原件校验后重验成员绑定，输出单公告 HTML 及固定引用组成的 JSON。该 HTML 仅作为测试解析输入。完整组响应留在原件存储，由归档权限持有者校验及恢复。两个分组命令均装配可信的调用者、用途及当前授权回调，并在取数前和返回前核验。部署使用 `MIAOQIA_ACQUISITION_FROZEN_RECORD_ACCESS` 及受信 `MIAOQIA_PACKS_DIR`。[冻结批次入口](../../../data/runtimes/acquisition/src/miaoqia/runtime_acquisition/frozen_batches.py)

**部署侧测试供数。** 运维可为每个测试服务装配独立的只读供数进程。进程以受信启动配置指定 `MIAOQIA_ACQUISITION_FROZEN_READ_POLICY`，指向运维维护的权限文件。文件字段为 `schema_version: 1`、`service`、`expires_at` 和 `batch`。其中 `service` 为该测试服务的标识，`expires_at` 为带时区的到期时间，`batch` 为已审核的 v1 或 v2 清单。测试请求提供批次和条目编号，进程在授权前后重新读取权限文件，核对固定条目、服务身份、当前数据库时钟及来源撤权。运维更新文件时使用原子替换。正文与可用附件沿 v1 读取，分组原件沿 v2 返回公告投影。冻结和恢复继续由受信运维回调授权。

使用 `mq-source-rights grant-frozen-reader --reader <role>` 为既有独立账号装配目录读权限。供数进程持有只读目录 DSN、独立权利读取 DSN 与原件对象读凭证。测试服务从受控进程取得输出，由部署边界保障测试请求无法改写供数进程的启动配置、权限文件或凭证。该装配面向数据环境内的测试用途。真实测试服务的权限文件与运行身份由部署方签发。

分组原件恢复由归档运维执行 `restore-record-original --manifest records.json --index 0`。运维回调单独授权该操作，并判定完整组原件的恢复权限。命令以 v2 清单核对归档目录和备份字节，按原哈希恢复对象，只输出状态。恢复过程可在尚未启用解析时执行。

## 13. 抓取与归档设计

从数据负责人启用的公开来源出发，每轮交付可追溯的**覆盖记录、已校验原件、不可变来源观察**。首批用 HTTP 获取官方列表与公告正文，声明附件处理范围，按 [D1b 逐源验收](../../05-delivery/11-d1b-anhui-pilot-sources.md)启用。来源专用参数由包声明，运行时负责预算、状态、持久化和事件。采集执行采用妙洽自研运行时，选择性实现 Scrapy 的有界并发、下载中间件、重试和优先级机制。每个来源声明绑定一种来源处理器 SPI。

### 13.1 来源启用与轮次

包的来源声明支持 `transport: http`（缺省）和 `transport: browser`。调度器从同一目录登记公开且通过能力验收的 `active` 来源，HTTP 执行角色只领取 HTTP 来源的计划。`staged` 声明保留在目录中。浏览器处理器声明正整数 `contract_version`，运行指纹包含该版本及传输类型。浏览器来源为发现阶段声明 HTTP 列表或新页面渲染列表，正文使用单条新页面导航。分组、定位和附件需要各自的采集契约。

1. **登记与激活。** 来源定义包含来源与共同平台标识、启用的栏目、稳定对象键和部件键、允许访问的站点与路径、请求方式、时区与排序保证、分页方式、详情成功判定、必要部件、访问预算和归档范围。新声明先用录制响应验分页及结构，再由数据负责人确认启用。运行轮次固定处理器、访问契约和当时的权利依据，实际请求及归档还须符合当前限制。
2. **计划先落库。** 调度以来源、栏目与时间窗口确定轮次，保存触发方式（增量、回填、补采或指定对象复查）、起止时间及边界口径、预算和当前进度。首批实网按[阶段基线](../../05-delivery/06-stage-baseline.md#11-当前主线)逐源启用。开始增量后按来源可访问范围回填，默认最近 30 天，允许逐源配置。手工、定时和重试共用执行器。重启沿原任务续跑，重叠窗口按来源对象键合并。回填与补采占用同一来源的限速预算，在线增量优先。受阻来源记录覆盖缺口并单独暂停。
3. **先确认发现，再推进分页。** 每个被接受的列表页先登记查询范围、页号或游标、返回边界、原始制品引用（如允许保留），将发现的公告及尚未获取的部件任务与页进度同一事务提交。返回明确页码的处理器通过 `ListPage.reported_page` 交给验收和采集共用的请求范围检验。页码须与请求一致，按日期筛选的来源还须核对公告日期落在请求窗口。验收和运行共用同一分页检查，按栏目和窗口核对重复与部分重叠，检测声明发布日期排序的来源发生页内或跨页倒序。发生倒序后继续按预算扫描，保留已取得的原件及覆盖缺口。只有已验证排序的来源且本轮未发现排序异常时，旧日期才可作为结束证据。使用源站保证稳定的游标或已冻结的分页视图续跑。页号随新公告插入移动时，从重叠窗口重新发现。

返回总数和记录的偏移接口将站点总数、固定页长和当前原始行数交给 `ListPage` 的共用校验，由验收与采集按请求页判断是否还有下一页。可核对的响应页号由 `reported_page` 表示。处理器可声明已验证的公开末页，到达末页且站点仍报告后续记录时留下覆盖缺口。跨页重复或总数变动同样留下覆盖缺口。

有序列表能证明已经越过请求日期下界时，本轮窗口可以在公开末页正确结算。到达受限末页而仍无法证明日期下界时，登记该来源的历史覆盖边界。

来源公开接口若先按公告键返回正文地址，处理器声明定位请求并校验响应中的定位关系。定位和正文共用来源预算和同源约束。定位尝试留在审计中，正文通过原站键与内容校验后进入原件归档。定位失败、拒绝、验证码或返回站外地址时不发正文请求。

正文校验需要列表身份或字段时，来源处理器可声明 `check_detail_with_ref(ref, response)`。验收和采集均通过同一入口调用。详情日期与已记录的列表日期冲突时拒收。来源规则可在证据足够时沿用已校验列表日期，正文原件保留原字节，列表收据保留发现记录。验证工具遇单份详情网络故障或瞬态 HTTP 错误时记录缺口并继续抽样，来源拒绝或限流时停止。

公开列表若要求查询预检，来源处理器声明同源的预检请求、响应判定和后续列表请求。两步沿用同一访问预算，预检拒绝或内容不明时停止该来源窗口。预检尝试进入采集审计。列表任务以栏目、日期、页和查询语义固定，原站要求的临时时间参数记录于实际请求指纹。恢复已取得的列表响应仍须核对任务、尝试和响应绑定，重新发出列表前需要执行当次预检。
4. **分别结算发现和获取。** 达到稳定列表末页且页记录均已提交，才标记扫描完成。完成扫描且范围内所有必要原件均可校验，才标记该窗口获取完整。确认空列表可标明无记录。页数、时间上限、页重复、异常空页、未取得的必要部件及权限阻断分别记录缺口。连续覆盖截至时间只跨过已完整或已确认空的区间，最新轮次可以继续向前运行。这个状态描述登记范围内的实际扫描，覆盖率仍靠独立参照集度量。

**正文发布日期。** 来源处理器可在正文身份校验通过时返回原站发布时间对应的完整日期。采集与验证器共用该校验。列表已提供完整日期时，两者须一致；列表只有月日时，采集在归档前使用经校验的正文日期与请求窗口核对。窗口外正文请求仍留审计。日期和历史边界不明的列表继续报告覆盖缺口，有限公开页的重复回填可等待来源契约更新。

#### 按组发现公告

原站若先列项目或标段，再在同一详情响应返回多条公告，处理器声明独立的组发现项和同源展开请求。组键用于请求、审计和恢复。校验回显组身份、成员唯一性及正文后，按成员的原站公告键和发布日期分别登记公告。用真实成员日期过滤请求窗口；组日期用于诊断。组列表分页与组内公告完整性分别结算。超限、截断、重复键、归属冲突或缺少可信历史边界保留缺口。湖南标段接口属于该模式。[实网证据](../../05-delivery/12-public-source-probe.md#湖南工程公告复验)

展开请求由现有来源租约、限频、请求任务和暂存管理。分组来源启用调度前需具备展开、请求重建和成员投影方法。完成一次有效抓取后，登记该次组尝试及完整响应哈希和字节数。一份完整的原站响应可以支持多个公告观察。每个公告用版本化选择器绑定允许的组及成员，并以该成员的公告日期、标题、类型、正文和已声明语义字段计算变更摘要。相邻成员变化、排序及外层信封变化只影响原件字节和抓取审计。每个公告的摘要与其最近已接受摘要比较，决定是否新增观察。组收据、观察、发件箱和请求结算在同一租约下原子提交，续跑校验并复用同一尝试。已绑定分组的公告拒绝无组绑定的正文推进；已关联到旧原件的公告保持现有观察流，交付方式变更需另作迁移校验。缺项不等于原站撤回。

`--validate-source` 已支持按组探测。`--max-details` 限制原件响应数，单份响应内报告有效成员总数，并列出请求日期范围内的公告键、日期和成员摘要。探测在内存中处理，按组原件的哈希单独报告。

分组观察事件 `acquisition.fetch.completed.v3` 携带成员选择器、摘要、发布日期和完整原件引用。隔离 PostgreSQL 和 S3 兼容存储已验证分组归档、同轮次接管和原字节复用。湖南实网样本已由采集运行时取得并交给 evidence 待解析队列，在隔离环境获准后从原件重放。运行配置启用已验证的两页公开标段范围，历史日期边界继续记为缺口。部署先升级 evidence 消费者及事件验证，再启动分组生产者。目标环境持续运行、历史窗口覆盖和正式字段质量需分别验收。

### 13.2 身份与版本

| 记录 | 身份与持久化边界 |
|---|---|
| 请求与尝试 | 请求指纹用于合并等价请求，按来源区分。会改变响应的变体由来源显式声明。一次实际发出的请求拥有独立尝试 ID。记录方法、脱敏目标、请求摘要、结果、重定向状态、时间、耗时及关联任务。认证值、Cookie、签名参数和完整响应头不进入请求记录或日志。附件制品的下载定位只保留路径，签名链接若出现在原始响应中，随原始字节保存于受访问约束的对象存储。 |
| 来源对象及部件 | 公告按来源 ID 与处理器定义的稳定字段组合标识。`DetailRef.source_key` 表示来源内的组合键，`DetailFetch.artifact_key` 标识正文或附件部件。展示 URL 用于定位。跨栏目复用同一可靠公告键，跨来源按各自权利保留记录。可靠标识一致的存量自动关联并保留原证据引用。身份缺失或冲突的公告可归档并标为待核对，暂缓归并和自动匹配。 |
| 原始制品 | 在允许共用的存储隔离范围内使用 `raw/<sha256>`。哈希标识已接收的原始字节，用于完整性验证及物理去重。媒体类型、来源、抓取时间、权利和保留理由由引用它的记录说明。哈希本身不能证明公告身份、版本或权限。 |
| 来源观察 | 首次取得正文、正文变化或已承诺的部件组成变化时，追加来源观察并分配对象内的顺序。观察包含正文与部件引用、各部件取得状态、首次见到本变化的时间、发布方声明时间（若有）、关联发现页和请求尝试、权利依据。重投同一任务提交复用其结果。连续接收到相同内容只更新复查状态，`A → B → A` 形成三次变化观察并复用两个原件。 |

同一来源对象在任一时点只允许一个活跃的观察提交。调度和接管通过任务租约及其代次核验提交资格。接管后返回的旧任务结果仍可记录请求结果，当前指针不由旧任务推进。来源列表短暂缺项、部件下载失败、正文响应 `404` 或请求超时只更新采集状态。发布方明确撤回或更正的响应作为原件记录，由下游判定业务含义。

### 13.3 请求执行与复查

**窗口派发。** `acq-scheduler` 用一个周期任务写入逐源调度水位与到期窗口计划，两者同事务生效。计划固定来源、触发键、日期窗口、采集契约指纹和预算。指纹包含处理器入口、栏目、日期窗能力、访问配置及已声明的处理器 `contract_version`。分组来源还固定回填页数上限，扩大范围时可重新尝试历史缺口。处理器变更请求、身份或校验规则时递增该版本，以便历史缺口和未结窗口按当前规则重跑。同一自然日的积压计划可合并，跨日仍登记历史日期。`acq-fetcher` 用固定并行度在短事务内锁定来源、领取窗口、绑定原有或新建轮次并提交租约。同一契约下，过期轮次用同一编号和新代次接管。来源受阻或权利变更时，仅暂停该来源的领取和出站。待发列表、分组展开、正文和附件继续使用各自的持久请求任务和共享下载槽。按需跨窗口的 Temporal 流程接线待验收。[窗口计划与领取](../../../data/subsystems/acquisition/src/miaoqia/acquisition/application/plans.py) · [执行角色](../../../data/subsystems/acquisition/src/miaoqia/acquisition/application/dispatch.py)

契约切换在来源租约结算或过期后生效。调度将旧未结计划及中断轮次标记为 `source_contract_changed`，保留审计和已取得的原件，沿用日期窗口、到期时间和重试时间，以当前页数及执行预算创建计划。新轮次从当前处理器重新发现，已归档公告按来源键和版本规则复用。旧轮次的暂存响应只属于原轮次。部署时两个角色采用同一契约快照。[发布与回退](../07-deployment-topology.md#21-acquisition-单元)

| 机制 | 妙洽实现规则 |
|---|---|
| 有界并发 | 借鉴下载槽，发出请求前同时满足全局、来源和站点的在途上限及最短发包间隔。同一来源默认串行，多个来源可以并发，共用站点预算的来源合并计量。限流等待与重试退避释放下载槽。暂存或归档积压达到上限时暂停新下载。多个执行进程按相同站点预算协调派发，扩容时总预算保持原口径。 |
| 下载中间件 | 用小型、固定顺序的处理链复用现有请求校验、来源访问策略、限速、传输、错误分类和尝试记录。每个出站请求及重定向各跳都经过目标校验和预算检查。来源处理器按契约构造请求与判定内容，原始字节按第 13.4 节的口径交归档。中间件没有推进来源观察、窗口或发件箱的权限。 |
| 重试 | 对声明为幂等读取的请求，在网络错误、超时及来源允许的暂态 5xx 上有限重试。429 按来源限流规则与有效的 `Retry-After` 推迟该预算范围内的请求。重试在原任务下登记新尝试，按退避时间重新入队并重新获取下载槽。退避超出本轮时限时保留待执行时间和覆盖缺口。验证码、登录要求、401/403 进入阻断并由操作员核查。结构校验失败、站点空壳及其他明确失败按原因记录，交对应处置。 |
| 优先级 | 只在已获准且已到可执行时间的任务中选取。在线增量和阻断当前窗口的必需补采优先，定向复查次之，历史回填使用单独的执行预算。同类任务按进入队列顺序处理。明确可用的回填份额避免持续增量使历史任务饿死。优先级始终受来源限速、冷却、截止时间及全局预算约束。 |

HTTPS 握手报 `BAD_ECPOINT` 且尚未发出 HTTP 请求时，传输层可在同一截止时间内用 P-256 重试一次握手，继续校验服务器证书及主机名。证书校验失败和旧式重协商错误按原错误报告。

实现参考 [Scrapy 下载槽](https://docs.scrapy.org/en/latest/topics/autothrottle.html)、[下载中间件](https://docs.scrapy.org/en/latest/topics/downloader-middleware.html)、[重试](https://docs.scrapy.org/en/latest/topics/downloader-middleware.html#retrymiddleware)和[调度顺序](https://docs.scrapy.org/en/latest/topics/scheduler.html)，按妙洽的任务、状态和接口编写。复用具体上游代码片段时记录来源版本，并保留 [Scrapy BSD-3-Clause 许可要求](https://github.com/scrapy/scrapy/blob/master/LICENSE)中的版权、许可与免责声明。

**复查与部件。**
- **复查触发。** 首次发现、可信修改标记、补采任务或周期性复查预算可以触发请求。按来源配置已知更正机制和回看周期。对确实提供且验证过语义的 ETag 或修改时间使用条件请求。`304` 仅引用同一来源对象与请求变体下可读、校验有效的已有制品；找不到原件时作为缺口执行有界完整重取。无条件请求能力时按复查预算取正文，并与最近一次已接受原件比较。
- **部件。** 来源处理器区分正文、必需附件和可选附件。附件候选只能来自该公告已验证的正文 DOM 容器，或详情接口中属于该公告的正文或附件专用字段。容器缺失或不唯一时停止提取，验收须包含带有效下载路径的页眉、导航、侧栏或页脚链接，并确认这些链接未进入附件清单。已验证的正文可声明同源附件，或指向来源访问契约列明的独立 HTTPS 附件端点。附件请求固定在处理器核对的路径，按实际站点使用共享预算，禁止重定向，跨站点请求不携带列表和正文的默认请求头。正文保存成功就保留原件，必需附件缺失时标记观察不完整并保留补采任务。后续取得新部件追加观察，历史观察中的缺失状态保留。临时错误保留历史部件并标注本轮未核实。正文变化时，旧部件只有经来源清单或重新校验确认仍属于该版正文，才可纳入新观察。源站明确移除部件时才记录移除，并保存相应依据。

### 13.4 归档范围与字节定义

| 输入 | 对象存储 | PostgreSQL |
|---|---|---|
| 通过校验的列表页 | 获准归档的响应正文默认保留 30 天。独立验收或故障样本按获准范围留存。 | 扫描范围、脱敏请求与指纹、发现键与日期、结束依据、部件任务、响应哈希、制品引用或不可保留原因。 |
| 正文、附件、允许保留的文件 | 原样保存响应体或文件字节，受来源及制品保留策略控制。 | 内容哈希、字节数、对象键、观察、原件角色、媒体类型、允许保留的内容编码、请求与来源上下文。 |
| 失败或无新字节 | `304` 复用已有引用。挑战页、鉴权响应、截断或超限内容默认不进入正式归档。 | 有界的失败类别、状态码、时间和后续处理；禁止把不完整字节登记为成功制品。 |

HTTP 原件以移除传输分帧后的响应体字节为准，保留内容编码层。字节在字符解码、JSON 变换、HTML 提取和浏览器渲染前求哈希。来源有独立文件交付时，以完整文件字节为准。下载期间按来源与部件限制大小和时间，超限终止。对象存储对相同键禁止覆盖不同内容，不能以 ETag 代替 SHA-256。列表响应到期后保留发现记录与哈希。公告正文和附件按来源权利长期保留。清理时核对有效引用、保留约束、暂存与恢复窗口；强制物理隔离或单独删除的来源使用独立存储范围。[数据保留与删除](../02-data-architecture.md#10-数据保留与删除)

**浏览器来源接入。** 原站有可独立使用的公开 HTTP 正文时沿用现有处理器。需要渲染的公开页面由来源处理器声明正常导航路径、正文请求及唯一正文容器。四川政府采购首页和重庆政府采购两个入口均有匿名浏览器的样本证据，部署准入逐入口验证。公告原站键按字符串保存。经跨入口、跨时样本验证后，同一发布身份域的入口共享公告流，发现记录各自保留栏目与分页。

渲染任务使用独立、短时且无业务凭证的浏览器上下文。受控出口对导航、资源、跳转与新窗口逐请求核验实际连接目的、来源限速和当前访问约束。任务遇到登录、验证码、访问拒绝或限流按该来源状态结算。采集运行时负责调度、任务尝试、租约、权利与归档；浏览器仅返回获准任务内的捕获产物。

浏览器适配器从部署方取得已隔离的新页面和受信目的地址。在导航前安装逐请求门禁，按来源计划许可主文档及正文请求。每次请求完成或取消后归还下载槽。正文选择器由来源代码声明，必须在当前主框架命中唯一可见正文，再由来源处理器核对公告键、原件及渲染内容。

一次成功观察须同时固定同次正文请求的原始响应和该公告的惰性文档投影，并保存两份哈希、字节数、媒体类型、投影版本，以及任务、实际请求、导航与公告键的绑定。若捕获接口只能取得已解码的压缩响应，需另有可复核的同次原件捕获才可准入。用正文键、实际请求与唯一正文验证配对，两个对象均可回读后才提交观察与发件箱。离线重放校验两份对象与绑定；面向下游的数据来自选中公告的惰性投影。无法复核精确字节或配对时记录来源缺口。重庆政府采购两个入口和四川政府采购首页保持候选，等待该路径的独立验收。[浏览器探测记录](../../05-delivery/12-public-source-probe.md#重庆政府采购两个入口复查)

隔离 Chromium 回环夹具已核对同次二进制响应。无内容压缩的响应在去除 HTTP 传输分帧后可逐字节一致，文本版响应接口可能转换字符编码。压缩响应的浏览器流是解码后的字节。浏览器接入只接受实际响应内容编码缺省或明确为 `identity`，原件和选中内容必须来自同一次已验证导航。声明长度不超过 64 KiB 的数据响应在响应阶段暂停并取得明确标识为二进制的 Base64 字节，随后原样继续浏览器处理，以覆盖快速响应在流式监听建立前已完成的情况。其他响应使用同次二进制响应流，无法取得精确字节时登记缺口。底层捕获在导航前监听，核对同一个网络请求、主框架、导航、实际连接、标头和完成状态，对缓存、服务工作器、重定向、响应失败、截断及超限均拒绝封存。目标站点、部署出口与结果规模需独立验证。[四川样本](../../05-delivery/12-public-source-probe.md#四川政府采购两入口)

浏览器观察沿用 `(source_id, notice_key, version)`。原件存入 `raw/<sha256>`，惰性投影存入 `projection/<sha256>`。投影是版本化的 UTF-8 JSON 文档，保留标题、正文块和表格，供 evidence 生成规范化文档。收据将两份对象的摘要、大小、媒体类型和投影版本绑定到列表发现、公告键、采集任务、尝试、脱敏的实际请求及同次主框架导航。收据不保存 Cookie、签名、请求头或浏览器状态。同次完整捕获可原子写入配额受限的本地暂存，接管进程按已登记的任务检查点取回两个部件。两份对象回读通过后，在同一事务结算任务、追加观察、登记收据及发布 `acquisition.fetch.completed.v4`。同一原件和投影重复取得只记录复查，原件或投影变化追加版本。相同摘要的历史对象可复用。

Evidence 验证成对引用和收据后读取投影，原件引用继续用于来源追溯。解析准入继续按来源和类型单独配置。离线重放和浏览器冻结批次均固定同一观察的两份对象，任一缺失或不匹配时失败。供数只交付获准的对象角色，原件与投影恢复分别按权限核对精确备份。浏览器观察不进入单公告原件批次或分组选择批次。

公共测试 VPS 的隔离 `acq-browser` 角色使用受监督 Chromium 领取合成浏览器计划，分别核对 PostgreSQL 列表绑定和 30 天到期登记、SeaweedFS 列表原件及正文和投影回读、事务内 V4。同次捕获的 V4 经 Go 发件箱中继和 Kafka 交付。Evidence 在暂停解析时持久化该观察，再独立验收从同一归档的重放。浏览器控制器沿用同一窗口、发现账本、下载预算和原件恢复路径。当前捕获只接受新页面的一次主框架导航。出口夹具已验证合成 HTTPS 固定对端和控制器退出后的内核撤销。真实发布者启用依赖常驻受控渲染器、逐请求出站权限及逐源验证，完整出口约束仍待验收。[发布与出口验收](../07-deployment-topology.md#21-acquisition-单元) · [交付收据](../../../deploy/vps/data-plane/browser/receipt-provider-ingest.jsonl)

**浏览器列表发现契约。** 处理器可为栏目、窗口与页码声明一次匿名 HTTPS 主框架导航、一条独立的同源列表 GET 与一个唯一可见的列表容器。每页由新的隔离页面执行。运行时在导航前登记逻辑列表任务，主文档和列表请求分别计入同一来源的请求预算。处理器核对同一主框架、同一次导航的列表响应及可见容器，返回带原站公告键与发布日期的发现记录，并以发布者提供的页码或分页元数据核对请求。发现记录的详情定位须在该来源的同源范围内。只显示应用壳、页面加载失败、验证码或拒绝访问均不能证明空窗。仅验证首页可见范围的来源须报告历史与分页缺口。

收据将列表响应摘要、大小、媒体类型及同次网络请求和导航标识绑定到该页的任务与成功尝试。响应原件通过回读后按来源约定保留 30 天。来源允许归档时，存储中断可从有配额的本地暂存取回该次完整原件和列表容器。可见 HTML 只作为校验和恢复的暂存输入，持久账本保留已校验的发现记录与绑定。登记、任务结算和覆盖推进复用现有列表路径。接管过程中使用暂存的列表时仍记录重新扫描所需的覆盖缺口。列表证据不产生公告采集事件，正文另行固定与验收。

采集进程的版本回退保留兼容的数据库结构，旧版本可继续领取其支持的来源。迁移不提供降级，需要恢复旧结构时使用已校验的升级前检查点，受影响的观察和覆盖按第 13.5 节复核。

首个列表实现仅许可主文档与同源列表请求。发布者页面额外依赖的资源、页面内点击翻页、弹窗、新框架、POST 及同址多次响应须另行验证执行路径与捕获契约。重庆、四川与江西政府采购候选入口的普通浏览器观察用于核对发布者差异，接入还需受控出口、来源准入及逐入口归档证据。[来源复查](../../05-delivery/12-public-source-probe.md#重庆政府采购两个入口复查)

### 13.5 提交与恢复

1. **接收。** 记录任务和尝试后才发请求。完整响应在受保护、有配额的本地暂存中流式写入并校验哈希。完整字节与恢复所需的最小元数据经原子发布为可恢复暂存项。下载过程中退出的临时文件不作为制品，任务带着未完成状态重试。
2. **持久化。** 把原件写入最终存储，校验对象键、字节数与 SHA-256。同一哈希对象已就绪时复用。对象存储不可写时保留可恢复暂存项，达到配额或超过允许期限时停止接收并记录覆盖缺口。暂存所在主机丢失时，未取得持久化确认的任务恢复为待补采，不能声称原件已保全。
3. **登记与发布。** 对象已可读且校验通过后，在 acquisition 数据库一次提交原件登记、尝试结果、来源观察、需要推进的任务或页状态和发件箱。列表页只推进发现与部件任务；公告及可供处理的部件通过获取事件交给 evidence。数据库未确认提交时保留暂存，重试先按任务与尝试标识核对提交结果。已写对象无已确认引用时由对账处理，不在请求异常时直接删除。
4. **异步交接。** 数据库提交后清理暂存，Kafka 中断由发件箱中继重试。持续积压到达预算时暂停新任务。消费者凭已提交的观察与原件引用读取和验证，重投同一观察不重复物化，迟到观察不覆盖更新状态。对象缺失或损坏时明确报错并发起补采，恢复原件优先从备份还原原哈希；重抓得到不同字节时只追加新观察。

### 13.6 下游契约

`evidence` 接收可核验的来源对象及观察引用、对象内顺序、正文与部件引用及取得状态、观察时间和来源权利。它读取原件、核验哈希，再决定规范化快照是否变化。附件缺失时，正文有证据并通过校验的字段可先读，依赖附件的信息保持未知。补采成功后按新观察追加版本。列表记录用于证明发现及覆盖，发现不触发业务事实发布。内容变化的观察可迟于发布发生，业务有效时间保持独立。

采集与解析按来源和公告类型分别验收。获准的已归档原件可用于测试文档池。测试服务使用固定批次清单，按来源、公告类型和日期范围选取，清单保存来源对象标识、版本、原件引用与 SHA-256，原件留在受控存储中按授权读取。字段以独立样本与证据门槛通过后供上层使用。[数据质量计划](../../05-delivery/04-data-quality-organization.md#12-评估集)

浏览器冻结使用 v3 清单。授权运维用 `freeze-browser` 固定观察和两份对象，受限测试服务用 `read-projection` 读惰性文档，或用 `verify-browser` 校验整对对象。读取原件及分别恢复原件、投影使用 `read-browser-original`、`restore-browser-original`、`restore-browser-projection` 的独立授权。

获取契约使用 `acquisition.fetch.completed.v2` 表示单公告原件，`v3` 表示分组响应中的单公告观察，`v4` 表示浏览器原件与惰性投影的配对观察。每个稳定公告键拥有递增顺序，按来源与该公告键分区。事件主体仍是原件的内容寻址引用。同一键有可核实的历史部件时，acquisition 可为 evidence 提供单一存量地址及原件哈希；evidence 根据旧快照校验后沿用其内部记录和已有证据引用。历史 `v1` 由 evidence 兼容消费，已由观察接管的地址不会被迟到的历史事件覆盖。无法核实的旧关系保留原样。先升级消费端再切换生产端。[获取事件契约](../../../contracts/events/acquisition/events.asyncapi.yaml)

### 13.7 验收样例

境内开发 VPS 的一次性角色运行 `mq-acquisition-fetch --list-sources --require-runtime`，核验采集库和独立登录身份 `mq_acq_coverage_ro`。同一套报告查询走受限证据视图，读取获准的账本字段。原件字节、写入和恢复使用各自入口。连接或身份核验失败时以固定错误退出。[发布包覆盖查验](../../../deploy/vps/data-plane/README.md#采集覆盖查验)

首条工程验收使用安徽公共资源交易平台中标结果的固定 mock HTTP 响应。列表以 `guid` 和公告类型标识公告，详情请求取得 `newDetailSub` 的正文。核对发现记录、请求、原件和观察引用、事件、快照、固定事实与受权证据读取。用可控响应复验 `A → B → A`、重复交付、旧任务接管后返回、正文不变与必需附件缺失。实网来源按 [D1b](../../05-delivery/11-d1b-anhui-pilot-sources.md#2-安徽省公共资源交易平台工程建设) 分别验收，记录各自的复查、排序与更正能力。[处理器实现](../../../packs/information_domains/procurement/src/miaoqia_pack_procurement/sources/anhui_ggzy.py)

故障演练覆盖达到页上限后补齐缺口、429 与访问阻断、下载中断、对象写后数据库未提交、提交后 Kafka 未发布、恢复原件后重新消费。验收记录能从来源与窗口查到页面、任务、尝试、观察、制品和发件箱状态。值班视图按来源报告最近完整窗口、未完成范围、请求与结构错误、归档和下游消费积压。需要数据负责人确认的配置包括首个来源、对象键及复查方式、各类原件的保留范围。平台负责人确认暂存预算、告警及备份恢复，质量负责人据独立样本核对完整性和时效。[持续运行验收](../07-deployment-topology.md#12-运行恢复与升级验收立项清单-c11)

请求执行先以串行配置跑通同一条持久化路径，再逐步打开并发。用录制响应与可控时钟验证两个来源的不同轮次截止时间互不影响，相同站点的两个来源共守预算，429 等待期间其他站点继续处理，慢附件请求受并发、大小和时长预算约束，优先级和回填份额按配置生效，过期租约返回的响应不能提交新的当前观察。开启并发后复跑原件和事件故障验收。
