# 来源采集子系统（acquisition）

> 状态：评审中 · 版本：2.2 · 更新：2026-10-17 · 平面：数据供应

## 1. 使命

合法、稳定、可证明地从外部与授权来源获取原始信息，并以不可变原始制品的形式交给证据子系统。

## 2. 职责与非职责

**职责**

- 来源目录：来源注册、分类、所属信息领域、更新频率、负责人；
- 访问契约：访问方式（HTTP、浏览器渲染、开放 API、授权数据接口、文件投递）、认证方式、限速、时间窗口；
- 来源权利：采集、存储、展示、再分发、模型使用、保留期限的许可范围及依据；再分发与允许用途决定数据能否进入私有部署馈送（[部署拓扑第 10 节](../07-deployment-topology.md#10-私有部署的公共数据馈送)）；
- 调度：增量、回填、补采、按事件触发的采集计划；历史回溯深度不预设，由研究按需请求驱动；
- 抓取执行：请求构建、渲染、重试、去重（请求指纹）、出口管理；
- 原始归档：响应、附件、元数据按内容哈希写入对象存储；
- 来源健康：成功率、延迟、结构漂移、覆盖缺口、告警。

**非职责**

- 不解析业务字段（属于 `evidence` 与领域包解析器）；
- 不感知租户的关键词或策略：采集计划只由来源特性和数据覆盖目标决定；
- 不判断内容是否为新版本（属于 `evidence`）。

M0探针消费者在公共消费框架中先验证operations请求载荷，再核对来源与probe_id/subject；真实跨语言链路及非法载荷死信见[运行时验收](../../05-delivery/05-m0-runtime-acceptance.md)。其他来源采集及业务事件仍按所属里程碑实现。

## 3. 内部组件

| 组件 | 说明 |
|---|---|
| `source_registry` | 来源与访问契约、来源权利的管理 |
| `scheduler` | 生成采集任务；基于 Temporal 的定时与回填工作流 |
| `fetch_runtime` | 抓取执行器：HTTP 客户端、浏览器池（Playwright）、API 连接器、文件接收器 |
| `egress` | 出口代理与限速：按来源、域名、出口地址的令牌桶 |
| `source_handlers` | 由信息领域包提供的来源处理器：列表发现、详情获取、分页、附件 |
| `archive` | 原始制品写入、内容哈希、元数据 |
| `health` | 来源健康指标、结构漂移检测、告警 |

## 4. 拥有的数据（公共域）

| 实体 | 说明 |
|---|---|
| `Source` | 来源：标识、名称、信息领域、处理器、状态 |
| `AccessContract` | 访问方式、认证引用（密钥在密钥管理系统中）、限速、窗口 |
| `SourceRights` | 来源权利条目：逐项许可（采集、存储、展示级别、再分发、模型使用、允许用途、保留期限）、依据（公开/协议）、生效与到期时间、版本与审查记录；结构与组合规则见[数据架构第 12 节](../02-data-architecture.md#12-来源权利与数据权益) |
| `FetchPlan` / `FetchTask` | 采集计划与任务 |
| `FetchAttempt` | 每次请求：时间、状态码、耗时、出口、错误 |
| `RawArtifact` | 原始制品元数据：内容哈希、对象键、类型、大小、来源 URL、获取时间 |
| `SourceHealth` | 健康快照与告警 |

公共运行时只采集公共与授权数据商来源，不连接客户自己的系统。客户系统集成复用本子系统的连接器代码，以随单元部署的租户集成实例运行，见第 10 节。

## 5. 接口

| 接口 | 类型 | 说明 |
|---|---|---|
| `RegisterSource` / `UpdateSource` | 命令 | 运营人员注册或修改来源（需审批的字段：权利、启停） |
| `RequestBackfill` | 命令 | 请求对来源或时间范围回填 |
| `RequestRefetch` | 命令 | 对指定 URL 或制品重新获取（如附件缺失） |
| `RequestCoverage` | 命令 | 研究 Agent 按需提交的数据获取请求：指定来源、时间范围或对象，用于历史回填或补采；按预算、优先级与来源权利排队执行，完成后发布事件 |
| `GetSource` / `ListSources` | 查询 | 来源目录与状态 |
| `GetSourceRights` | 查询 | 供各子系统判定数据用途 |
| `GetRawArtifact` | 查询 | 返回元数据与短时签名访问地址 |
| `GetSourceHealth` | 查询 | 健康指标 |

## 6. 事件

载荷唯一定义见[`contracts/events/acquisition/events.asyncapi.yaml`](../../../contracts/events/acquisition/events.asyncapi.yaml)。复用公共事件原语，稳定制品引用不含签名URL或凭据；事件正反例及引用兼容检查通过不代表生产发布/消费、事务发件箱或重放已实现。

**发布**

| 事件 | 说明 |
|---|---|
| `acquisition.fetch.completed.v1` | 一个原始制品已归档；载荷含来源、制品引用、内容哈希、获取时间 |
| `acquisition.fetch.failed.v1` | 抓取最终失败 |
| `acquisition.source.health_changed.v1` | 来源健康状态变化 |
| `acquisition.source.rights_changed.v1` | 来源权利变化（下游据此调整可见性或下线数据） |

**消费**

| 事件 | 处理 |
|---|---|
| `evidence.artifact.refetch_requested.v1` | 证据处理发现附件缺失或内容损坏时请求补采 |
| `domain.coverage.gap_detected.v1` | 领域情报发现覆盖缺口时触发补采 |

## 7. 扩展点

- **来源处理器 SPI**（`SourceHandler`）：由信息领域包提供，实现列表发现、详情与附件获取；
- **连接器 SPI**（`Connector`）：新的访问方式（如某授权数据商的 API）；客户系统的连接器实现同一 SPI，只在租户集成实例中加载（第 10 节）；
- **健康规则**：领域包可提供结构漂移检测规则。

## 8. 伸缩与可靠性

- 负载特征：I/O 密集、突发；浏览器渲染为 CPU/内存密集；
- 伸缩：`fetch_runtime` 按任务队列深度水平伸缩；浏览器池独立伸缩；
- 隔离：单个来源的故障不影响其他来源（按来源的并发与熔断）；
- 幂等：请求指纹 + 内容哈希，重复抓取不产生重复制品；
- 降级：对象存储或事件总线不可用时本地缓冲并暂停调度，不丢失已抓取内容。

## 9. 安全要点

- 只访问来源权利允许的来源与路径；遵守限速与访问时间窗口；
- 不使用个人账号，不规避登录、验证码或技术保护措施；
- 访问凭证存放于密钥管理系统，运行时短期获取；
- 抓取到的内容一律视为不可信输入，不在本子系统执行任何脚本或宏；
- 出口地址与请求日志保留以备合规审查。

## 10. 租户集成

客户自己的系统（CRM、项目管理、ERP、文件投递目录等）按以下分工接入，不新增子系统：

| 环节 | 所有者 | 内容 |
|---|---|---|
| 凭证 | 租户管理员授权（`identity` 的 `can_manage_credentials`，强认证），密钥存于所在单元的密钥管理，数据库只存引用 | OAuth 授权或 API 密钥、作用域、轮换与吊销；吊销后连接立即停止 |
| 连接生命周期与增量同步 | `acquisition` 的租户集成实例（随单元部署，使用单元级凭证、存储与出口，不与公共实例混用） | 连接状态与健康、同步游标、限速与重试、按外部记录标识幂等、外部删除转为“已删除”标记；原始记录写入租户隔离存储，只发布单元内的租户主题事件 |
| 业务映射 | 使用这份数据的业务所有者 | `pursuit`：CRM 商机与推进的映射（`ExternalLink`）及字段归属；`customer-context`：客户、产品、资质与业绩的导入；`evidence` 租户实例：客户文档。映射规则、冲突处理与回写内容由所有者决定，回写只发往该租户已连接的系统并留审计 |
| 通讯录与成员同步 | `identity` | 企业目录、SSO 与成员同步属于身份数据，由 `directory` 直接对接，不经租户集成实例 |

公共采集计划不受租户关键词或业务策略影响；当前权利只读入口仍须核验调用用户、tenant/cell 和 purpose。租户集成实例只运行租户的连接，不读取公共来源计划，也不把租户数据写入公共存储或公共事件。本子系统的 `tenant` 数据域与单元级角色在首个租户集成启用时登记（[子系统索引第 4 节](README.md#4-运行实例的数据域)、[部署拓扑](../07-deployment-topology.md#5-租户单元)）。

## 11. 开放问题

1. 授权数据供应商的选型与接入方式；
2. 每个来源的权利登记编号与启用验收；数据负责人决定启用，法务确认权利，来源变更按治理流程下线。

历史回填仅承诺已登记来源的可访问范围；按任务配置并发、请求范围、时长与费用上限，在线增量优先。来源无法提供、超限或超时返回覆盖缺口，研究使用部分证据并标注未知，不制造完整历史。

## 12. 当前实现边界

已实现[冻结语料当前权利端口（d0）](source-rights-runtime.md)：acquisition 自有 PostgreSQL 的不可变版本/组合别名、原子当前撤销与审计、本地受限 operator CLI、acq-admin 内部 mTLS 只读接口和跨单元 remote client。允许两个已复核 building corpus/source 组合及一个精确 building-topic 参考 source/tags 组合登记；参考内容身份由 evidence 固定 manifest/绑定核验，两个独立 register/bind 批次均不激活；所有输入的原始和当前限制同时成立才允许。旧 tags、事实、事件与快照保持不变。真实来源采集、完整来源治理及 rights_changed 事件、data 查询 listener、Go 生产适配和完整 R2 未交付；A02 保持 L0。
