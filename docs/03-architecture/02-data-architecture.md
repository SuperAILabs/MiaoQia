# 数据架构

> 状态：评审中 · 版本：1.0 · 更新：2026-10-12 · 负责人：数据架构负责人

## 1. 数据分区

```text
┌──────────────────────────── 公共域 Public Zone ────────────────────────────┐
│ 原始制品 → 快照/文档/解析修订/证据 → 领域事实/事件 → 实体/关系 → 检索投影 │
│ acquisition    evidence             domain-intelligence  entity-graph search │
└─────────────────────────────────────────────────────────────────────────────┘
                     ▲ 只读引用（subject_ref + version）
┌──────────────────────────── 租户域 Tenant Zone（按租户单元部署）────────────┐
│ 客户上下文/策略/知识资产 → 监测/信号 → 研究 → 判断/决策 → 推进/结果 → 反馈   │
│ customer-context          detection   research assessment pursuit learning   │
│ + 客户授权原始数据与文档（租户隔离存储）                                    │
└─────────────────────────────────────────────────────────────────────────────┘
┌──────────────────────────── 平台域 Platform Zone ──────────────────────────┐
│ 身份与授权 · 订阅计量 · 审计 · 模型目录与调用记录 · 运营工单               │
└─────────────────────────────────────────────────────────────────────────────┘
```

规则：

- 公共域永不读取租户域；
- 租户域通过 `subject_ref` 引用公共域对象的特定版本，不复制公共数据（检索结果快照与特征快照只保存判断所需的最小字段与引用）；
- 平台域数据带租户标识，按租户访问控制。

## 2. 存储组合

| 存储 | 用途 | 所有权规则 |
|---|---|---|
| **PostgreSQL** | 所有子系统的权威事务数据 | 每个子系统独占一个逻辑数据库与数据库账号；禁止跨库访问 |
| **对象存储（S3 兼容）** | 原始制品、规范化文档、附件、知识资产文件、导出、大型研究产物 | 按域与子系统划分桶与前缀；租户对象使用租户前缀与租户密钥 |
| **OpenSearch** | 全文、语义、混合检索；订阅反查；租户知识检索 | `search` 子系统独占；全部为派生数据 |
| **PostgreSQL 只读副本** | 领域统计、仿真与评估等重查询 | 与主库同一所有权；只读，隔离在线写入负载 |
| **Kafka** | 领域事件与集成事件 | 主题按发布子系统划分所有权 |
| **Redis** | 缓存、限流、短期幂等记录、分布式锁 | 不作为任何数据的权威来源 |
| **图查询引擎**（读模型） | 实体关系的多跳遍历 | `entity-graph` 独占；由 PostgreSQL 权威数据投影 |

选型理由见 [ADR-0007](../04-decisions/0007-storage-portfolio.md)。

### 2.1 数据规模估算与分析能力

| 数据 | 量级估算 **[待核验]** | 处理方式 |
|---|---|---|
| 公共采购领域事实 | 每年数百万条公告，数年累计千万级 | PostgreSQL 按时间分区 |
| 企业主数据 | 千万级组织 | PostgreSQL |
| 实体关系 | 千万至亿级边 | PostgreSQL 分区 + 图查询读模型 |
| 租户信号、判断、反馈 | 每租户每年数万至数十万条 | PostgreSQL 分区 |
| 审计与计量事件 | 每日数十万至数百万条 | PostgreSQL 按月分区，过期归档到对象存储 |

这个规模在 PostgreSQL（分区、索引、汇总表、只读副本）的能力范围内，因此**不引入专用分析数据库**。统计类查询通过两种方式保证性能：

- **统计汇总表**：`domain-intelligence` 维护按采购人、品类、区域、月份等维度预聚合的汇总表，随领域事实增量更新，研究工具与界面读取汇总表而非扫描明细；
- **只读副本**：仿真、评估回归、运营报表等批量查询走只读副本，与在线写入隔离。

统计查询以 `domain-intelligence.GetDomainStatistics` 等接口固定契约。若将来出现交互式多维分析（例如面向客户的自助分析报表）且汇总表与只读副本无法满足，再按 ADR 评估引入列式分析库，调用方不受影响。

## 3. 标识符

- 格式：`<类型前缀>_<ULID>`，例如 `org_01JA…`、`sig_01JA…`；ULID 保证时间有序与全局唯一；
- 前缀登记在 `contracts/identifiers.yaml`，由各子系统申请，禁止重复；
- 外部业务标识（统一社会信用代码、项目编号、公告编号）作为属性存储，不作为主键；
- 标识一经分配永不复用；实体合并后旧标识保留并指向存续实体。

## 4. 时间模型

所有长期对象使用双时态，并按需记录来源时间：

| 时间字段 | 含义 |
|---|---|
| `published_at` | 来源声明的发布时间（可能缺失或不准确） |
| `observed_at` | 系统首次观察到该内容的时间 |
| `valid_from` / `valid_to` | 事实在现实世界中的有效区间（如资质有效期、关系存续期） |
| `recorded_at` | 系统记录该版本的时间 |

所有时间以 UTC 存储，原始时区与精度作为属性保留（如“仅精确到日”）。

## 5. 版本模型

```text
RawArtifact (内容哈希, 不可变)
  └─ SourceSnapshot v1, v2 …          来源内容实际变化 → 新快照
       └─ ExtractionRevision r1, r2 … 解析器升级/人工修正 → 新修订
            └─ DomainFactVersion       领域事实版本（引用修订）
                 └─ Entity/Relationship 版本（引用事实）

TenantSide:
  PolicyVersion, ContextSnapshot, ModelVersion, PromptVersion, TemplateVersion
  ResearchReport  ─固定引用→  事实版本 + 上下文快照 + 模型/提示/工具/模板版本
  Assessment      ─固定引用→  研究报告 + 策略版本 + 特征快照 + 框架版本
  Decision        ─固定引用→  判断版本
```

- 原始制品与快照不可变；解析修订与事实版本追加式；
- “当前版本”是指针，不是覆盖；
- 任何租户侧产物都可以按其固定的版本重放。

## 6. 通用对象字段

所有长期对象至少包含：

| 字段 | 说明 |
|---|---|
| `id` | 类型化 ULID |
| `schema_version` | 对象 Schema 版本 |
| `tenant_id` | 租户域对象必填，只能由服务端从认证上下文写入 |
| `visibility` / `rights_tags` | 可见性与来源权利标签（公共域对象） |
| `classification` | 数据分级 |
| `created_at` / `recorded_at` | 记录时间 |
| `source_refs` / `evidence_refs` | 来源与证据引用（适用时） |
| `quality` | 质量状态与警告（适用时） |
| `change_reason` | 变更原因（可变对象） |

## 7. 数据库设计约定

- 每个子系统一个逻辑数据库；数据库内按信息领域或聚合划分 schema；
- 迁移工具统一（Alembic），迁移必须向前兼容，至少支持“扩展—迁移—收缩”三步；
- 大表按时间分区（领域事实、抓取记录、信号、审计）；
- 租户域表全部带 `tenant_id`，启用行级安全（RLS），会话变量由数据访问层从请求上下文设置；
- 事务性发件箱表 `outbox` 存在于每个发布事件的子系统数据库中；
- 禁止数据库触发器承载业务逻辑。

## 8. 派生数据与重建

| 派生数据 | 来源 | 重建方式 |
|---|---|---|
| 检索索引 | 领域事实、实体、知识资产 | 全量重放事件或批量导出导入，别名切换 |
| 统计汇总表 | 领域事实 | 从领域事实增量或批量重算 |
| 图查询读模型 | 实体与关系 | 从 PostgreSQL 批量投影 |
| 实体画像 | 关系与统计 | 重新计算 |

派生数据的任何不一致都以权威数据为准；派生数据不得被写回权威数据。

## 9. 数据保留与删除

- 保留期限由 `governance` 的保留策略定义，按数据类别配置；
- 公共域原始制品与证据默认长期保留（受来源权利约束）；
- 租户数据在租户注销后按合同约定期限删除，删除覆盖所有存储及备份的过期策略；
- 模型调用记录不保存敏感原文，按策略短期保留。

## 10. 备份与容灾

| 数据 | 恢复点目标（RPO） | 恢复时间目标（RTO） |
|---|---|---|
| PostgreSQL（全部子系统） | ≤ 5 分钟（持续归档） | ≤ 1 小时 |
| 对象存储 | 跨可用区冗余，版本保护 | ≤ 1 小时 |
| Kafka | 多副本；事件可由发件箱重发 | ≤ 1 小时 |
| OpenSearch、图读模型、统计汇总表 | 可重建 | 数小时（重建） |

目标在生产上线前以恢复演练验证，演练每季度执行一次。
