# 安全与租户隔离

> 状态：评审中 · 版本：1.0 · 更新：2026-10-12 · 负责人：安全负责人

## 1. 安全目标

| 目标 | 度量 |
|---|---|
| 跨租户数据暴露 | 0 次 |
| 未经批准执行的高影响动作 | 0 次 |
| 敏感数据进入日志、分析或未授权模型 | 0 次（负向测试 100% 通过） |
| 来源权利外的数据使用 | 0 次 |
| 安全事件可追溯 | 100% 有审计记录 |

## 2. 租户模型

```text
Tenant（签约客户）
 ├─ OrgUnit（事业部、区域，可多级）
 │   └─ Workspace（可选：项目组、业务线）
 ├─ Member / ServiceAccount / ExternalCollaborator
 └─ 归属 Cell（租户单元）
```

- **租户单元（Cell）**：一套客户智能平面的运行实例与数据存储（数据库、索引、主题），承载一组租户。共享单元服务标准租户；专属单元服务大型或高合规租户；
- 数据供应平面在所有单元之间共享（公共域）；
- 平台平面全局共享，数据按租户隔离。

单元化使平台可以通过增加单元水平扩展租户规模，并以同一套代码提供专属部署。

## 3. 隔离层次

| 层次 | 机制 |
|---|---|
| 身份 | 租户只从已验证令牌派生；请求体、工具参数、事件载荷中的租户字段不被信任 |
| 应用 | 所有租户域查询经数据访问层自动注入租户条件；授权决策点检查资源归属 |
| 数据库 | 行级安全（RLS），会话变量由数据访问层设置；租户域子系统使用独立数据库账号 |
| 对象存储 | 租户前缀 + 租户专属加密密钥（KMS 数据密钥）；签名地址短时有效 |
| 检索 | 租户私有索引物理分离；公共索引查询服务端强制注入可见性过滤 |
| 事件 | 租户事件在单元主题中，信封携带租户与单元；消费者校验 |
| 缓存 | 缓存键包含租户与数据版本；禁止跨租户共享缓存条目 |
| 模型 | 模型上下文只包含当前租户数据；调用记录带租户；结果缓存仅限公共域任务 |
| 日志与分析 | 结构化日志禁止记录敏感内容；分析事件只含标识与度量 |
| 部署 | 专属单元：独立数据库、索引、主题与计算 |

## 4. 授权

- RBAC 定义角色权限模板；ReBAC/ABAC 处理资源归属、协作者关系与数据分级、金额、区域等条件；
- 所有子系统通过统一授权 SDK 调用 `identity` 的授权决策点；
- 高影响动作清单与审批见 [identity](subsystems/identity.md)；
- 内部人员访问租户数据仅限经批准的限时支持访问，只读优先，全程审计，租户管理员可见。

## 5. 数据分级与处理约束

| 分级 | 示例 | 存储 | 模型路由 | 日志 |
|---|---|---|---|---|
| 公开 | 公告正文、公开企业信息 | 标准 | 已备案模型 | 允许摘要 |
| 内部 | 租户策略、信号、判断 | 租户隔离 | 已备案模型（租户可限制） | 只记引用 |
| 敏感 | 客户报价、未公开项目、合同 | 租户隔离 + 租户密钥 | 私有部署模型或租户指定 | 禁止 |
| 个人信息 | 联系人姓名、电话、邮箱 | 单独字段加密 | 默认不进入模型 | 禁止 |

分级规则由 `governance` 维护，随数据在系统中传递（字段级标签）。

## 6. 个人信息

- 公开来源中的联系人信息仍属于个人信息：单独存储、加密、分级展示；
- 用途限定：用于与该采购项目相关的业务联系；禁止批量导出用于营销；查看与导出均审计；
- 不对评标专家、监管人员建立画像；
- 自动化推送提供关闭方式；
- 个人信息主体权利请求由 `governance` 编排处理。

## 7. 应用安全

- 依赖与镜像漏洞扫描、签名镜像、最小基础镜像；
- 文档处理与浏览器渲染在沙箱中执行；
- 出站请求（Webhook、采集）防 SSRF：目标地址校验与出口隔离；
- 密钥统一存放于密钥管理系统，运行时短期获取，定期轮换；
- 管理操作强制多因素认证；
- 安全事件响应流程与演练。

## 8. 安全测试要求

除常规测试外，必须覆盖：

1. **跨租户负向测试**：以租户 A 身份，通过 API、MCP、事件、检索、导出、缓存、研究工具访问租户 B 资源，全部失败；
2. **未知字段负向测试**：在合法请求中加入顶层与嵌套的未知键、其他租户标识、密钥形态值、文件路径、供应商原始载荷，验证被拒绝或净化，且不出现在输出、日志、分析事件与模型请求中；
3. **提示注入测试**：在公告、附件、客户文档中嵌入指令，验证不能触发工具、扩大权限或改变租户；
4. **审批绕过测试**：通过任何渠道尝试直接执行高影响动作；
5. **删除完整性测试**：租户删除后在所有存储中不可检索。

这些测试是持续集成的阻断项，见 [研发规范](../05-delivery/03-engineering-standards.md)。
