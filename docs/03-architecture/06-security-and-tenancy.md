# 安全与租户隔离

> 状态：评审中 · 版本：1.4 · 更新：2026-10-17 · 负责人：安全负责人

## 1. 安全目标

| 目标 | 度量 |
|---|---|
| 跨租户数据暴露 | 0 次 |
| 未经批准执行的高影响动作 | 0 次 |
| 敏感数据进入日志、分析或未授权模型 | 0 次（负向测试 100% 通过） |
| 来源权利外的数据使用 | 0 次 |
| 安全事件可追溯 | 100% 有审计记录 |

## 2. 租户模型

```text
Tenant（签约客户）
 ├─ OrgUnit（事业部、区域，可多级）
 │   └─ Workspace（可选：项目组、业务线）
 ├─ Member / ServiceAccount / ExternalCollaborator
 └─ 归属 Cell（租户单元）
```

- **租户单元（Cell）**：一套客户智能平面的运行实例与数据存储（数据库、索引、主题），承载一组租户。共享单元服务标准租户；专属单元服务大型或高合规租户；
- 公共数据供应实例在所有单元之间共享；`search` 的租户知识/订阅索引与 `evidence` 的租户文档实例随 Cell 部署。平面是能力分类，数据域是运行实例的访问边界，不能从平面、语言或镜像名称推断隔离；
- 平台平面全局共享，数据按租户隔离。

单元化使平台可以通过增加单元水平扩展租户规模，并以同一套代码提供专属部署。

## 3. 隔离层次

| 层次 | 机制 |
|---|---|
| 身份 | 租户只从已验证令牌派生；请求体、工具参数、事件载荷中的租户字段不被信任 |
| 应用 | 所有租户域查询经数据访问层自动注入租户条件；授权决策点检查资源归属 |
| 数据库 | 行级安全（RLS），会话变量由数据访问层设置；租户域子系统使用独立数据库账号 |
| 对象存储 | 租户前缀 + 租户专属加密密钥（OpenBao Transit 信封加密）；签名地址短时有效 |
| 检索 | 租户私有索引物理分离；公共索引查询服务端强制注入可见性过滤 |
| 事件 | 租户事件在单元主题中，信封携带租户与单元；消费者校验 |
| 缓存 | 缓存键包含租户与数据版本；禁止跨租户共享缓存条目 |
| 模型 | 模型上下文只包含当前租户数据；调用记录带租户；结果缓存仅限公共域任务 |
| 日志与分析 | 结构化日志禁止记录敏感内容；分析事件只含标识与度量 |
| 部署 | 专属单元：独立数据库、索引、主题与计算 |
| 驻留 | 每个 Cell 与私有部署引用驻留策略，覆盖数据库、备份、对象、索引、模型端点、日志与运维访问（[部署拓扑第 11 节](07-deployment-topology.md#11-数据驻留)） |

### 3.1 M0 HTTP认证边界

外部网关只接受指定HTTPS Keycloak issuer签发、目标audience匹配的RS256 Bearer访问令牌，必须含有效exp/iat；检查nbf、主体及租户/单元配对，丢弃客户端Miaoqia-Context头。租户请求再经identity权威目录核对当前租户/成员状态及cell-01归属；错误租户/cell拒绝，目录故障503，不读取令牌角色恢复撤权。生命周期管理要求已签名amr=mfa且通过当前授权，MFA声明不在内部头传递；平台operator+MFA命令可指定受管理的tenantID，但不据此切换用户上下文或cell。具体边界见[M0身份验收](../05-delivery/07-m0-identity-acceptance.md)。内部上下文只经TLS1.3双向认证及精确SPIFFE调用方白名单传递。默认生产策略缺配置失败关闭，仅显式development允许实验环境明文。认证配置及真实正反例见[M0运行时验收](../05-delivery/05-m0-runtime-acceptance.md)；实际证书运维和部署网络另验收。

## 4. 授权

- RBAC 定义角色权限模板；ReBAC/ABAC 处理资源归属、协作者关系与数据分级、金额、区域等条件；
- 所有子系统通过统一授权 SDK 调用 `identity` 的授权决策点；
- 高影响动作清单与审批见 [identity](subsystems/identity.md)；
- 内部人员访问租户数据只有两条路径：排障用经批准的限时支持访问，只读优先；托管服务用租户管理员授予的服务委托，限范围、动作与期限，可随时撤销（[identity 第 7.8 节](subsystems/identity.md#78-服务委托)）。两者都全程审计并记录实际操作者与代表的租户，租户管理员可见；托管服务合同不授予访问。

## 5. 数据分级与处理约束

| 分级 | 示例 | 存储 | 模型路由 | 日志 |
|---|---|---|---|---|
| 公开 | 公告正文、公开企业信息 | 标准 | 已备案模型 | 允许摘要 |
| 内部 | 租户策略、信号、判断 | 租户隔离 | 已备案模型（租户可限制） | 只记引用 |
| 敏感 | 客户报价、未公开项目、合同 | 租户隔离 + 租户密钥 | 默认不进入模型；租户显式授权的指定供应商（零留存、禁止训练、境内处理），私有部署为客户自有端点 | 禁止 |

分级规则由 `governance` 维护，随数据在系统中传递（字段级标签）。公开来源中的个人业务信息按“公开”处理，租户提供的数据中的个人信息按所在的租户数据分级处理（见第 6 节）。

## 6. 个人信息

- 公开来源中的个人业务信息（公告联系人的姓名、电话、邮箱，企业登记中的法定代表人、股东、高管等）是客户开展业务联系所需的信息，按公开数据明文存储、检索、展示、进入模型输入，不做加密或脱敏；代码仓库中的语料样本保留原文；删除、更正请求须覆盖检索索引与派生数据；
- 不对评标专家、监管人员建立画像或提供接触信息；
- 主体为自然人的司法与信用记录不采集（见 INF-CRED）；
- 个人信息主体的删除、更正等权利请求由 `governance` 编排处理；
- 自动化推送提供关闭方式。

## 7. 公共数据暴露控制

公共信源数据是平台的核心资产。用户与外部接口只能**按需、受控**地接触其中一部分，全量数据只供平台内部的 Agent 研究使用。

| 层面 | 控制 |
|---|---|
| 可见范围 | 租户自身数据完整可见；公共数据只通过检索、对象页、证据查看、研究报告引用按需呈现 |
| 结果规模 | 单次检索结果上限与翻页深度上限；对象页只展示与该对象相关的数据 |
| 配额 | 按套餐设定每日检索、对象查看、原文查看的配额（由 `commerce` 执行） |
| 导出 | 只允许导出租户自身产物；公共数据不提供批量导出；原始附件下载按来源权利控制；租户导出与迁移的审批见 [governance 第 10 节](subsystems/governance.md#10-数据导出与迁移) |
| 接口 | API 与 MCP 适用相同的上限与配额；不提供公共数据的全量同步接口（数据与 API 交付模式另按合同单独授权；私有部署馈送只含可再分发数据，见 [部署拓扑第 10 节](07-deployment-topology.md#10-私有部署的公共数据馈送)） |
| Agent 输出 | Agent 可使用全量数据进行研究，但输出给用户的是结论与所引用的证据片段，而非数据转储 |
| 追溯 | 页面与导出文件带租户与用户水印 |
| 反爬取 | 按用户、租户、凭证监测访问频率与遍历模式；异常时限流、要求复核、告警，必要时暂停凭证 |

暴露策略以配置版本化，由 `gateway`、`search` 与 `commerce` 共同执行，策略变更需安全负责人批准。

## 8. 应用安全

- 依赖与镜像漏洞扫描、签名镜像、最小基础镜像；
- 文档处理与浏览器渲染在沙箱中执行；
- 出站请求（Webhook、采集）防 SSRF：目标地址校验与出口隔离；
- 密钥统一存放于密钥管理系统，运行时短期获取，定期轮换；
- 管理操作强制多因素认证；
- 安全事件响应流程与演练。

## 9. 安全测试要求

除常规测试外，必须覆盖：

1. **跨租户负向测试**：以租户 A 身份，通过 API、MCP、事件、检索、导出、缓存、研究工具访问租户 B 资源，全部失败；
2. **未知字段负向测试**：在合法请求中加入顶层与嵌套的未知键、其他租户标识、密钥形态值、文件路径、供应商原始载荷，验证被拒绝或净化，且不出现在输出、日志、分析事件与模型请求中；
3. **提示注入测试**：在公告、附件、客户文档中嵌入指令，验证不能触发工具、扩大权限或改变租户；
4. **审批绕过测试**：通过任何渠道尝试直接执行高影响动作；
5. **删除完整性测试**：租户删除后在所有存储中不可检索；
6. **数据暴露测试**：通过 Web、API、MCP、渠道尝试遍历或批量获取公共数据，验证上限、配额、限流与异常检测生效。

这些测试是持续集成的阻断项，见 [研发规范](../05-delivery/03-engineering-standards.md)。
