# 从 Tender Intel 迁移

> 状态：评审中 · 版本：1.0 · 更新：2026-10-12 · 负责人：数据负责人

## 1. 定位

[Tender Intel](https://github.com/lansespirit/tender-intel) 是妙洽的参考实现与首个信息领域（`INF-PROC` 公共采购）的资产来源。它验证了妙洽最重要的数据原则，但其运行形态（Python CLI、SQLite、本地文件）与对象模型（以招投标公告为中心）不是妙洽的平台架构。

迁移的目标是：**把已验证的原则和代码资产放进妙洽的终态结构，而不是把 Tender Intel 的结构扩展成妙洽。**

## 2. 必须继承的原则

| 原则 | 在妙洽中的落点 |
|---|---|
| 公共信源一次采集、多客户复用 | 数据供应平面与租户域分离 |
| 请求资源、抓取尝试、原始 Blob 归档 | `acquisition` |
| 稳定公告身份、不可变来源版本、可重放解析修订 | `evidence` 的快照与解析修订 |
| 字段 provenance 与质量 | `evidence` 的字段溯源与质量评估 |
| 客户规则版本、双版本固定 | `customer-context` 策略版本；判断固定引用 |
| 证据化候选评估与处置分层 | `detection` 处置模型 |
| 增量与回填匹配、原子增量交付 | `detection` 回填、`notification` 幂等投递 |
| 共享事实与客户状态物理隔离 | 公共域与租户域、租户单元 |

## 3. 资产映射

| Tender Intel 组件 | 迁移判断 | 妙洽中的位置 |
|---|---|---|
| 来源目录与每源 handler | 高复用 | `packs/information_domains/procurement` 的来源定义与 `SourceHandler` 实现 |
| 请求指纹、原始 Blob | 高复用（概念与测试） | `acquisition.archive`，存储适配为对象存储与 PostgreSQL |
| 稳定公告身份与来源版本 | 核心资产 | `evidence.snapshotter` 的快照判定规则（由领域包提供身份规则） |
| 解析器与字段 provenance | 高复用 | 领域包 `Extractor` 实现 |
| 质量评估 | 高复用 | 领域包质量规则 |
| 公告字段模型 | 重构 | 领域包的领域 Schema（`Notice`、`Lot`、`Item`、`Requirement`、`Deadline`、`BidResult` 等） |
| 客户规则与匹配 | 重构 | 规则语义迁入策略 DSL 与 `detection` 特征函数；行业相关部分迁入行业包（建材管材） |
| 处置分类 | 保留 | `detection` 处置模型 |
| 客户独立 SQLite | 不迁移形态 | 租户域 PostgreSQL + RLS；隔离原则保留 |
| CLI 与 Skill | 改造 | 运维命令迁入 `operations` 与工具脚本；Skill 改为调用 MCP |
| Excel/CSV/JSON 导出 | 保留功能 | 异步导出服务（权限、过期、审计、水印） |
| 216 个测试 | 保留 | 迁入领域包测试与 `evidence` 回归测试，作为迁移验收基线 |
| “当前模式重建、无迁移”的数据库策略 | 不适用 | 生产迁移必须向前兼容并可回滚 |

## 4. 迁移步骤

| 步骤 | 内容 | 验收 |
|---|---|---|
| M-1 权利确认 | 确认 Tender Intel 代码与数据的知识产权归属和商业使用授权；逐一复核其来源的来源权利 | 书面确认；来源权利登记完成 |
| M-2 基线冻结 | 在原仓库重新运行全部测试与来源清单，记录基线（来源数、启用数、测试通过数、样本解析结果） | 基线报告 |
| M-3 领域包化 | 来源处理器、解析器、质量规则、身份规则按 SPI 重写为 `procurement` 信息领域包 | 原测试在新 SPI 下通过；样本解析结果一致 |
| M-4 数据导入 | 历史原始制品导入对象存储；按新规则生成快照与解析修订（保留原版本对应关系） | 抽样一致性校验；版本链完整 |
| M-5 规则迁移 | 现有客户规则转写为策略 DSL；建材管材相关语义抽为行业包 | 在历史数据上，新旧匹配结果的差异全部可解释 |
| M-6 并行运行 | 新旧系统并行采集与匹配，对比覆盖、时效与匹配结果 | 差异报告，关键指标不劣于旧系统 |
| M-7 切换 | 妙洽成为主记录；Tender Intel 只作参考 | 切换检查表 |

## 5. 风险

| 风险 | 应对 |
|---|---|
| 权利不清导致资产不可用 | M-1 为前置步骤，不通过则对应资产不迁移 |
| 重写 SPI 时破坏已验证的边界 | 以原测试与样本为回归基线 |
| 历史数据规模与质量问题 | 分批导入，导入本身作为可重放工作流 |
