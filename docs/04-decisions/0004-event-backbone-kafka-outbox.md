# ADR-0004：事件骨干：Kafka + 事务性发件箱 + CloudEvents

> 状态：提议 · 日期：2026-10-12 · 决策者：首席架构师、产品负责人

## 背景

子系统之间以事件传播状态变化；需要持久、可重放、分区有序，并保证业务写入与事件发布一致。

## 决策

- 事件总线使用 Kafka（优先使用云托管服务）；
- 每个发布事件的子系统在自己的数据库中维护 `outbox` 表，与业务写入同事务提交，由中继发布；
- 事件信封采用 CloudEvents 1.0，扩展属性携带域、租户、单元；
- 事件 Schema 以 AsyncAPI + JSON Schema 管理，CI 检查兼容性；
- 主题按域与单元划分：`public.*`、`cell-<id>.*`、`platform.*`；
- 同进程的生产者与消费者也经 Kafka，不使用进程内事件总线。

## 备选

- 只用 PostgreSQL 作队列：规模与重放能力不足，与终态不符；
- Pulsar / NATS JetStream：功能可行，但国内托管与运维经验不如 Kafka 普及。

## 后果

- 正面：读模型可重建、消费者可独立伸缩、拆分子系统不改变语义；
- 代价：所有消费者必须幂等；最终一致性需要在产品交互上明确表达。
