# ADR-0011：证据不可变与双版本

> 状态：已批准 · 日期：2026-10-12 · 决策者：首席架构师、产品负责人 · 批准：项目负责人

## 背景

前期原型（Tender Intel）的实践表明：原始证据不可变、来源版本与解析版本分离、判断固定引用版本，是可信与可重放的基础。

## 决策

作为平台不变量：

- 原始制品按内容哈希不可变存储；
- 来源内容变化产生新快照；解析器升级或人工修正产生新解析修订；两者分别记录；
- 领域事实版本引用解析修订；“当前版本”是指针；
- 研究报告、判断与决策固定引用其依据的全部版本，可按版本重放；
- 客户反馈不得改写公共事实。

## 后果

- 正面：任何结论都能回到原文并解释“当时为什么这样判断”；
- 代价：存储增长；需要版本感知的查询与清理策略。

## 补充：结构化证据与派生证据（2026-10-16，待批准）

> 本节随任务书 D1 提出，批准前不改变上文已批准的决策；三种证据契约均为 0.1.0 草案。

证据有三种形态，共用 `ev_` 标识空间，字段溯源 `provenance.evidence_ref` 不区分形态：

| 形态 | 契约 | 坐标系 | 不可变依据 |
|---|---|---|---|
| 文档证据 | `contracts/schemas/evidence/evidence-ref.schema.json`（1.0.0，已冻结，不带 `kind`） | 规范化文档的块、字符区间、表格单元 | 快照 + 处理管线版本 + `quote_hash` |
| 记录证据 | `record-evidence-ref.schema.json`（`kind=record`） | 结构化记录集（`structured-record.schema.json`）的记录键 + 字段路径 | 快照 + 处理管线版本 + `value_hash` |
| 派生证据 | `derivation-evidence-ref.schema.json`（`kind=derivation`） | 输入列表：每项的证据，及固定的事实版本与字段路径 | 转换标识与版本 + 参考数据版本 + 输入 + `value_hash` |

- 接口、数据下载等结构化来源产生的快照转换为结构化记录集，与规范化文档并列存放在 L1，按快照 × 处理管线版本追加；网页、PDF、Office 文档及其中的表格仍只走规范化文档，不另设平行格式。
- 派生只用于确定性转换（日期推算、单位换算、区划新旧代码对照等），同一转换版本对同样输入给出同样结果；模型推断走解析或增强，带各自的证据。
- 派生证据链必须无环，末端都是文档证据或记录证据；输入来自领域事实字段时固定引用事实版本，不随当前版本指针变化。输入多于 64 项的汇总属于统计，按统计口径与版本追溯，不作为字段证据。
- 双版本不变量扩展为：结构化来源同样区分来源快照与处理管线版本；派生取值另记转换版本与参考数据版本，任一版本变化都产生新的派生证据，旧证据保留。
