# ADR-0011：证据不可变与双版本

> 状态：已批准 · 日期：2026-10-12 · 决策者：首席架构师、产品负责人 · 批准：项目负责人
> 修订：2026-10-16 并入结构化证据与派生证据（任务书 D1），按项目负责人审阅意见修订，随所在 PR 合并生效；新增三份契约仍为草案，运行能力按下文首次启用门禁验收

## 背景

前期原型（Tender Intel）的实践表明：原始证据不可变、来源版本与解析版本分离、判断固定引用版本，是可信与可重放的基础。

## 决策

作为平台不变量：

- 原始制品按内容哈希不可变存储；
- 来源内容变化产生新快照；解析器升级或人工修正产生新解析修订；两者分别记录；
- 领域事实版本引用解析修订；“当前版本”是指针；
- 研究报告、判断与决策固定引用其依据的全部版本，可按版本重放；
- 客户反馈不得改写公共事实。

证据有三种形态，共用 `ev_` 标识空间，字段溯源 `provenance.evidence_ref` 不区分形态：

| 形态 | 契约 | 坐标系 | 不可变依据 |
|---|---|---|---|
| 文档证据 | `contracts/schemas/evidence/evidence-ref.schema.json`（1.0.0，已冻结，不带 `kind`） | 规范化文档的块、字符区间、表格单元 | 快照 + 处理管线版本 + `quote_hash` |
| 记录证据 | `record-evidence-ref.schema.json`（`kind=record`，草案） | 结构化记录集（`structured-record.schema.json`，草案）的记录键 + 字段路径 | 快照 + 处理管线版本 + `value_hash` |
| 派生证据 | `derivation-evidence-ref.schema.json`（`kind=derivation`，草案） | 输入列表：每项的证据，及固定的事实版本与字段路径 | 转换版本 + 参考数据版本 + 输入 + `value_hash` |

- 文档证据定位原文段落与表格；接口、数据下载等结构化来源的快照转换为结构化记录集，与规范化文档并列存放在 L1，按快照 × 处理管线版本追加，由记录证据定位到记录与字段。网页、PDF、Office 文档及其中的表格只走规范化文档，不另设平行格式。
- 派生证据只解释确定性计算（日期推算、单位换算、区划新旧代码对照等）：同一转换版本对同样输入给出同样结果。模型推断走解析或增强，带各自的证据，以区分“计算所得”与“推断所得”。
- 字段派生与统计按计算目的区分，不按输入个数区分：为领域事实的一个字段求值是字段派生，带派生证据；描述一批事实分布的是统计，按统计口径与版本追溯。单条派生证据的输入个数上限是契约中的资源限制，超限时登记被拒绝、不截断，字段派生拆成多级，中间结果各自登记派生证据。
- 可重放要求固定全部影响结果的依赖：转换版本固定参数、时区、舍入与精度规则等，任一变化都发布新版本；参考数据版本必须对应不可变且可取得的内容，同一版本不得重新发布为不同内容。只有版本字符串与结果哈希不构成可重放。
- 派生证据链必须无环，末端都是文档证据或记录证据；输入来自领域事实字段时固定引用事实版本，不随当前版本指针变化。
- 双版本同样适用于结构化来源：区分来源快照与处理管线版本；派生取值另记转换版本与参考数据版本，任一版本变化都产生新的派生证据，旧证据保留。
- 派生取值的可见性取全部输入来源可见性的交集，不只继承其中一个来源。

## 后果

- 正面：任何结论都能回到原文并解释“当时为什么这样判断”；
- 代价：存储增长；需要版本感知的查询与清理策略；转换与参考数据需要登记与长期保存。
- 首次启用门禁：架构方向已批准，运行能力尚未验收。第一个结构化来源或派生字段启用前，须验收记录键唯一与字段路径可解析、`value_hash` 与取值一致、派生链无环且末端为文档或记录证据、事实版本固定可解析、转换与参考数据内容可取得，以及派生结果的权限按全部来源传播。
