# ADR-0015：基础设施开源自建优先

> 状态：提议 · 日期：2026-10-13 · 决策者：项目负责人、首席架构师

## 背景

原方案优先使用云厂商托管的 PostgreSQL、Kafka、对象存储、Redis 与 Kubernetes。项目负责人确定方向：不依赖任何云厂商的专有服务，能自建的开源方案全部自建，除非托管价格优势明显。专属单元与私有部署本就要求同一套清单可离线运行；基础设施搭建工作主要由编码 Agent 承担。分析见 [技术选型分析](../03-architecture/11-technology-selection-analysis.md) 第 3 节。

## 决策

1. 云厂商只作为 IaaS 供应商（虚拟机、云盘、VPC、四层负载均衡、带宽），不使用其 PaaS 专有能力。
2. 自建组件：RKE2（Kubernetes）、Envoy Gateway、PostgreSQL（CloudNativePG）、Kafka 4.x KRaft（Strimzi）、OpenSearch（Operator）、Valkey、Temporal、Keycloak、OpenFGA、OpenBao、Harbor、Argo CD、可观测性组件；基础设施即代码使用 OpenTofu。
3. 价格例外：托管服务在同等可靠性下总成本低 30% 以上，且只经标准协议使用时允许托管；被托管组件必须在 `staging` 或私有部署包中以自建方式持续运行。
4. 当前唯一的价格例外是生产环境的对象存储：使用 IaaS 供应商的对象存储，只用 S3 标准协议；私有部署与 `staging` 使用 Ceph RGW。
5. 选用组件的许可证必须允许向私有部署客户分发；AGPL 组件随私有部署分发前经法务确认。

## 备选

- **托管优先**（原方案）：初期运维少，但形成厂商锁定，私有部署无法复用清单，扩展与版本受托管白名单限制；
- **全部自建，包括对象存储**：在公有云上用云盘自建对象存储的成本约为托管的数倍。

## 后果

- 正面：SaaS、专属单元与私有部署使用同一套清单；可在不同云与自有机房之间迁移；组件版本与扩展自主；
- 代价：升级、备份恢复演练、扩容与故障处理由平台工程团队承担，需要值班与演练制度；需要在 C1 商务报价完成后按价格例外规则复核一次；
- 影响：ADR-0004（Kafka 不再优先托管）、ADR-0007（缓存为 Valkey）、部署拓扑、安全与租户（OpenBao 替代 KMS）。
