# ADR-0003：子系统划分与数据所有权

> 状态：已批准 · 日期：2026-10-12 · 决策者：首席架构师、产品负责人 · 批准：项目负责人

## 背景

需要稳定的业务能力边界，支撑多领域扩展、团队分工与独立部署。

## 决策

划分为四个平面、18 个子系统（登记见 `03-architecture/subsystems/README.md`）。关键边界选择：

- **证据**与**领域情报**分离：证据管来源版本与解析（领域无关），领域情报管领域语义与生命周期；
- **实体图谱**独立：跨信息领域共享的主数据与关系是最核心的数据资产，独立演进；
- **检索**独立且只持有派生数据；
- **监测**与**研究**分离：前者是高吞吐、确定性的流式匹配，后者是低吞吐、高成本的长流程；
- **判断**独立于研究：判断的输入既来自监测也来自研究，且承担决策记录；
- **学习**只通过提案影响策略，不直接修改；
- **审批**属于身份与权限子系统，作为通用能力供所有子系统使用；
- 每类数据只有一个所有者子系统可写。

## 后果

- 正面：边界与业务能力一一对应，便于团队所有权与独立演进；
- 代价：子系统数量多，需要严格的契约管理与依赖检查；
