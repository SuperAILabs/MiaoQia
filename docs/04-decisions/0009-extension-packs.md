# ADR-0009：三类扩展包

> 状态：已批准 · 日期：2026-10-12 · 决策者：首席架构师、产品负责人 · 批准：项目负责人

## 背景

平台需要持续接入新的信息领域、应用领域、行业与商业目标，且不能修改平台核心。

## 决策

扩展机制与业务层级对应：

- **信息领域包**：来源、处理器、解析器、领域 Schema、生命周期、事件、实体关系、检索映射、研究工具；
- **应用领域包**：客户细分、目标实例、机会路径、研究模板、判断框架、策略模板、反馈标签、指标、评估集、视图；
- **行业包**：品类与映射、词表、能力与资质模板、默认规则。

扩展包以声明式定义为主：信息领域包可包含受限 SPI 代码（Python）；应用领域包与行业包为纯声明 + CEL 表达式（ADR-0006）。扩展包只依赖 `sdk` 与被扩展子系统的 `api`，定义多版本共存，运行实例固定版本。

## 后果

- 正面：领域差异下沉，核心保持通用；
- 代价：SPI 与定义 Schema 需要稳定的版本管理；需要扩展包级测试与评估基础设施。

## 补充：应用领域包的定义格式与覆盖矩阵（2026-10-16，待批准）

> 本节随任务书 I1 提出，批准前不改变上文已批准的决策。

- 应用领域包除策略模板外的定义（角色模板、目标模板、机会路径、判断框架、研究模板）使用统一格式文件 `contracts/packs/application-domain.schema.json`（0.1.0 草案），在 `pack.yaml` 的 `provides` 中按种类登记；条件仍只用 CEL。
- 每个应用领域包登记覆盖矩阵：每条机会路径的进入策略、路径定义、框架与研究模板标为已定义、复用、无需或待定。共用必须显式写出，待定只引用阶段基线已有任务，不另立任务。
- 引用与校验由 `mqc` P9 执行，与策略模板的 P0–P7 共用同一检查入口，不另建工具。
