# ADR-0009：三类扩展包

> 状态：已批准 · 日期：2026-10-12 · 决策者：首席架构师、产品负责人 · 批准：项目负责人
> 修订：2026-10-16 并入应用领域包的定义格式与覆盖矩阵（任务书 I1），按项目负责人审阅意见修订，随所在 PR 合并生效；2026-10-19 并入交付定义（卡片、简报、反馈、结果、指标）与行业包格式（阶段基线 M2-P2）；定义格式 Schema 仍为草案

## 背景

平台需要持续接入新的信息领域、应用领域、行业与商业目标，且不能修改平台核心。

## 决策

扩展机制与业务层级对应：

- **信息领域包**：来源、处理器、解析器、领域 Schema、生命周期、事件、实体关系、检索映射、研究工具；
- **应用领域包**：客户细分、目标实例、机会路径、研究模板、判断框架、策略模板、反馈标签、指标、评估集、视图；
- **行业包**：品类与映射、词表、能力与资质模板、默认规则。

扩展包以声明式定义为主：信息领域包可包含受限 SPI 代码（Python）；应用领域包与行业包为纯声明 + CEL 表达式（ADR-0006）。扩展包只依赖 `sdk` 与被扩展子系统的 `api`，定义多版本共存，运行实例固定版本。

应用领域包的定义与覆盖：

- 除策略模板外的定义（角色模板、目标模板、机会路径、判断框架、研究模板、卡片、简报分区、反馈与结果原因、效果指标）使用统一格式 `contracts/packs/application-domain.schema.json`（草案），在 `pack.yaml` 的 `provides` 中按种类登记；条件只用 CEL。
- 每个应用领域包必须在 `provides.coverage` 登记覆盖矩阵：每条机会路径的进入策略、路径定义、判断框架与研究模板标为已定义、复用、无需或待定。共用必须显式写出，多条路径可共用同一策略与框架，不为每条路径复制定义。
- 待定项必须注明交付阶段；阶段基线已有对应任务时引用该任务，不重复立项。
- 覆盖矩阵表达设计完整性，不等于运行就绪：待定项允许设计检查通过；具体功能启用时，它所必需的定义必须已经交付并通过验收，“引用存在”不能证明能力可执行。
- 引用与校验由 `mqc` P9 执行（缺少覆盖矩阵、引用不存在、待定任务不在阶段基线或与交付阶段不一致均失败），交付定义由 P10 校验，与策略模板的 P0–P7 共用同一检查入口，不另建工具。行业包按 `contracts/packs/industry.schema.json`（草案）登记，由同一入口的 I1–I5 校验（[可扩展性 2.4](../03-architecture/04-extensibility.md#24-行业包)）。

## 后果

- 正面：领域差异下沉，核心保持通用；
- 代价：SPI 与定义 Schema 需要稳定的版本管理；需要扩展包级测试与评估基础设施。
- 覆盖矩阵让复用与缺口可见，但功能启用仍以定义交付和验收为门禁，不以矩阵登记为准。
