# ADR-0007：存储组合

> 状态：提议 · 日期：2026-10-12 · 决策者：首席架构师、产品负责人

## 背景

平台需要事务一致性、海量原始文件、中文全文与语义检索、订阅反查、大规模统计、多跳关系查询。

## 决策

| 需求 | 存储 | 角色 |
|---|---|---|
| 事务与权威数据 | PostgreSQL（每子系统独立逻辑数据库与账号，RLS） | 权威 |
| 原始制品与文件 | S3 兼容对象存储 | 权威 |
| 检索、语义、订阅反查 | OpenSearch | 派生 |
| 统计、审计、计量、仿真计算 | ClickHouse | 派生或追加式 |
| 缓存与限流 | Redis | 非权威 |
| 多跳关系查询 | 图查询引擎读模型（引擎经基准测试选定） | 派生 |

图查询以 `entity-graph.GraphQuery` 接口固定契约，引擎作为可替换投影，权威关系始终在 PostgreSQL。

## 后果

- 正面：每类负载使用合适引擎；派生存储均可重建；
- 代价：运维面较大；需要完善的投影与重建工具。
