# ADR-0015：前期 AI 推理只接 API

> 状态：已批准 · 日期：2026-10-13 · 决策者：项目负责人、首席架构师、AI 负责人

## 背景

平台需要生成、嵌入、重排、OCR 与版面能力。前期调用量有限，境内已备案供应商的 API 能覆盖全部能力；项目负责人确定前期只接模型 API，不做私有模型部署，不建设 GPU。

## 决策

1. 生成、嵌入、重排、OCR 与版面能力均通过境内已备案供应商的 API 获得，经 `ai-platform` 模型网关统一路由、计量与治理；供应商按评测选定主选与备选。
2. 模型网关以 OpenAI 兼容协议适配器为主；私有部署客户可把端点指向其自有推理服务。
3. 敏感数据默认不进入模型，路由规则以 [安全与租户](../03-architecture/06-security-and-tenancy.md) 的数据分级为准。
4. 嵌入模型与版本记录在索引版本中，更换嵌入模型即构建新版本索引。
5. 不建设 GPU 资源与私有推理服务。

调用量依据：公共域分块每年千万至亿级、每块约 500 token，按内容哈希只嵌入一次，约每年 50 亿至 500 亿 token；按每千 token 约 0.0005 元 **[待核验]**，年成本在数千至数万元，整体重算一次也在同一量级。OCR 只用于扫描件（公告多为 HTML 与文本型 PDF），按页计量。

## 备选

- **私有推理（vLLM + GPU）**：数据不出域、大规模时单位成本更低，但前期调用量不足以覆盖 GPU 与运维成本。

## 后果

- 正面：无 GPU 采购与推理运维；可快速切换到评测更优的模型；
- 代价：依赖供应商可用性与价格（以多供应商备选缓解）；敏感数据的 AI 能力受限；
- 重新评估条件：某类任务的月度 API 成本超过同等 GPU 资源成本；签约客户合同要求妙洽提供私有模型；关键能力在合规供应商中无可用模型。

## 补充（2026-10-17，PR #18）

模型网关增加分类与评分两类决策能力（类 Jev 决策模型，定义见 [ai-platform 第11节](../03-architecture/subsystems/ai-platform.md#11-决策能力类-jev-决策模型)）。它们同样只经境内已备案供应商的 API 获得，适用本 ADR 的全部决策；“类 Jev”不指定品牌，候选按任务评测选定主选与备选。模型目录的计费单位扩展为按 token 与按请求两种，按请求计费的端点同样受调用前费用上限约束。本补充不改变上述决策，也不授权真实调用。
