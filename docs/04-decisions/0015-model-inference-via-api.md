# ADR-0015：前期 AI 推理只接 API

> 状态：已批准 · 日期：2026-11-07 · 决策者：项目负责人、首席架构师、AI 负责人

## 背景

平台需要结构化生成、OCR 与版面、分类与评分能力。前期调用量有限，成熟的大模型 API 能覆盖全部能力；项目负责人确定前期只接模型 API，不做私有模型部署，不建设 GPU。检索前期只用全文与结构化条件，不引入向量检索（[search](../03-architecture/subsystems/search.md)），因此不需要嵌入与重排能力。

## 决策

1. 结构化生成、OCR 与版面（多模态模型）、分类与评分能力均通过模型供应商的 API 获得，经 `ai-platform` 模型网关统一路由、计量与治理。
2. 供应商为 DeepSeek、豆包（字节跳动火山引擎）、OpenAI、Anthropic、Google；每项能力按[模型评测方案](../05-delivery/08-model-vendor-evaluation.md)在这五家中选定主选与备选。
3. 每家供应商在网关中各有一个适配器，网关的路由、主备切换、预算、输出校验与计量与供应商无关。私有部署客户可把端点指向其自有推理服务。
4. 敏感数据默认不进入模型，路由规则以 [安全与租户](../03-architecture/06-security-and-tenancy.md) 的数据分级为准。
5. 不建设 GPU 资源与私有推理服务。
6. 分类与评分两类决策能力（定义见 [ai-platform 第11节](../03-architecture/subsystems/ai-platform.md#11-决策能力类-jev-决策模型)）同样经上述供应商的 API 获得，按任务评测选定主选与备选。模型目录的计费单位为按 token 与按请求两种，所有端点受调用前费用上限约束。

## 备选

- **私有推理（vLLM + GPU）**：数据不出域、大规模时单位成本更低，但前期调用量不足以覆盖 GPU 与运维成本。
- **只接境内已备案供应商**：合规路径最简单，但限制了模型质量的选择范围；前期处理的是公开数据，不需要这一限制。

## 后果

- 正面：无 GPU 采购与推理运维；可在五家之间按评测切换到更优的模型；
- 代价：依赖供应商可用性与价格（以多供应商备选缓解）；敏感数据的 AI 能力受限；
- 重新评估条件：某类任务的月度 API 成本超过同等 GPU 资源成本；签约客户合同要求妙洽提供私有模型或限定供应商；引入向量检索时补嵌入能力；某家供应商不再可用。
