# ADR-0016：前期 AI 推理只接 API

> 状态：提议 · 日期：2026-10-13 · 决策者：项目负责人、首席架构师、AI 负责人

## 背景

原方案包括 vLLM 私有模型推理、GPU 节点池以及私有部署的嵌入、重排与 OCR 模型。项目负责人确定方向：前期只接模型 API，不做私有部署，不考虑 GPU。分析见 [技术选型分析](../03-architecture/11-technology-selection-analysis.md) 第 4 节。

## 决策

1. 生成、嵌入、重排、OCR 与版面能力均通过境内已备案供应商的 API 获得，经 `ai-platform` 模型网关统一路由、计量与治理。
2. 模型网关以 OpenAI 兼容协议适配器为主；私有部署客户可把端点指向其自有推理服务。
3. 敏感数据默认不进入模型；租户显式授权后，仅路由到签有零留存、禁止训练、境内处理条款的指定供应商。
4. 嵌入模型与版本记录在索引版本中，更换嵌入模型即构建新版本索引。
5. 不建设 GPU 资源与私有推理服务。

## 备选

- **私有推理（vLLM + GPU）**：数据不出域、单位成本在大规模时更低，但前期调用量不足以覆盖 GPU 与运维成本。

## 后果

- 正面：无 GPU 采购与推理运维；可快速切换到评测更优的模型；
- 代价：依赖供应商可用性与价格（以多供应商备选缓解）；敏感数据的 AI 能力受限；
- 重新评估条件：某类任务的月度 API 成本超过同等 GPU 资源成本；签约客户合同要求妙洽提供私有模型；关键能力在合规供应商中无可用模型。
