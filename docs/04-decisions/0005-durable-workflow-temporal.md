# ADR-0005：持久化工作流：Temporal

> 状态：已批准 · 日期：2026-10-12（2026-10-13 按 ADR-0014～0017 审查修正） · 决策者：首席架构师、产品负责人 · 批准：项目负责人

## 背景

研究运行、策略仿真、回填、重放、删除编排、推进时限等是长时、多步、需要重试、定时与人工中断的流程。

## 决策

使用 Temporal 作为持久化工作流引擎（自建集群，持久化在独立的 PostgreSQL 集群，ADR-0015）。工作流按子系统划分任务队列；工作流只调用本子系统活动，跨子系统经公开接口。Go 子系统使用 Temporal Go SDK，Python 子系统使用 Python SDK（ADR-0014）；Agent 研究运行时构建在 Temporal Go SDK 之上。

## 备选

- 自研任务状态机：需要重复实现定时、重试、版本化与可观测，长期成本更高；
- Celery 等任务队列：不提供持久化的多步状态与确定性重放。

## 后果

- 正面：长流程可靠、可恢复、可观测；
- 代价：团队需掌握工作流确定性约束与版本化；Temporal 集群需要运维。
