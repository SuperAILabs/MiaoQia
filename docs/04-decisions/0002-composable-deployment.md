# ADR-0002：逻辑架构按终态设计，部署从少量单元开始

> 状态：已批准 · 日期：2026-10-14 · 决策者：首席架构师、产品负责人 · 批准：项目负责人

## 背景

妙洽是长期演进的平台，子系统与可扩展性按终态设计；人员和预算灵活安排，开发与生产资源按阶段配置。同时，初期把 18 个子系统各自部署为独立服务会带来不必要的运维面和跨服务调试成本。

## 决策

1. 18 个子系统的边界、数据所有权、接口与事件契约按终态实现；
2. 基础组件一次选定（Kafka、Temporal、OpenSearch等），开发阶段运行于VPS/本地小规模配置，正式运行前完成生产云与高可用部署；保持同一接口与数据契约，开发不以其他产品冒充既定组件；
3. 应用打包为三个部署单元：`acquisition`（外部采集：独立故障域、网络边界与伸缩特征）、`data`（其余公共域数据处理子系统，Python）、`platform`（其余子系统，Go）；每个单元一个镜像、多进程角色；
4. 采用**可组合部署**：进程角色加载哪些子系统由部署清单配置；同语言子系统间调用经接口包，绑定本地实现或远程客户端；
5. 即使在同一进程中，子系统也使用独立数据库账号、不共享事务、事件经 Kafka 传递。

## 后果

- 正面：拆分任一子系统是配置与运维操作，不是重构；
- 正面：初期运维面小，调试简单；
- 代价：同进程调用也要经过完整调用管线，有少量开销；需要在 `kernel` 中投入接口绑定与代码生成能力；
- 代价：开发配置不能证明生产容量/可靠性；正式运行前需要生产等价环境和迁移/恢复演练；
